# GOVERNANCE_EXCEPTIONS — declarations & exception ledger (B-GOV)

> **Purpose:** the single, machine-greppable audit trail for the FOUR self-declared inputs the governance-checker keys off, plus legitimate-skip (N/A) confirmations. Kept here (not in CHANGES_AND_FIXES) so the checker can parse it deterministically and so the record survives independent of the §10.5 alert queue. Created by B-GOV (2026-06-17).
>
> **Why this exists:** every self-declared input is a soft spot (the same sessions being governed declare them). Recording each declaration here makes (a) the audit trail durable + greppable, (b) the stale-open-state cross-check (C3) implementable — the checker greps this file for open-declarations and flags ones past the 48h backstop, (c) repeat-skip patterns (Item 3) visible.

## How the checker uses this file
- **N/A skip:** when a required doc is marked N/A, the checker keeps the gap alert ACTIVE until a confirmed row appears here. **Who confirms, per type (B-PLAN-CURRENCY-CHECK P22; Langston's Q11 (a), scope §10i, 2026-09-30):** the `confirmed_by` cell counts by its LEADING word, lowercased and split on `+`; every part must be one of `langston`, `kyle`, `cc-a`, `cc-b`, `cc-c`, `cc-infra`. An `na-skip` or `class-override` row needs `langston` or `kyle` among the parts (`langston (routed alert …)` and `langston+cc-a` both count; `kyle` for a three-way N/A, see Tiering); an `open` row accepts any of the six. `pending` is unconfirmed and raises nothing; any other cell is unconfirmed AND raises `gov-exceptions-malformed`. ⚠️ **Dormant until the one-line flip of `EXCEPTIONS_V2_ENABLED` (`scripts/governance-checker/config.mjs`)** — until then the checker counts any non-`pending` confirmer.
- **Parent-ride N/A (policy — B-GOV-ORPHAN-CLASS, 2026-07-13, CC-B + Langston):** a sub-batch that rode its PARENT's docs (scope / pre_audit / plan / etc. — Kyle's "named overflow home" pattern) gets ONE explicit `na-skip` row **per doc**, NOT a loosened matcher. The checker's `findEntryDoc` deliberately requires the FULL contiguous batch-id token; a prose mention of a sub-batch under the parent's row is NOT a standalone entry, and treating it as one would let a genuinely-missing entry hide behind a parent's paragraph. Keep the matcher exact; record parent-ride coverage as a deliberate, auditable human confirmation here (cheap: one row per sub-batch doc).
- **Open-state:** a batch declared OPEN (timer-suspended) must have an `open` row here; the checker flags an `open` row older than 48h (OPEN_STATE_BACKSTOP_HOURS) with a "still open?" route to Langston.
- **Umbrella namespace — NOT IMPLEMENTED.** This file once described an umbrella declaring the sub-batch namespace it owns (`umbrella-namespace`) and a roll-up gate (`umbrella-done`). **No parser branch was ever built** (Kyle's 2026-09-02 ruling on the `P19-B8.5` `open` row). Both type names are recognised by the closed grammar and FLAGGED *not implemented — B-UMBRELLA-OPEN-STATE (CC-B)* (Langston R1-Q8, scope §10i, 2026-09-30), so a row that relies on one surfaces instead of sitting inert. The build is `B-UMBRELLA-OPEN-STATE` (CC-B). ⚠️ The flag is dormant until the flip of `EXCEPTIONS_V2_ENABLED`; until then such a row is silently ignored.
- **Ledger-row N/A (B-TASK-LIST-SLOT, 2026-09-11):** the checker's `gov-ledgerrow:<batch>:task_lists` alert — a completion report missing the Tier-1 task-list row — is cleared by a confirmed `na-skip` row whose doc value is `task_lists`. Ledger-row names share one flat `na-skip` set with the doc keys, so a ledger-row name may never equal a doc key (`poller.test.mjs` asserts the two sets are disjoint).
- **Class override:** a declared change-class that differs from the path-heuristic's expectation (Obj-12) is recorded here with the rationale.

## Tiering (Item 3)
- **Langston-alone** confirms an N/A that AGREES with the config (a CONDITIONAL doc marked N/A).
- **Three-way (escalate Kyle)** for an N/A that OVERRIDES a REQUIRED doc (esp. SYSTEM_MANUAL/SIM on an arch batch), or a repeat-skip pattern of the same doc across batches.

## ★ Grandfather cutoff (B-GOV-3 Obj-1, 2026-06-20)
**Decision:** the checker does NOT retroactively enforce on batches that CLOSED before it went live. The 2026-06-19 flood (88 `info` alerts on P19-B1/B2/B3a/B3b/B4a, B-NEW-22, B67.1, and others) was exactly this — historical batches closed under older rules being graded against the new doc-set. **Mechanism (B-GOV-3 Obj-1, to implement):** a cutoff (date or commit) in `config.mjs` so only batches whose code-push is AFTER the cutoff are graded; everything before is grandfathered with no per-row seeding required. This ledger then holds only genuine POST-cutoff exceptions going forward. Cutoff value + Langston confirm = Obj-1 close. Until implemented, the timer stays disabled (no retroactive flood).
