### 5b. ITEM 4.5 — Tiered fee-model accuracy fix (Kraken July 2026 cross-platform tiers)
**Status: NOT started. Tracked here 2026-06-08 (Kyle directive) after Kraken published the change (their support page "Cross-platform fee tier changes (July 2026)," effective 2026-07-09).** Full analysis + the transcribed tier table live in `Claude Comms and Packages/Cross-Session Briefs/KRAKEN_TIERED_FEE_CHANGE_ANALYSIS_2026-06-08.md`.

**What Kraken changed (plain terms):** previously your spot fee was set only by your spot volume, futures fee only by futures volume — separate. Going forward Kraken looks at THREE things — your 30-day spot volume, your 30-day futures volume, and the total value of assets you simply hold on Kraken (they call it Assets on Platform / AoP, which counts wallet balances + staked + rewards) — and puts you in the **most favorable tier any one of the three earns.** Once your tier is set, the same rate applies to spot and futures. The new tier ladder runs from Tier 1 (the entry tier: **0.80% taker / 0.40% maker on spot**) down to Pro 5 (0.05% taker / 0.00% maker).

**Why it matters to us — the gap:** our friction model today hard-codes a SINGLE fee level (0.26% taker / 0.16% maker) identically for crypto and xStock, sourced from a code file (`server/config/exchange-defaults.ts` + the per-class `friction.ts` files), **not** from the database, and with **no concept of fee tiers at all.** At our current size (~$830 portfolio, negligible 30-day volume, negligible AoP) the real tier is **Tier 1 = 0.80% taker / 0.40% maker** — roughly **3× the 0.26% taker we model.** Round-trip friction would be roughly **1.8% in reality vs. the ~0.7% we currently assume** — about a **1.1-percentage-point under-estimate per round trip (real friction ≈ 2.5× the model).** That means the Net-Expectancy gate would wave through trades that look marginally profitable but actually lose money once real fees apply. (For reference, the 0.26% taker we currently model only matches ~Tier 6, which needs ~$100K of 30-day spot volume or ~$200K of assets held on Kraken — well above where we are.) Not a live money-leak today (VTS + paper pay no real fees), so this is a **model-accuracy fix, not an emergency** — but it has to be right before any live capital, and ideally before the Phase 19 paper-audit so the audit watches realistic numbers.

**The fix (3 parts, design-before-build with Langston per §5#15 NO-PATCHES):**
1. **Move the fee values out of the hard-coded source files into the database settings layer** (`module_constants`, same per-asset-class resolution the other knobs use) so the rate is tunable without a redeploy. (Note: today crypto and xStock happen to share one fee level; under the new cross-platform structure that sharing is now *structurally correct* — the tier is account-wide, not per-product — so this does NOT need a per-asset-class fee dimension, though the DB layer supports one if ever needed.)
2. **Give the system a way to know the live account's current tier** — most likely a periodic read from Kraken's API (the account's current fee schedule), feeding the DB value. Until that's wired, default to **Tier 1 (the most expensive)** — over-estimating fees only ever rejects some good trades; it never lets a bad one through, which is the safe failure mode during calibration.
3. **Bias the modeled fee upward to the resolved (or default Tier-1) rate** and confirm the EV kernel consumes it everywhere fees flow in (`cost-model.ts` round-trip friction → Net-Expectancy kernel).

**Account tier CONFIRMED (Kyle 2026-06-08): Tier 1 — worst case, no softening.** Live account total balance / Assets-on-Platform ≈ $835 (far below the ~$20K needed for even Tier 3); 30-day trading volume negligible (trading key idle ~6 months). Staking + Stablecoin Rewards are on, but the totals are tiny. So **default-to-Tier-1 (0.80% taker / 0.40% maker) is the accurate setting**, not merely conservative, for the foreseeable future. **Timing:** the new tier structure takes effect **2026-07-09**; until then the old Kraken Pro schedule applies, which at this size is also above our modeled 0.26% — so the fix is warranted either way.

**Futures note:** the new table also lists futures-tier rates, but our futures (perp) friction is not configured yet anyway (errors out until crypto_perp / xstock_perp onboard) — so the futures column is captured in the analysis doc for later, not part of this fix.
