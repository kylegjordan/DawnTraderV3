# Crypto Day Trading Web App

## Overview
A long-only, spot-trading cryptocurrency day trading web application that automates strategies on Kraken. It scans markets, monitors pairs in real-time, and executes VWAP Pullback, ABCD Long, and SMA Trend Ride strategies. The application enforces disciplined risk management, supports live and paper trading, and integrates OpenAI's GPT-5 for AI analysis, conversational assistance, and intelligent system management. It provides trade tracking, performance analytics, tax-ready export, AI audit trails, and error diagnosis via a responsive dashboard optimized for Android and Windows. The system includes robust execution bot resilience with bracket order rollback, partial fill recovery, exchange constraint enforcement, rate limiting, retry logic, and a circuit breaker. A daily loss kill switch automatically suspends trading and closes positions if losses exceed a configurable threshold, with user-controlled recovery and ChatGPT incident analysis.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture
The frontend uses React + TypeScript with Vite, shadcn/ui (Radix UI + Tailwind CSS) for UI, and TanStack Query for state management. Wouter handles routing, and WebSockets provide real-time market and trade updates. It follows a mobile-first responsive design.

### Backend Architecture
The backend is Node.js with Express, using ESM. It features a RESTful API and WebSocket support. A service layer includes `KrakenService` for API interaction, `TradingEngine` for orchestration, `StrategyEngine` for implementing fixed trading strategies, `MarketScanner` for pair identification, `RiskManager` for pre-trade checks, `AIAnalyst` for GPT-5 powered insights, and `AIOpportunitiesService` for automated hourly opportunity generation using GPT-4o mini. It supports both "live" and "paper" trading modes.

### Data Storage Solutions
PostgreSQL, accessed via Neon serverless driver, is used for data storage. Drizzle ORM provides type-safe schema definitions and migrations. Key schemas include `users`, `tradingSettings`, `watchlistPairs`, `trades`, `aiReports`, `aiConversations`, `aiChatLogs`, `priceData`, `aiOpportunityRuns`, and `aiOpportunities`. Extensive use of PostgreSQL enums and decimal types ensures data integrity. Authentication currently uses a simplified `user-id` header but is designed for future expansion.

### System Design Choices
- **Trading Strategy Implementation**: Fixed rules for VWAP Pullback, ABCD Long, and SMA Trend Ride strategies, calculating entry, stop loss, and target prices.
- **Risk Management System**: Multi-layered, including risk per trade (R), maximum exposure, maximum open trades, slippage tolerance tiers, and order book depth validation. A daily loss kill switch feature prevents excessive losses by automatically suspending trading and closes positions.
- **Settings Page**: Reorganized into four tabs (Screener Filters, Portfolio Guardrails, Strategies, Notifications) with plain-language descriptions and finalized default values.
- **Timezone Handling**: All timestamps are stored in UTC (`timestamptz`) and displayed in the user's local timezone with a comprehensive timezone selection widget.
- **AI Opportunities**: Hourly automated pipeline that analyzes all Kraken spot pairs (~220), ranks top 150 by liquidity/volatility, applies delta filter for material changes, sends to GPT-4o mini for structured opportunity generation, validates and stores results. Supports five opportunity types: long_term_hold, moonshot, momentum, breakout, and mean_reversion. Each opportunity includes entry zone, stop floor, target ceiling, time horizon, risk amount rule, probability score, risk/reward rating, and eligibility flags. Cost-efficient at ~$0.003 per run using GPT-4o mini.
- **Live Kraken Balance Integration**: Portfolio Value widget now displays live account balances fetched from Kraken API. `RiskManager.getLiveKrakenBalance()` queries Kraken for all asset balances, converts crypto holdings to USD using market data, and implements 45-second per-user caching to minimize API calls. Falls back gracefully to internal calculation ($50,000 base + realized/unrealized P/L) if Kraken API fails. Displays sync status with UTC timestamp: "Synced from Kraken • Last updated HH:MM:SS UTC" on success, "Sync failed • {error}" on API failure, or "Using internal estimate" for fallback mode. Per-user cache isolation prevents cross-account data leakage in multi-user scenarios.
- **Comprehensive Reports Panel**: Dedicated Reports page with navigation item in sidebar. Three tabs: (1) Canned Reports with pre-configured exports (Tax Report, Performance Summary, Trade Journal, Fees & Costs, P&L Reports); (2) Custom Reports with date range and filter controls (symbol, strategy, mode); (3) Quick Exports for common formats. Backend API endpoint `/api/reports/export` generates CSV files with comprehensive field coverage. Tax Report includes cost basis, proceeds, holding duration (hours and days), realized vs unrealized gains, term classification (short/long-term), and account type (Live/Paper) for accountant-ready filing. Performance Summary aggregates KPIs by symbol/strategy with win rate, R Multiple, total P/L. Trade Journal provides chronological log with notes. Fees & Costs breaks down monthly fees with volume analysis. P&L Reports generate monthly, quarterly, and annual aggregates. PDF export functionality noted as coming soon. All export functionality consolidated exclusively in Reports panel.
- **Maintenance Mode**: System-wide maintenance mode controlled by `MAINTENANCE_MODE=true` environment variable. When active, all Kraken API calls (public and private) are blocked at the KrakenService level with console logging. Frontend displays a maintenance banner on the dashboard: "🔒 Maintenance Mode: Exchange connections temporarily disabled for system updates." Status endpoint `/api/maintenance/status` allows frontend to poll maintenance state. This enables safe offline testing and system updates without external API traffic.
- **Market Data Health Check**: Automated daily health monitoring system that runs every 24 hours to verify market data service reliability. Tests BTC, ETH, SOL, and SUI against both CoinGecko (primary) and Kraken (fallback) APIs. Monitors API response times, validates JSON responses, tracks cache hit ratios (targeting >70%), and logs all results to `/reports/daily_market_data_health.log`. Detects and reports API failures, latency spikes (>2 seconds), and cache performance issues. Maintains last-known-working timestamps for each endpoint to aid in troubleshooting. Status categories: HEALTHY (no issues), DEGRADED (warnings detected), CRITICAL (endpoint failures). Service automatically starts on server initialization and runs first check immediately.
- **Daily Trading Brief**: Automated daily briefing system that generates comprehensive end-of-day reports using GPT-4o. The `DailyBriefService` scheduler creates a new brief at 00:01 UTC, updates it every 30 minutes throughout the day, and finalizes it at 23:59 UTC. Each brief includes: a compelling headline and summary, detailed narrative analysis, key metrics (number of trades, win rate, total P&L, portfolio percentage change, realized/unrealized P&L, exposure, drawdown), trade highlights (top winners and losers with P&L and percentage gains/losses), closed and open trade summaries, AI-generated learnings and actionable recommendations, and system health status. Dashboard displays a card with today's brief showing the headline, summary, key metrics, system health, and last update time with a link to view the full report. Dedicated `/daily-brief` page provides the complete briefing with all sections displayed in a clean, readable layout. Reports page includes a "Daily Briefs" tab showing historical briefs with dates, status (in-progress/final), headlines, summaries, and metrics. All briefs are stored in the `dailyBriefs` table with status tracking and timestamps. Backend API endpoints: `/api/daily-briefs/today` (get current day), `/api/daily-briefs` (list all briefs), `/api/daily-briefs/:date` (get specific date), `/api/daily-briefs/update` (manual trigger). Email delivery support planned for finalized briefs.

## External Dependencies

- **Kraken Exchange API**: Integrated for market data, trade execution, balance queries, order management, and HMAC-SHA512 signature generation. Features comprehensive API load management with multi-tier caching system: account balance (60s TTL), open orders (90s TTL), closed orders (600s/10min TTL). Implements automatic rate limit detection and 2-minute cooldown on `EGeneral:Temporary lockout` errors, serving stale cache during lockouts to maintain service availability. Per-user cache isolation prevents cross-account data leakage. Cache statistics available via `/api/kraken/cache-stats` endpoint. Total private API call rate maintained at ~1 call/minute average (1% of safe threshold). Signature generation uses proper Buffer concatenation matching Kraken's official specification: SHA-256 hash of `nonce+postData`, then HMAC-SHA512 of `path+hash` using base64-decoded secret.
- **OpenAI GPT-4o API**: Powers AI analysis and conversational assistance with a ChatGPT-style interface. Features include multi-turn conversations, cost control (token counting, configurable context, auto-trimming), database query capabilities, an Ask→Confirm→Update flow for settings changes, an audit trail system, error diagnosis, and performance reports. Also uses GPT-4o mini for cost-effective AI Opportunities generation (~$0.003 per hourly run).
- **Finnhub API**: Provides stock market data with robust retry and fallback mechanisms. Features automatic retry logic (up to 2 retries with exponential backoff: 2s, 4s delays), multi-tier fallback system (/quote → /stock/profile2 → /search), 2-minute response caching, and graceful degradation returning partial data with null price and explanatory notes when quote data is temporarily unavailable. All responses include symbol, name, and price (or null) for consistent frontend handling.
- **Neon Database**: Serverless PostgreSQL database requiring a `DATABASE_URL` environment variable.
- **WebSocket Infrastructure**: Custom WebSocket server for real-time data push (price updates, trade notifications, portfolio metrics, system status).
