# Crypto Day Trading Web App

## Overview
This project is a long-only, spot-trading cryptocurrency day trading web application for Kraken. It automates advanced trading strategies, integrates real-time market scanning, disciplined risk management, and offers both live and paper trading capabilities. Leveraging OpenAI's GPT models, it provides AI analysis, trade tracking, performance analytics, error diagnosis, and an autonomous learning engine. The primary goal is to deliver a comprehensive, resilient, and continuously improving self-optimizing trading platform with significant business and market potential in automated crypto trading.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture
The application features a React, TypeScript, Vite frontend with a mobile-first, responsive design. The backend uses Node.js and Express, providing a RESTful API and WebSocket support. Data persistence is managed by PostgreSQL via Neon serverless driver and Drizzle ORM.

Core services include `KrakenService`, `TradingEngine`, `StrategyEngine`, `MarketScanner`, `RiskManager`, `AIAnalyst`, and `AIOpportunitiesService`. Authentication uses username/password, bcrypt, JWT, and WebAuthn.

An AI Orchestrator & Command Center, powered by GPT-4o, features an AI SysAdmin Co-Pilot named Walter. Walter's architecture includes a Unified Command & Conversation Layer, Semantic Memory Layer, Intelligence Refinement Layer (with multi-module intelligent caching and a Hybrid Cortex Intelligent Memory Layer), `SystemHealthMonitor`, `SelfRepairService`, Natural Language Action Interpreter (NLAI), and a Contextual Intent Engine (CIE). The Real-Time Execution Layer manages market data, execution timing, slippage modeling, and rate control. A Unified Portfolio & Strategy State ensures a single source of truth. Walter's architecture is Hybrid Cognitive-Operational, featuring an Intent Gateway for validating commands and a `SecureCoreService` for domain restriction. A Continuous Learning Pipeline extends the Event Broker to capture trade events, and a `StateAwarenessService` provides system state snapshots. An Intent Execution Framework provides safe, audited execution of validated intents with a `Pre-Execution Validator`. The Context Bridge enables real-time, bidirectional synchronization between Walter's panel, chat widget, and backend via WebSocket.

The Reasoning Orchestrator enables Walter's multi-step transparent reasoning via Domain Bobs (DevOps, FullStack, UX, TradingBob). The Memory Lifecycle Manager ensures semantic memory integrity, and an Async Task Queue provides distributed multi-domain reasoning with parallel execution. Cognitive Tuning & Testing provides automated performance validation.

The Autonomy Layer introduces self-directed analysis, meta-reasoning, exploratory learning, and automated optimization capabilities through `AutonomyController`, `MetaReasoningEngine`, `CuriosityEngine`, and `SelfOptimizer`. The Emergent Awareness Layer enables meta-cognitive state tracking and self-reflection via `AwarenessCoreService`. The Adaptive Learning & Goal Alignment Foundation enables experience-based learning and policy-aligned adaptation through `ExperienceMemoryService` and `AdaptiveObjectiveEngine`.

Safety Guardrails & Operational Kill Switch provides comprehensive safety controls with database tables, a `SafetyGuardrails` service, and admin-only API endpoints to halt all trading/execution. An Ethical Alignment Framework establishes comprehensive ethical reasoning across all autonomous decisions, integrated into the Autonomy Controller. Controlled Web Intelligence & Knowledge Retrieval uses a `KnowledgeRetrievalService` for policy-bound web acquisition and a `SemanticCorrelationEngine`.

The Autonomous Execution Layer provides Walter with complete autonomous command execution capabilities. The `ExecutionPolicyController` evaluates every Walter command against approval matrix settings and risk thresholds, creating comprehensive audit trails in the `walter_execution_log` database table. The NLAI Execution Broker orchestrates the execution pipeline.

Paper Trading Simulation State Management uses a database-first architecture with comprehensive reconciliation diagnostics. Multi-Intent Command Processing enhances Walter's NLAI to detect, parse, and execute multiple intents. Live Trading Voice/Chat Activation enables Walter to manage live trading mode through voice or chat commands with manual approval workflows. An Automatic Test Harness provides automated end-to-end validation.

Context Persistence Framework enables Walter to automatically internalize mission context and development history on startup by scanning designated markdown files. This framework includes a 10-layer sanitization pipeline. Inline Approval Prompts & Interactive Notifications provide seamless manual approval workflows through chat and a bell notification center, with API endpoints and WebSocket integration.

Frontend Permission Integration implements comprehensive role-based access control (RBAC) on the frontend with fail-closed security, using a `useUserRole` hook and `can(permission)` helper, backed by server-side validation with `requirePermission` middleware.

Trading State Synchronization & Fail-Safe Recovery provides database-backed trading mode persistence with automatic recovery and cross-service coordination via the `system_context` table and `TradingStateSync` service. It includes kill-switch integration and broadcasts state changes via WebSocket. Goals Engine Persistence & Audit Logging provides comprehensive audit trails for all goal changes via the `goal_audit_log` table, ensuring durable persistence and server-authoritative hydration, including metric name canonicalization. Trading Engine Invocation ensures trading toggles start/stop trading engines and provides comprehensive audit logging via a `trading_audit_log` table, with frontend modals for safety guardrails.

PaperSim Lifecycle Initialization implements lazy initialization and explicit reset on startup. PaperSim State Reconciliation & Atomic Manager Creation fixes state mismatches by implementing synchronized manager API helpers and atomic creation/destruction patterns with comprehensive reconciliation logic. Cross-Mode Isolation & PaperSim Broadcast Sync ensures paper trading broadcasts real-time WebSocket events just like live trading, providing instant UI updates and independent state management for live and paper modes.

PaperSim Universe Scan & Filter Trace provides read-only diagnostic capabilities to verify end-to-end filtering without starting engines. The `PaperSimDiagnosticService` loads the raw Kraken universe and manually applies all screener filters, tracking exclusion reasons. An admin/owner-only GET endpoint `/api/paper-sim/diagnostics/scan` returns detailed breakdown data. Symbol Canonicalization & Filter Parity enforces one canonical pair format (BASE/QUOTE) across all filtering components, with a `symbol-canonicalizer.ts` utility. This includes a fix for Kraken's prefixed quote currencies (e.g., ZUSD→USD) which was causing high rejection rates.

Trading Panel Enhancements introduce comprehensive filter insights and real-time data feeds to the Trading page. A new **Filter Insights** tab displays universe statistics and breakdown by filter rule, with auto-refresh and manual refresh. **Inline Live Trading Confirmation Modals** appear directly above Walter Chat for "start/stop live trading" commands. A **Filtered Pairs Live Data Feed** responds to real-time updates during Paper Trading Mode, with dynamic refetch intervals and WebSocket listeners.

Filter Health Diagnostic Logging enables real-time filter statistics tracking by integrating diagnostic logging into the MarketScanner's scan cycle. The `MarketScanner.logFilterDiagnostics()` method logs comprehensive scan statistics to the `filter_diagnostics` database table for both paper and live modes. Filter Breakdown in the Filter Insights tab displays all 11 filter categories.

Screener Alignment with Goals Engine Filters unifies data sources by migrating filtering logic from `trading_settings` to the `screener_filters` table, ensuring consistency between MarketScanner and Goals Engine. `KrakenService.getEligiblePairs()` accepts 14 filter parameters, and the system implements 9 operational filters (Min Volume, Daily Range, Min/Max Price, Bid-Ask Spread, Stablecoins, Quote Currency, Blacklist, Whitelist, History) plus Volatility (using daily range). Four filters (RSI, market cap, regulated status, liquidity) are noted as unavailable due to Kraken API limitations. The `/api/filters/diagnostics` endpoint returns threshold values, and the Filter Insights UI displays these thresholds with tooltips.

Walter Chat Intent Detection & Hardening (Phase 27.F.16.D) implements comprehensive intent parsing with hard override rules and multi-layer safeguards. The frontend (`walter.tsx`) uses word-boundary regex patterns to detect paper keywords (paper, simulation, simulated, practice, test, demo) and live keywords, with PAPER ALWAYS WINNING even if "live" is also present in the message. Enhanced trace logging shows token detection (`[INTENT] tokens={paper:true, live:false...}`), selected intent, and rule ID for every message. The backend NLAI action registry (`nlai-action-registry.ts`) includes a routing guard that forces paper-sim service when paper keywords are detected, blocking any live-api route and logging `[INTENT] guard_applied=paper_forced`. Inline modal enforcement prevents notification-only paths for live trading—modals must be shown for start/stop live trading commands. A debug intent pill in the Walter header displays the detected intent (e.g., "Parsed: START PAPER SIM") when `VITE_DEBUG_INTENT=true` is set. Console logs track intent detection with detailed breakdowns showing tokens, selected intent, routing decisions, and modal enforcement checks.

UI Navigation Reorganization consolidates navigation by removing standalone Users, Command Center, and Search and Analysis pages. The Command Center's three tabs (Overview, AI Analysis, AI Recommendations) are now integrated into the AI Transparency page as the first three tabs: "AI Command Center" (renamed from Overview), "AI Analysis", and "AI Recommendations". AI Command Center is the default active tab and displays system metrics (CPU, memory, uptime), trading performance (P/L, win rate, ROI), AI activity (learning cycles, opportunities, adjustments), active goals, guardrails, and system audit reports. It includes "Trigger Analysis" and "Run System Audit" buttons for manual operations. The AI Analysis tab shows detected anomalies and optimization opportunities. The AI Recommendations tab displays orchestrator logs with approve/reject workflows for goal updates, guardrail changes, and strategy adjustments. The AI Transparency page now has 13 total tabs with comprehensive AI oversight capabilities. The Search and Analysis functionality has been integrated into the Watchlist page as the third and final tab, alongside "AI Opportunities" and "User Watchlists" tabs, providing symbol search, market data analysis, and AI-generated insights within a unified watchlist interface.
