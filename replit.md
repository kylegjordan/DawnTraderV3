# Crypto Day Trading Web App

## Overview
This project is a long-only, spot-trading cryptocurrency day trading web application for Kraken. It automates advanced trading strategies, integrates real-time market scanning, disciplined risk management, and offers both live and paper trading capabilities. The application leverages OpenAI's GPT models for AI analysis, trade tracking, performance analytics, error diagnosis, and an autonomous learning engine. Its primary goal is to provide a comprehensive, resilient, and continuously improving self-optimizing trading platform, delivering a leading-edge solution in automated crypto trading with significant business and market potential.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture
The application features a React, TypeScript, Vite frontend with a mobile-first, responsive design, dynamic mode-aware UI, voice transcription, and a System Truth Panel. The backend uses Node.js with Express, providing a RESTful API and WebSocket support. Data is stored in PostgreSQL via Neon serverless driver and Drizzle ORM.

Core services include `KrakenService`, `TradingEngine`, `StrategyEngine`, `MarketScanner`, `RiskManager`, `AIAnalyst`, and `AIOpportunitiesService`, supporting 8 automated trading strategies and multi-layered risk management. Authentication uses username/password with bcrypt, JWT, and WebAuthn.

An AI Orchestrator & Command Center, powered by GPT-4o, provides insights through an AI SysAdmin Co-Pilot named Walter. Walter features a Unified Command & Conversation Layer, Semantic Memory Layer (pgvector and OpenAI embeddings), and an Intelligence Refinement Layer with a Self-optimizing Cognitive Weight Adjuster. A Paper Trading Simulation Engine provides real-time execution. The system incorporates a multi-module intelligent caching system (Bob Core) and a Hybrid Cortex Intelligent Memory Layer.

The system includes `SystemHealthMonitor`, `SelfRepairService`, a Natural Language Action Interpreter (NLAI), and a Contextual Intent Engine (CIE) for Walter's understanding and command execution. The Real-Time Execution Layer manages market data, execution timing, slippage modeling, rate control, and parity gating. A Unified Portfolio & Strategy State ensures a single source of truth, maintained by a `portfolio_state` table and `StrategySync` Service.

Walter's architecture is Hybrid Cognitive-Operational, with a Cognitive Layer for intent reflection and an Intent Gateway for validating operational commands with RBAC, risk assessment, and audit logging. All system outputs are routed through natural language interpretation via a Cognitive Interpreter Service and Event Broker. Data Provenance & Source Governance is ensured with `data_lineage` and `bob_trace_log` tables. Schema Binding Validation & Learning Alignment provides comprehensive validation of data sources and cognitive learning alignment. A `SecureCoreService` restricts Walter's domains when enabled. The Continuous Learning Pipeline extends the Event Broker to capture trade events, generate insights, and transfer knowledge from paper to live trading. A `StateAwarenessService` provides a single authoritative snapshot of the entire system state for Walter and UI components, injected into Walter's system prompt. An Intent Execution Framework provides safe, audited execution of validated intents with full RBAC, state validation, and provenance tracking, logging operations to `intent_audit_log`. A `Pre-Execution Validator` ensures every trade intent undergoes comprehensive validation before placement. The Context Bridge enables real-time, bidirectional synchronization between Walter's panel, chat widget, and backend systems via WebSocket broadcasting, logging all broadcasts to `context_bridge_log`.

The Reasoning Orchestrator enables Walter's multi-step transparent reasoning via Domain Bobs (DevOps, FullStack, UX, TradingBob) for contextual analysis, building execution plans, queuing domain-specific tasks, and logging complete reasoning traces to `reasoning_trace` and `reasoning_queue` tables. The Memory Lifecycle Manager ensures semantic memory integrity through automated checksum validation, auto-repair from file_persistence backup, and nightly learning feedback aggregation from trade insights into `learning_fragments`. An Async Task Queue provides distributed multi-domain reasoning with parallel execution, retry handling, and Context Bridge integration, using a PostgreSQL-backed queue with optimistic locking. Cognitive Tuning & Testing provides automated performance validation and tuning for Walter's cognitive subsystems via a benchmark harness with scenarios like Intent Parsing Accuracy, Multi-Domain Coordination, Memory Recovery & Integrity, Reasoning Trace Completeness, and Response Quality Metrics, storing results in `cognitive_tuning_log` and broadcasting via Context Bridge.

The Autonomy Layer introduces self-directed analysis, meta-reasoning, exploratory learning, and automated optimization capabilities, enabling Walter to operate with higher-order cognition and continuous self-improvement. Key components include `AutonomyController`, `MetaReasoningEngine`, `CuriosityEngine`, and `SelfOptimizer`, which manage self-checks, anomaly detection, recursive reasoning analysis, knowledge expansion, and performance optimization respectively. This layer also incorporates `TradingBob` for market, portfolio, and risk analysis during autonomous self-checks.

The Emergent Awareness Layer enables meta-cognitive state tracking, self-reflection, and operational context awareness. The `AwarenessCoreService` aggregates system health, cognitive performance, active domains, and recent actions into a unified awareness state stored in the `awareness_state_log` table. The `AwarenessScheduler` runs hourly state updates and 6-hour deep reflections for comprehensive self-analysis.

The Adaptive Learning & Goal Alignment Foundation enables experience-based learning, policy-aligned adaptation, and autonomous self-improvement. Core components include `ExperienceMemoryService` for capturing and synthesizing operational experiences, `AdaptiveObjectiveEngine` for managing goal alignment profiles and adapting objectives based on performance drift, and `AlignmentVerifier` for ensuring all system actions and adaptations comply with defined policies.

The Strategic Planner & Continuous Learning Model (Phase 9.2) extends the Autonomy Layer with long-range strategic planning, continuous cognitive weight optimization, and policy-based guardrails. Core components include `StrategicPlannerService` for multi-phase strategic plan creation and progress tracking, `ContinuousLearningEngine` for adaptive cognitive weight adjustment through observation-adjustment-evaluation cycles, and `StrategicPolicyGuard` for enforcing strategic policies and ensuring compliance. The system uses `strategic_plan_log` and `learning_weight_profile` database tables to persist plans and learning state. Strategic plans support draft, active, paused, and completed statuses with JSONB-based progress tracking and alignment scoring. The learning engine operates in three phases (observation, adjustment, evaluation) with iterative weight refinement based on performance metrics. Automated scheduler tasks run strategy evaluation every 3 hours and learning updates every 6 hours, with integration into the Autonomy Controller for coordinated execution. Phase 9.2 metrics (strategic plan status, learning profile phase, policy compliance) are aggregated by the Awareness Core and broadcast via Context Bridge for real-time UI updates. The Enhanced System Monitoring UI includes a Strategy tab displaying Strategic Plans, Continuous Learning Profile, and Policy Compliance Status cards with live data refresh every 30-60 seconds.

The Strategic Memory & Simulation Engine (Phase 9.3) provides advanced decision forecasting and strategic lesson capture. `SimulationEngine` enables pre-execution strategy simulations with decision trace logging to `strategic_simulation_log` and `decision_trace_log` tables, allowing the system to evaluate potential actions before execution. `StrategicMemory` captures high-value lessons learned from simulations and operational experiences in `strategic_memory_snapshot` table, with automated lesson extraction and applicability scoring. Simulations support multiple types (risk_assessment, strategy_test, market_scenario) with predicted vs. actual outcome tracking and prediction accuracy metrics. The system runs automated simulation evaluation every 4 hours via scheduler integration, extracting strategic insights that inform future decision-making. Lessons are tagged with confidence levels, applicable contexts, and actionable recommendations. Context Bridge integration broadcasts simulation results and lesson extractions in real-time. The Enhanced System Monitoring UI includes a Simulation tab displaying recent simulations, strategic lessons learned, and prediction accuracy tracking with live data refresh.

The Reflective Intelligence Layer (Phase 9.4) enables meta-cognitive self-reflection and decision quality analysis. `ReflectiveIntelligence` provides four reflection depth levels: surface (basic pattern recognition), analytical (causal analysis), deep (systemic implications), and meta (reasoning about reasoning itself). The service performs automated reflection analysis logged to `reflection_log` table with insights, questions raised, improvement suggestions, and confidence scores. `DecisionQualityAudit` conducts post-execution analysis of decisions, logging to `decision_quality_audit` table with quality ratings (poor, fair, good, excellent), bias detection, lessons learned, and alternative approaches. The system detects cognitive biases (confirmation bias, availability heuristic, recency bias, overconfidence) and provides specific remediation guidance. Automated reflection analysis runs every 6 hours via scheduler, with deep and meta-reflections triggered on system state changes. The Autonomy Controller integrates surface-level reflections during self-checks and decision audits when issues are detected. Context Bridge broadcasts reflection completions and quality assessments in real-time. The Enhanced System Monitoring UI includes a Reflection tab displaying recent reflections, decision quality audits, bias detections, and meta-reasoning insights with live data refresh.

The Ethical Reasoning & Value Alignment Module (Phase 9.5) enforces ethical constraints and value alignment across all system operations. `EthicalReasoningEngine` evaluates actions against defined ethical rules stored in `ethical_rule_set` table, with rules categorized by value type (safety, fairness, transparency, accountability, user_welfare) and priority (critical, high, medium, low). Each rule defines constraint logic, violation actions (block, warn, log), and compliance thresholds. The engine performs pre-execution ethical checks with blocking enforcement on violations, logging all evaluations to `ethical_audit_log` table with compliance status (compliant, warning, violation, override), detected violations, and remediation recommendations. `ValueAlignmentService` manages the alignment matrix between system objectives and ethical values in `value_alignment_matrix` table, calculating weighted alignment scores across value categories. The system initializes with default ethical rules including risk limits (2% max), position sizing (10% max portfolio), decision transparency (reasoning required), and user welfare protection (5% max daily loss). The Autonomy Controller awaits ethical evaluation results and blocks execution on violations, pushing violation details to issuesDetected, triggering block actions, and broadcasting enforcement decisions via Context Bridge. Violations surface to operators with remediation guidance. Override capability exists for justified exceptions with full audit trail. The Enhanced System Monitoring UI includes an Ethics tab displaying compliance audits, active ethical rules, value alignment scores by category, and overall alignment percentage with initialization controls.

The Autonomous Task Scheduler coordinates all higher-order cognitive processes across Phases 9.0-9.5. Six autonomous tasks run continuously: self-checks (every hour), optimization (every 24 hours), strategy evaluation (every 3 hours), learning updates (every 6 hours), simulation evaluation (every 4 hours), and reflection analysis (every 6 hours). All tasks use async non-blocking patterns to avoid system interference, with comprehensive error handling and Context Bridge integration. The scheduler provides real-time status tracking for all tasks including last run time, next run time, and current status. Task execution is coordinated through the Autonomy Controller with full integration across simulation, reflection, and ethical enforcement systems. The Enhanced System Monitoring UI displays scheduler status across all tabs with real-time updates every 30-60 seconds.
