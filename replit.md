# Crypto Day Trading Web App

## Overview
This project is a long-only, spot-trading cryptocurrency day trading web application for Kraken. It automates advanced trading strategies, integrates real-time market scanning, disciplined risk management, and offers both live and paper trading capabilities. The application leverages OpenAI's GPT models for AI analysis, trade tracking, performance analytics, error diagnosis, and an autonomous learning engine. Its primary goal is to provide a comprehensive, resilient, and continuously improving self-optimizing trading platform with a focus on business vision, market potential, and project ambitions to deliver a leading-edge solution in automated crypto trading.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### UI/UX
The frontend is built with React, TypeScript, Vite, shadcn/ui (Radix UI + Tailwind CSS), and TanStack Query. It features a mobile-first, responsive design with dynamic mode-aware UI, microphone-based voice transcription, context-based persistent chat history, and a mode-aware toggle for trading engines with safety confirmations. A comprehensive, categorized notification system with smart filtering and actionable alerts is integrated. The chat sidebar includes increased width, always-visible action icons with tooltips, and full accessibility support (aria-labels, keyboard navigation).

### Technical Implementation
The backend uses Node.js with Express, providing a RESTful API and WebSocket support. Core services include `KrakenService`, `TradingEngine`, `StrategyEngine`, `MarketScanner`, `RiskManager`, `AIAnalyst`, and `AIOpportunitiesService`. PostgreSQL, accessed via Neon serverless driver and Drizzle ORM, handles data storage. Key features include 8 automated trading strategies, a multi-layered risk management system, AI-powered opportunity identification, and a Continuous Learning Engine (CLE) for optimization. Authentication uses username/password with bcrypt and JWT, and WebAuthn.

The system incorporates an AI Orchestrator & Command Center for monitoring and insights, powered by GPT-4o, and an AI SysAdmin Co-Pilot named Walter for system configuration and optimization with a dual-control system. Walter includes a Unified Command & Conversation Layer for natural language command interpretation, intent parsing, and routing to subsystems with safety confirmations and a persistent command logger. It includes a Semantic Memory Layer using pgvector and OpenAI embeddings, an Intelligence Refinement Layer with a Self-optimizing Cognitive Weight Adjuster, and an Autonomous Adjustments Actuation Policy. Diagnostics and auto-analysis are performed by `DiagnosticsAnalyzer` and "Bob Inspector Service." A Paper Trading Simulation Engine provides real-time execution and system-wide global session tracking ensures dashboard synchronization. Internal HTTP API endpoints facilitate cross-process communication for standalone scripts.

#### Feature Specifications
- **Real-time Data Synchronization:** Robust synchronization mechanisms between frontend and backend, including internal HTTP API endpoints for cross-process communication and auto-resync logic using system health polling and TanStack Query cache invalidation.
- **Mode-Aware Configuration:** All configuration tabs (Goals, Guardrails, Screeners, Strategies, Purpose) support independent LIVE and PAPER mode data, with visual indicators and automatic data refresh upon mode switching. Initial duplication from LIVE to PAPER mode is supported.
- **System Health Monitoring:** A comprehensive `/api/system/health` endpoint provides real-time status of backend, database, paper trading, and goals. A developer data flow trace panel is available for debugging.
- **Walter Communication Stabilization (Phase 7.0 Complete):** Walter communicates naturally with accurate, synchronized, mode-aware dashboard data, maintaining reliable intent detection and natural language error handling. It integrates a data pipeline to fetch live dashboard data, enhanced intent classification (command, inquiry, conversation), and provides natural language error handling. A health monitor re-enabled in `server/index.ts` polls system health and alerts on status changes.
- **Walter Communication Stability Reinforcement (Phase 7.1b Complete):** Extended OpenAI context-build timeout from 8s to 30s with early completion via Promise.race. Implemented mode-scoped prefetch of 6 dashboard endpoints on chat mount using Set-based tracking to handle mode switching. Added dynamic, non-blocking progress messages that advance asynchronously during API requests ("Gathering goals" → "Checking health" → "Finalizing"). All responses use natural language formatting with no raw JSON exposure. Optional provenance footer displays data timestamp, mode, and sources when VITE_WALTER_PROVENANCE=true.
- **Walter Intent Router + Fallback Enforcement (Phase 7.1c Complete):** Implemented universal output stringification via `ensureNaturalLanguageResponse()` function applied to all Walter response paths (chat + commands). Added conversational shield with pronoun detection (I, you, your, my, we, our) and stop-words to prevent phrases like "what is your purpose" from triggering command intents. Wrapped all command-router outputs in humanizer layer to convert technical payloads to natural language. Frontend validation checks response types with toast alerts for malformed data. Chat management controls added: New Chat button with confirmation, DELETE and POST endpoints for chat lifecycle, and storage method for context-based deletion.
- **Bob Core - Multi-Module Intelligent Cache (Phase 7.2 Complete):** Lightweight optimization coordinator with in-memory cache, configurable TTL, and module registration system. MetricsBob module provides parallel-fetch caching for `/api/system/health` and `/api/paper-sim/status` endpoints. Transparent routing layer intercepts health/metrics requests with zero-regression fallback to original handlers. Three prefetch triggers warm the cache: server startup (default mode), Walter chat open (current mode), and mode change (newly selected mode). Environment configuration includes BOB_ENABLED, BOB_METRICS_TTL_SECONDS, BOB_PREFETCH_ON_CHAT_OPEN, and BOB_PREFETCH_ON_MODE_CHANGE flags. Structured logging tracks cache hits/misses, prefetch operations, and fallback events. Performance counters available via `/api/bob/stats` endpoint.
- **DataBob - Dashboard Optimization Module (Phase 7.3 Complete):** Extended Bob Core with DataBob module to cache trading data endpoints (`/api/trading/results`, `/api/trading/averages`). User-scoped caching with mode awareness ensures each user gets personalized cached data. Transparent routing intercepts dashboard widget requests with graceful fallback to original handlers. Prefetch integration with Walter chat open and mode change events warms cache for faster dashboard loading. All DataBob metrics automatically tracked in `/api/bob/stats` endpoint. Default period 'today' optimizes most common dashboard queries. Note: Activity endpoint not cached due to period filtering incompatibility with original implementation.
- **ConfigBob - Configuration Optimization Module (Phase 7.4 Complete):** Extended Bob Core with ConfigBob module to cache 5 configuration endpoints: goals (`/api/goals/summary`), guardrails (`/api/guardrails`), screeners (`/api/screeners`), strategies (`/api/strategies/settings/all`), and purpose (`/api/walter/purpose`). User-scoped and mode-aware caching ensures personalized, isolated configuration data for LIVE and PAPER modes. Transparent routing intercepts configuration requests with graceful fallback to original handlers. Prefetch integration with Walter chat open and mode change events warms cache for instant configuration loading. All ConfigBob metrics automatically tracked in `/api/bob/stats` endpoint. Registered with 5 fetch functions for comprehensive configuration coverage.
- **StrategyBob - Strategy Intelligence Optimization Module (Phase 7.5 Complete):** Extended Bob Core with StrategyBob module to cache strategy performance and intelligence data. Handles 3 endpoint types: performance metrics (`/api/metrics/strategies`, `/api/paper/metrics/strategies`), historic signals (`/api/historic-signals`), and strategy summaries. User-scoped and mode-aware caching provides instant access to win rates, P/L metrics, R-multiples, prediction accuracy, and signal history for Walter AI queries and dashboard widgets. Transparent routing intercepts strategy endpoints with graceful fallback to original handlers. Prefetch integration uses conditional signal caching: chat open prefetches performance + summary only (lightweight), mode change prefetches all 3 including signals (comprehensive). All StrategyBob metrics automatically tracked in `/api/bob/stats` endpoint. Registered with 3 fetch functions (performance, signals, summary) for complete strategy intelligence coverage.
- **TradeBob - Trade Execution Optimization Module (Phase 7.6 Complete):** Extended Bob Core with TradeBob module to cache real-time trade data with ultra-tight 1-second TTLs. Caches 2 critical endpoints: `/api/trades/active` (all active trades, live+paper combined) and `/api/paper/trades/open` (paper-only open trades). Architecture follows combined-cache pattern per architect guidance: `/api/trades/active` cached as single union payload per user, with in-memory filtering for mode-specific Walter queries. User-scoped caching with transparent routing and graceful fallback to storage layer. Event-driven cache invalidation on trade close/update ensures real-time accuracy. Prefetch integration with Walter chat open and mode change for instant trade visibility. Registered with 2 fetch functions. All TradeBob metrics tracked in `/api/bob/stats` endpoint.
- **InsightBob & UIBob - System Introspection Modules (Phase 7.7 Complete):** Extended Bob Core with two context-awareness modules for Walter AI. InsightBob (5s TTL) tracks Bob Core health, cache performance metrics, module states, and recent system changes - enabling queries like "What changed?" or "What's the system health?". UIBob (300s TTL) tracks per-user UI visibility state including current view, subview, mode, and active filters - enabling context-aware responses like "What am I looking at?". Both modules integrate into Walter's prompt via `formatInsightContext` and `formatUIContext` functions. New endpoints: `/api/bob/insight` (GET) and `/api/ui/state` (GET/POST). Walter now receives system introspection and UI context automatically in all conversations. Goals table formatting: Average Return metric displays both goal and actual as percentages (e.g., "5.0%"), profit-based percentage metrics (Target Profit %, Monthly Return Goal %) display goals as percentages and actuals as dollar amounts (e.g., "$50.00"), while ratio/count metrics display as plain numbers.
- **Hybrid Cortex - Intelligent Memory Layer (Phase 8.0 Complete):** Introduced memory bridge layer between Bob Core (data) and Walter (AI) for short-term context storage and snapshot management. CortexCore service manages in-memory snapshots with configurable TTLs (300s short-term / 86400s long-term) via YAML config file. Automated sync scheduler runs every 30s pushing Bob snapshots to Cortex knowledge cache. Tracks 7 Bob modules (MetricsBob, DataBob, ConfigBob, StrategyBob, TradeBob, InsightBob, UIBob) with `formatCortexContext()` injecting snapshots into Walter prompts for faster context retrieval. API endpoints: `/api/cortex/status` (health), `/api/cortex/snapshot/:type` (retrieve), `/api/cortex/flush` (clear cache), `/api/cortex/force-sync` (manual sync). Cortex context automatically included in all Walter conversations alongside InsightBob/UIBob data.
