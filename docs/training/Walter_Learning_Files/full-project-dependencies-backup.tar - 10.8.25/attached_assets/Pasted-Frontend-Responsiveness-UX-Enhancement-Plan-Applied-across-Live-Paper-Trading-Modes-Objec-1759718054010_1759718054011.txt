Frontend Responsiveness & UX Enhancement Plan

(Applied across Live + Paper Trading Modes)

🎯 Objective

Enhance the usability, performance, and clarity of the trading interface:

Faster visual feedback and real-time feel.

Clearer navigation and data mode awareness (Live vs Paper).

Consistent visual hierarchy between dashboard widgets, reports, and briefs.

Seamless mobile and tablet responsiveness.

🧩 Scope
Phase 1 — Global UI Framework Improvements

Responsive Layout Grid

Migrate dashboard layout to fluid grid with breakpoints:

>1440px: 4-column wide layout.

1024–1440px: 3-column layout.

<1024px: collapses to 2-column stack.

<768px: single-column stacked layout.

Ensure widgets auto-resize (especially portfolio, daily brief, and charts).

Async Loading Feedback

Replace blank or shifting sections with skeleton loaders and spinners.

Introduce “updating” badges on widgets that auto-refresh (briefs, metrics).

State Persistence

Remember last selected mode (Live/Paper) and last active report tab between sessions.

Implement via localStorage (no backend dependency).

Visual Identity Updates

Update color palette:

Live Mode: emerald green accent.

Paper Mode: cool blue accent.

Add subtle header banner showing current mode.

Animate mode transitions (fade/slide).

Phase 2 — Dashboard & Widget UX

Widget Responsiveness

Portfolio Overview, Earnings Summary, and Daily Brief cards should:

Scale typography for mobile.

Prevent horizontal scrolling.

Support tap expansion (mobile).

Interactive Sparkline

Add hover tooltips showing date + earnings value.

Adaptive height for mobile (< 120px height).

Daily Brief Card

Display compact summary (2–3 lines) + “Read full briefing” button.

Graceful fallback when no brief is available (“Brief not yet generated”).

System Health Indicator

Add colored dot (green/yellow/red) showing backend health.

Tooltip: last sync time, API latency, and any warnings.

Phase 3 — Reports & Brief Pages

Unified Mode Navigation

Reports page adds a mode selector at top (Live / Paper).

Each report tab (Daily, Weekly, etc.) filters automatically based on mode.

Historical Brief Page

Correct labeling:

“Current Daily Briefing” for today.

“Daily Briefing for [Date]” for past days.

“No briefing available for this date” when empty.

Include breadcrumb (“Dashboard → Briefs → [Date]”).

Smooth Transitions

Use fade transitions when switching between modes or viewing dates.

Ensure navigation updates URL cleanly without reload.

Phase 4 — Interaction & Performance Enhancements

Live Data Refresh

Implement refresh intervals for all metric widgets (30–60 sec).

Add manual “↻ Refresh Data” button at the top right.

Optimized Rendering

Lazy-load charts and sparkline components.

Batch API calls on page load to reduce network overhead.

Touch Optimizations

Improve spacing for tap targets (buttons, tabs).

Swipe gestures:

Swipe left/right to navigate between daily briefs.

Accessibility (A11y)

Ensure all charts and badges have ARIA labels.

Use readable color contrast for light/dark modes.
