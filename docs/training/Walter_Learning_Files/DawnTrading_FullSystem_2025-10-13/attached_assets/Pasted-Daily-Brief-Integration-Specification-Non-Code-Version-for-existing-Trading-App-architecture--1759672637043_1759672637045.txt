Daily Brief Integration Specification — Non-Code Version

(for existing Trading App architecture)

🎯 Purpose

Create a Daily Trading Briefing feature that automatically summarizes each trading day — telling the story of how the day progressed, what trades were opened or closed, what worked or didn’t, system health, and any valuable lessons or actionable insights.

The report should update throughout the day and finalize automatically at end-of-day (UTC). It must be viewable on the dashboard and optionally sent by email.

1. Scope Overview

This feature adds a reporting and storytelling layer on top of your current app — using your existing backend, AI analysis system, and database.

No new infrastructure, accounts, or services are required.

Main deliverables:

A backend process that compiles, updates, and finalizes a Daily Brief each UTC day.

A dashboard card that previews the current day’s performance and recommendations.

A report view page that shows the full narrative and key details.

(Optional) An email sender to deliver the final daily report.

2. Functional Requirements
A. Daily Brief Lifecycle

Automatic creation each day (UTC 00:01)

System begins compiling data for the new trading day.

Brief status is set to “In Progress”.

Regular updates during the day

System refreshes the report several times per day (every 30–60 minutes).

Each update reflects latest trades, open positions, and performance metrics.

Automatic finalization (UTC 23:59)

System marks the day’s brief as “Final”.

Optional: sends a summary email to Kyle.

Manual access anytime

The most recent “In Progress” report should be viewable in real time.

Past reports remain accessible in the analysis/reports panel.

B. Report Content

Each Daily Brief should contain:

Headline & Summary:

A concise title describing the day’s overall result and tone.

One-sentence summary for dashboard preview.

Narrative Overview:

Storytelling description of how the day unfolded (morning → close).

Focus on what was learned and what drove results.

Key Metrics:

P&L %, win rate, drawdown, exposure, number of trades, realized/unrealized gains.

Trade Breakdown:

Brief summary of top winning and losing trades.

Highlight closed and still-open positions.

Learnings & Recommendations:

Lessons from the day’s performance.

Only include genuine recommendations that add value (no filler).

System Health Check:

Display any technical issues detected in market data, API connections, or data analysis.

If all clear, display “System operating normally”.

(Optional) Contextual Events:

Include external market influences detected that day (e.g., major announcements, macro moves).

(Optional) Forward Outlook:

Quick mention of what to monitor going into the next session.

3. User Interface Requirements
A. Dashboard Integration

Replace existing “AI Recommendations” / “Daily Performance Summary” section with:
“Current Day Performance & Recommendations Summary”

This card should display:

Headline (from the Daily Brief)

Key KPIs (P&L %, win rate)

One-line highlight of most important insight or recommendation

“Read Full Briefing” button

B. Full Daily Brief View

Accessible when clicking “Read Full Briefing.”

Structured view containing:

Headline and full narrative

Key stats and trade summary

Learnings and recommendations

System health and (optional) external events

Should visually match existing report styles.

C. Reports Panel Integration

Add Daily Briefs to the reports list.

Allow selection by date to view historical records.

D. Email Delivery (Optional)

Send one email per day at finalization.

Subject: Daily Trading Brief — YYYY-MM-DD

Body: headline, brief summary, and link to view full report.

4. Functional Connections
Component	Connection	Description
Trading Engine	Provides daily trade and P&L data	Used to summarize open/closed trades and performance
AI Analyst	Generates narrative and insights	Converts raw metrics into a readable, story-like report
Risk Manager	Supplies win rate, drawdown, portfolio metrics	Integrated into the report metrics section
Database Layer	Stores daily brief records	Reuse existing schema patterns with Drizzle ORM
WebSocket Server	Updates dashboard in real time	Sends live “in-progress” updates
Frontend Dashboard	Displays live summary card	Uses WebSocket or short polling
Email Service	Sends end-of-day summary (optional)	Simple SMTP/Gmail integration
5. Operational Flow (End-to-End)

Data Collection

Gather metrics and trades from the day.

Check system health logs.

AI Narrative Generation

Pass metrics and trade data to GPT-4o (existing OpenAI integration).

Receive structured summary including headline, narrative, and recommendations.

Storage

Save or update the Daily Brief record for today in the database.

Frontend Display

Dashboard fetches the live summary.

Detailed view available in reports section.

Finalization

At end of day, mark the report complete and send optional email.
