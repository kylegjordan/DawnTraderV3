Milestone 4 — Guardrails Wiring for Execution

When executing an opportunity:

Spot only (no margin/derivs).

Risk sizing: position size = R($)/stop_distance.

Caps: max exposure %, max open trades, per-trade R.

Slippage: simulate exit at stop vs. depth; compare to tolerance.

Balance: ensure free funds.

Duplicate symbol policy: avoid overlap unless allowed.

Start/Stop respected.

Return user-readable reason on fail; always audit.

Exit criteria: one failing case (blocked with reason + audit) and one passing case (orders placed, trades + audit persisted).

Milestone 5 — API Routes

Implement, document, and test the following:

GET /api/opportunities?filters…
Filters: status, type, symbol, probability_min, date range; pagination.

GET /api/opportunities/validation/latest
Returns the latest Validation Snapshot (see Milestone 6).

POST /api/opportunities/execute
Body: { opportunity_id } → guardrails → confirm modal flow → place OCO order(s) → set status='executed' → write trades → audit.

POST /api/opportunities/watchlist
Body: { opportunity_id } → status='watchlist' → audit.

POST /api/opportunities/dismiss
Body: { opportunity_id } → status='dismissed' → audit.

POST /api/ai/conversations/opportunity
Body: { opportunity_id } → create conversation titled Opportunity: {SYMBOL} – {TYPE} – {DATE}, seed first system/context message with the exact structured JSON, return conversation_id → audit chat_created.

Exit criteria: All routes respond with expected contracts and errors, and are covered in integration tests.
