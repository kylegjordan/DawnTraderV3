Non-Code Implementation Plan — Historical Brief Fix + Dashboard Placement Update
🎯 Objective

Fix the issue where historical daily briefs (by date) always show today’s brief.

Adjust dashboard layout to position the “Current Daily Briefing” section directly below the top widgets for clear visibility.

1️⃣ Bug Fix — Historical Daily Brief Retrieval
🔍 Problem Summary

When a user selects or navigates to a past brief (e.g., 2025-10-02), the app currently still loads the current day’s brief.
This happens because the frontend always requests /api/daily-briefs/today instead of the date-specific endpoint.

✅ Required Behavior

Detect the selected date

When navigating to a Daily Brief page (from the Reports tab or via URL), the app must read the date from the query parameter or route segment.

Example URLs:

/daily-brief → loads today’s brief

/daily-brief?date=2025-10-02 or /daily-brief/2025-10-02 → loads brief for Oct 2 2025

Call correct API endpoint

If date param is present → call /api/daily-briefs/{date}

If no date param → call /api/daily-briefs/today

Handle missing data gracefully

If the API returns null or 404 → show friendly message:

“No Daily Briefing available for this date.”

Page should not crash or show partial data.

UI indicator for context

When viewing an older brief, show a small label or banner at the top:

“Viewing Historical Brief — October 2, 2025”

When viewing today’s brief, display:

“Current Daily Briefing — October 5, 2025”

Navigation link

Include a simple “Back to Reports” or “View All Briefs” link for quick navigation.

🧪 Testing Instructions for Replit
Test	Expected Result
Visit /daily-brief	Displays today’s brief (“Current Daily Briefing — [today’s date]”)
Visit /daily-brief?date=<yesterday>	Displays that date’s brief, not today’s
Visit /daily-brief?date=<future date>	Shows “No Daily Briefing available” message
Reports page “View Brief” links	Open correct date-specific report
Dashboard “Read Full Briefing” button	Always opens today’s brief
Browser refresh on /daily-brief/:date	Page reloads correctly with same data
Console errors	None — page renders gracefully even with missing data
💼 Deliverables for the Fix

Replit should return:

Confirmation that /api/daily-briefs/:date endpoint is being correctly called from the frontend.

A short video or screen capture showing:

Opening a historical brief.

“No data” behavior for an invalid date.

Normal behavior for today’s brief.

Updated documentation note in replit.md or CHANGELOG.md describing the routing logic.
