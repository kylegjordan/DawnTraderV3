API Load Management Plan (for Replit)

This will ensure your dashboard and trading logic run smoothly 24/7 while staying far below Kraken’s rate limits.

⚙️ General Principles

Never exceed 1 private API call per 3 seconds.

Use caching to avoid repeat balance fetches within short timeframes.

Use fallback values from cache when Kraken is temporarily unavailable.

Log all API errors for visibility (especially rate-limit “EGeneral:Temporary lockout”).

🔄 Recommended Fetch Intervals
Endpoint	Purpose	Frequency	Notes
getAccountBalance()	Fetch wallet balances	every 60 seconds	Cached for 45–90s to prevent bursts
getOpenOrders()	Check active trades	every 60–120 seconds	Lightweight call
getClosedOrders()	Update trade history	every 10–15 minutes	Optional background sync
getTicker() / getOHLC()	Market data	every 1–3 seconds (public endpoint)	Not rate-limited per key
placeOrder() / cancelOrder()	Trading	as needed	<1 per trade event

✅ This ensures total private call load ≈ 1 call/minute average — ~1% of Kraken’s safe threshold.
✅ Zero chance of re-triggering a rate-limit lockout.

🧠 Caching and Error Handling

Cache balance, orders, and positions in memory (or Redis) with TTL = 45–90s.

On EGeneral:Temporary lockout:

Skip live calls for 2 minutes.

Serve cached data to dashboard.

Log:

timestamp

endpoint name

KrakenService error code/message

Auto-resume after cooldown expires.
