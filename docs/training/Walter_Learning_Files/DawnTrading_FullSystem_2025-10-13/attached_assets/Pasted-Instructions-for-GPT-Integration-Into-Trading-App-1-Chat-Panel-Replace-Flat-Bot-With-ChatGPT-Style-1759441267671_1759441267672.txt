Instructions for GPT Integration Into Trading App
1. Chat Panel (Replace Flat Bot With ChatGPT-Style)

Replace the current “customer service” style chat box with a ChatGPT-style conversation panel.

Support multi-turn context so GPT can recall recent exchanges.

Use the OpenAI Chat Completions API (gpt-4o-mini or equivalent).

Include message history in each request so it feels like ChatGPT (not a flat bot).

2. Data Access & Analysis

Connect GPT to the Postgres database (Neon) through a controlled service layer (middleware).

Allowed queries include:

Risk settings (trading_settings)

Watchlist/scanner results (watchlist_pairs)

Trades (open/closed history)

AI reports (ai_reports, ai_conversations)

Error logs (if stored in DB or log table)

GPT can query these tables only through safe, pre-defined SQL templates (not free-text SQL).

3. Ask → Confirm → Update Flow

GPT can propose a setting change when asked by user. Example:

“Set my risk per trade to $50.”

GPT should:

Retrieve current value (from trading_settings).

Respond with confirmation:
“You currently risk $25 per trade. Would you like me to update it to $50?”

Only after user confirms → execute the update in DB.

Keep UI fallback: user can still manually change settings in the Settings dashboard.

4. Audit Trail of GPT-Driven Changes

Add a new table: ai_audit_log with fields:

id (UUID)

user_id

timestamp

action_type (e.g., “update_setting”, “analysis_request”)

setting_name (nullable)

old_value (JSON)

new_value (JSON)

confirmation_method (e.g., “user_confirmed_chat”)

gpt_response (full text of GPT explanation)

Every confirmed GPT change is logged here.

Add “Audit Log” tab in dashboard so user can pull up full history.

5. Reports & Analysis

Reports (daily/weekly/monthly) should only be generated:

On user request (via chat or dashboard).

Or if user enables scheduled reports in settings.

GPT should query trades, ai_reports, and risk metrics to produce summaries.

6. Error Diagnosis

If app encounters an error (e.g., trade execution failed, scanner error), log details to DB (new error_logs table).

User can ask GPT:

“Why did my trade in ETH fail?”

GPT retrieves error log context and explains in plain English.

For code errors: GPT can analyze error logs/snippets/configs only if user requests.

7. Cost Control

Avoid streaming GPT tokens on every trade/scan.

GPT calls should only happen when:

User asks something in chat.

Reports are scheduled.

Explicit troubleshooting request.

Scanner/trading logic stays local — do not offload to GPT.

Set per-session token limits in backend (configurable).

8. Dashboard Integration

Keep existing Settings UI → always available.

Add AI toggle button: when clicked, ChatGPT panel opens.

Add Quick Action Buttons in chat:

“Change Risk Settings”

“View Open Trades”

“Get Daily Report”

“View Audit Log”

AI can guide user, but cannot bypass confirmation for sensitive updates.
