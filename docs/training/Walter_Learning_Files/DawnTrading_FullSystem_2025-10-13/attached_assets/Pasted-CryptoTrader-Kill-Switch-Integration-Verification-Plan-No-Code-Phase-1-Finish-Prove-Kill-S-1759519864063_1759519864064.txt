CryptoTrader – Kill Switch Integration & Verification Plan (No Code)
Phase 1 — Finish & Prove Kill Switch Integration

Goal: Ensure the daily-loss kill switch is fully wired into the pipeline and cannot be bypassed.

Risk Gate (Portfolio Layer)

Add/verify the first check in the pre-trade risk flow:
If tradingSuspended === true ⇒ reject any trade immediately with a clear log reason.

Confirm daily rolling-24h loss calculation triggers:

Warning at user setting (default 75% of limit).

Kill at user limit (default 7%).

On kill: close all open positions, set tradingSuspended = true, persist an event record, and emit notifications.

Signal Stage (Strategy Runner)

In the scan loop, before running any strategy on any symbol, check tradingSuspended.
If true ⇒ skip signal generation for all symbols; emit a single concise log:
“Trading suspended by Kill Switch — strategies skipped.”

UI/UX

Confirm Settings → Portfolio → Kill Switch section shows:

Daily Loss Kill Switch % (default 7.00).

Warning Trigger % of Kill Switch (default 75.00).

System-controlled Trading Suspended indicator + manual Resume Trading toggle.

Confirm Kill Switch screen:

Red banner “Trading Suspended.”

Equity before/after, % loss vs limit, timestamp (user TZ).

Collapsible trade breakdown (symbol, strategy, entry/stop/target, PnL).

“View Analysis in ChatGPT” button.

Notifications & Audit

Verify push/email/Telegram fire on warning and kill with human-readable text.

Ensure event logging captures: window start/end for rolling-24h, equity before/after, % loss, trade list, and who/what resumed trading.

Deliver back:

Short note confirming where the tradingSuspended checks live (file + function names).

Screenshot of Kill Switch Settings + Kill Switch screen.

Sample warning and kill notifications (payloads or screenshots).

One event log sample (redacted OK).

Phase 2 — Controlled End-to-End Tests (No Live Funds)

Create /api tests (or run via internal tooling) to simulate PnL:

Case A (Warning): push rolling-24h loss to ~75% of limit ⇒ expect warning only, no suspension.

Case B (Kill): push loss to >100% of limit ⇒ expect trades closed, suspension = true, redirect to Kill Switch screen.

Case C (Blocked While Suspended): attempt to place a trade ⇒ blocked at risk gate and strategies skipped.

Case D (Resume): user toggles “Resume Trading” in Settings ⇒ tradingSuspended = false, next valid signal can execute.

What to capture

Logs showing the sequence for each case.

Screenshots: warning banner, kill screen, and successful resume.

Deliver back:

Test outputs (logs) for A/B/C/D.

Confirmation that redirect rules allow only /kill-switch and /settings while suspended.

Phase 3 — Strategy & Guardrail Re-verification (Post Kill Switch)

Lenient Screener config (e.g., lower min volume/range) to guarantee a few signals.

Confirm:

Strategies still pull DB settings (no hardcoded thresholds).

Signals are produced only for screener-eligible pairs.

Guardrails (risk per trade, exposure %, max open trades, slippage, stop buffer) behave as before.

Trigger a soft warning (not kill) during active signals to validate non-blocking alert.

Deliver back:

Brief run log showing: Screener → Strategy signals → Guardrail decisions → Executions.

A note that strategy behavior was unchanged by kill switch (as intended).

Phase 4 — ChatGPT Analysis Button (Incident Flow)

On Kill Switch screen, tapping “View Analysis in ChatGPT”:

Open a new conversation pre-filled with the incident context:
equity before/after, % loss vs limit, rolling-24h window, trade list with PnL, settings snapshot (screener/strategy/guardrails).

ChatGPT returns an analysis + recommendations.

Offer actions: Accept recommendations, Ask follow-ups, Reject & Edit Settings.

Privacy & Idempotency

Ensure the payload excludes secrets/API keys.

Multiple taps should not spawn duplicate chats (dedupe by incident id).

Deliver back:

One example chat creation payload (redacted) and the first ChatGPT turn output.

Screenshot of the CTA buttons beneath the analysis.

Acceptance Criteria (quick)

Trades never execute when tradingSuspended = true.

Strategies never run when suspended.

Warning triggers without blocking; Kill triggers blocking + close-all.

Kill Switch screen is the first view after a kill event; Settings remain accessible.

ChatGPT incident chat launches with full context on demand.
