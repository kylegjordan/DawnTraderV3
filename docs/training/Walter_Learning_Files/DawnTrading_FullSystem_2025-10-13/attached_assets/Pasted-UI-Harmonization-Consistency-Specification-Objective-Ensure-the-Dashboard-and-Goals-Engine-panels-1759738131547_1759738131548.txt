UI Harmonization & Consistency Specification
Objective

Ensure the Dashboard and Goals Engine panels share a cohesive, professional, and intuitive visual language — making them feel like parts of a single, integrated control system.

This specification covers layout, typography, interactivity, color coding, and responsiveness across all widgets and tables introduced in the Dashboard and Goals Engine.

1. 📊 Dashboard Panel — Unified Visual Language
1.1 Widget Styling

All dashboard widgets (Portfolio Value, Earnings, Trading Activity, Results, Averages, and Goals Summary) should share:

Card structure: Rounded corners (2xl radius), subtle shadow, consistent padding (p-4 / p-6), and soft hover elevation.

Header layout: Title aligned left, small subtext for timeframe or unit aligned right.

Typography:

Title → text-sm font-semibold text-gray-500 uppercase tracking-wide

Metric Value → text-3xl font-bold text-gray-900

Delta/Change → text-sm font-medium with green/red color coding.

Color coding conventions:

Positive metrics → green (#10B981)

Negative metrics → red (#EF4444)

Neutral / steady → gray (#6B7280)

Responsive behavior:

Desktop: 4 widgets per row (equal width).

Tablet: 2 per row.

Mobile: 1 per row (stacked layout).

Hover feedback: Subtle background shift or glow to indicate interactivity (if clickable).

1.2 Goals Summary Widget

Positioned below the 4 primary widgets.

Spans the full width of the dashboard grid.

Displays a Goals Table with columns:

Metric | Goal | Actual | % Achieved

Table styling:

Alternating row background color.

Center-aligned percentage column.

Goal-achievement bar or pill:

≥100% → solid green pill.

80–99% → yellow pill.

<80% → red pill.

“Edit Goals” link placed top-right in header, styled like a text button (no border, hover underline), linking to Goals Engine Panel → Goals Tab.

2. 🎯 Goals Engine Panel — Structure & Visual Consistency
2.1 Panel Layout

The Goals Engine panel appears directly below the Dashboard in the navigation.

Page layout mirrors the dashboard in spacing and header format:

Page title → large header: text-2xl font-bold text-gray-800

Subtitle → smaller note beneath, describing the purpose.

Include a persistent mode badge at top (Live / Paper).

2.2 Tabs (Five Tabs)

Tabs within Goals Engine:

Goals

Portfolio

Guardrails

Screener Filters

Strategies

Tab design:

Active tab → highlighted with accent border and bolder text.

Inactive tabs → muted gray text; hover underline on hover.

Mobile: collapsible dropdown version of the tab bar.

2.3 Goals Tab

Top section: Editable Goals Table

Structure matches dashboard Goals Summary widget, but inputs enabled in the “Goals” column.

Fields:

Earnings per trade

Average return (%)

Earnings per day / week / month / year

Interdependent auto-calculation:

Editing one updates the others proportionally.

“Save Goals” button below table (primary accent color).

Below the table: AI Goals Chat Interface

Fixed-height chat container (scrollable).

Messages color-coded:

AI Analyst messages → light blue background.

User messages → light gray background.

“Send” button enabled when text exists.

AI should summarize adjustments and confirm when goals are finalized.

2.4 Other Tabs (Portfolio, Guardrails, Screener, Strategies)

Each uses consistent section headers and styling.

Form fields styled identically to Goals input fields.

Subtle vertical separators for clarity.

Sticky “Apply Changes” or “Revert” controls at bottom.

3. ⚙️ Interaction & Data Feedback
3.1 Loading States

All widgets and tables should include a skeleton loader or spinner.

For empty data, display friendly placeholders:

“No trades yet — data will appear as positions open and close.”

3.2 Hover & Tooltip Behaviors

Hovering over any metric or % shows tooltip with:

Metric definition.

Last updated timestamp.

Source (Live / Paper mode).

3.3 Goal Alignment Feedback

When AI analysis suggests variable adjustments:

Display proposed changes in a structured summary:

Strategy Adjustments

Guardrail Updates

Screener Filter Tweaks

Each change has a small checkbox next to it.

When user clicks “Agree and Apply,” the system implements changes and confirms with success toast notification.
