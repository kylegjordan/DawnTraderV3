0.1 TypeScript Errors (priority: 🔴)

Goal: Reduce TypeScript errors to zero without changing runtime behavior.

Instructions

Baseline scan & grouping

Generate the full TypeScript error list and group by:

Missing/incorrect types on component props

Null/undefined access (optional chaining/guards)

Union type narrowing (e.g., mode-dependent objects)

Index signatures and array access (unchecked index access)

Async/await return types and Promise shapes

Incorrect or missing imports for shared types

Tackle by folder in this order: src/types → src/lib → src/services → src/state → src/panels → src/routes.

Shared “Mode” typing

Introduce a single shared “mode” type covering paper and live and ensure every API call, store slice, selector, and DB-bound function accepts or provides this value explicitly.

Propagate it from the app’s central state to:

API request layer (inject as a header on every request)

Query keys (so caches are isolated per mode)

Selectors (so in-memory state is partitioned by mode)

Path aliases

Ensure path aliases are defined and consistent for:

@/* → client source

@server/* and @db/* → server code and Drizzle models

Update any imports still using long relative paths.

Strictness clean-up (do not change behavior)

Replace unsafe array/record access with conditional checks.

Narrow unions using explicit guards (e.g., check for required keys).

Add explicit return types for exported functions that currently infer poorly (especially async functions returning structured data).

Convert any “implicit any” situations into explicit types or generics.

Re-run TypeScript; repeat until zero errors

Iterate until all errors are resolved.

Do not introduce new runtime behavior or side effects while fixing types.

Acceptance Criteria

TypeScript build reports 0 errors.

No functional changes observed in the main user flows (dashboard load, auth, watchlists, screeners).

0.4 Structured Logging (priority: 🟡)

Goal: Replace ad-hoc console.log calls with minimal structured logs to simplify debugging during paper trading.

Instructions

Introduce a single logging utility (client + server)

Methods: debug, info, warn, error.

Output JSON with fields: application name, environment, level, message, optional context, timestamp (epoch).

In development: allow debug; in production: restrict to info and above.

Replace occurrences

Search for all console.log (and other console.* where appropriate) and replace with the logger.

Keep console.error only in truly exceptional paths; otherwise switch to logger’s error.

Redaction

Ensure log helper redacts tokens, secrets, and PII (e.g., API keys, auth headers, JWTs) if they appear in objects.

Acceptance Criteria

No raw console.log remain in the repository.

Logs in both browser devtools and server output appear as single-line JSON objects with the required fields.

Sensitive data is not printed in logs.
