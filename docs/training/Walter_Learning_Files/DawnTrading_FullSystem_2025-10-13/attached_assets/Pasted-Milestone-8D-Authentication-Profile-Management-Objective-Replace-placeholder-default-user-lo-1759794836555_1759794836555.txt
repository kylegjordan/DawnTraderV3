Milestone 8D — Authentication & Profile Management
🎯 Objective

Replace placeholder default-user logic with authenticated user profiles.
Ensure all API routes save and retrieve data per verified user ID, preparing the platform for multi-user operation, personalized dashboards, and secure cloud persistence.

📂 Scope of Work

This milestone adds secure authentication and user scoping across:

Database schema — users table with profile data and relationships

Backend routes — auth-aware wrappers for /api/strategies/*, /api/goals/*, /api/system/*

Frontend context — user session awareness and profile loading

Settings panel — user preferences (timezone, notifications, etc.)

🔧 Implementation Tasks (no code, procedural)
1️⃣ Create User Schema and Relationships

Inspect existing schema (shared/schema.ts).

Add a users table with fields:

id (UUID or string auth identifier)

email (unique)

displayName (optional)

timezone (default UTC)

createdAt, updatedAt

Add userId foreign-key references to:

strategySettings

goals

guardrails

ai_audit (if applicable)

Run a schema migration / npm run db:push to confirm.

Deliverable: Screenshot of updated schema migration log showing new users table and relationships.

2️⃣ Integrate Authentication Middleware

Review how Replit’s auth context or current auth system is set up.

Create a middleware function that:

Verifies the incoming JWT or session token.

Extracts userId from token claims.

Attaches it to req.user.

Apply this middleware to all routes that read/write user data:
/api/strategies/*, /api/goals/*, /api/system/*.

Deliverables

Screenshot of routes file showing middleware usage.

Console log from authenticated request proving req.user.id is present.

3️⃣ Adjust API Routes for User Context

Modify each storage method to filter by userId.
Example: getStrategySettings(userId, mode) instead of global query.

Ensure POST/PUT requests save records with the authenticated userId.

Add server-side validation to prevent cross-user access.

Deliverable: API response JSON showing "userId": "<token-id>" field returned for a strategy record.

4️⃣ Update Frontend User Session Handling

In the frontend root context (e.g. App.tsx or layout.tsx):

Detect and store logged-in user session.

Expose user.id, user.email, and user.timezone via context.

Replace any hard-coded default-user headers with dynamic auth token headers.

Add a global state refresh when user logs in or out.

Deliverable: Screenshot of browser Network tab showing authenticated API calls with user token header.

5️⃣ Enhance Settings Panel with User Profile

Under Settings, add a “Profile Preferences” section below Notifications with:

Email (locked read-only from auth)

Display Name (editable)

Timezone (drop-down with common zones)

Saving updates calls PUT /api/users/profile.

Confirm profile updates persist to the database.

Deliverables

Screenshot of Settings page showing Profile Preferences form.

Database query output showing updated timezone for user.

6️⃣ Verification Checklist & Testing
Test	Expected Result
API without token	401 Unauthorized
API with valid token	200 OK and user-scoped data
Save strategy → refresh	Values persist only for logged-in user
Switch users → new config	Independent data per user
Update timezone → refresh	Setting remains saved and used in timestamps
Console and LSP errors	None

Deliverables

Table summarizing pass/fail results of each check.

Screenshots of two different user profiles showing distinct strategy configs.

7️⃣ Final Integration Review

Confirm Goals Engine and AI Analysis tabs still function with auth context.

Verify Systems Monitoring logs still load (but now filtered by user).

Check no console or TypeScript errors after reload.

Deliverable: Short summary confirming “all modules operational under authenticated context”.

✅ Users table created and linked
✅ Auth middleware protects API routes
✅ Frontend API calls include token
✅ Settings panel shows user profile and timezone
✅ All data persists per user
✅ No regressions in Goals, Strategies, or Monitoring tabs
