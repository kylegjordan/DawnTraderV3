# Directive 11.7P — Passive Decision Schema v1.0

**Date**: 2026-01-28
**Schema Version**: passive-decision/v1.0

## Overview

This document defines the canonical schema for Passive Decisions — the evaluation records generated by VTS (Virtual Trade Simulator) during passive learning mode.

## A1. Definition: What is a Passive Decision?

A **Passive Decision** is defined as:

> A signal evaluated by VTS that results in either:
> - **Accepted** → Simulated Trade Created (logged to `logs/virtual_trades/`)
> - **Rejected** → Skipped with explicit reason (logged to `logs/vts_skipped_signals/`)

Passive decisions occur during paper/passive mode when the VTS is running simulations. No actual trades are placed.

## A2. Canonical Decision Fields

Each decision record MUST expose the following fields:

| Field | Type | Description | Source |
|-------|------|-------------|--------|
| `timestamp` | ISO 8601 string | Evaluation time | Both logs |
| `symbol` | string | Trading pair (e.g., "BTC/USD") | Both logs |
| `signalType` | enum | `QUANT` / `HYBRID` / `PATTERN` | Both logs |
| `strategy` | string | Strategy evaluated (e.g., "mean_reversion") | Both logs |
| `regime` | string | Market regime at decision time | Both logs |
| `outcome` | enum | `ACCEPTED` / `REJECTED` | Derived |
| `reason` | string | Skip reason for rejected, "Trade_Created" for accepted | Skipped log |
| `expectedReturn` | number | Expected ROI if available | Both logs |
| `netEV` | number | Net expected value if available | Virtual trades |
| `finalScore` | number | Final score if available | Both logs |

## A3. Skip Reasons (Rejection Codes)

The following canonical skip reasons are defined:

| Reason | Description |
|--------|-------------|
| `Low_ROI` | Expected return below minimum threshold |
| `Illiquid_USD` | Insufficient USD volume |
| `Net_EV_Negative` | Net expected value is negative |
| `FinalScore_Low` | Final score below threshold |
| `RegimeWeight_Low` | Regime weight below threshold |
| `ADX_Guard` | ADX guard filter triggered |
| `Duplicate_Position` | Position already exists for this symbol |

## A4. Data Sources

### Rejected Decisions
- **Location**: `logs/vts_skipped_signals/{date}.json`
- **Format**: JSON array of SkippedSignalEntry objects

### Accepted Decisions
- **Location**: `logs/virtual_trades/{date}.json`
- **Format**: JSON array of VirtualTrade objects
- **Derived**: outcome = "ACCEPTED", reason = "Trade_Created"

## A5. UI Display Requirements

The Decision Traceback UI must:

1. Display last N decisions (default: 100)
2. Clearly label: "Passive Learning — Pre-Execution Decisions"
3. Group decisions by:
   - Accepted (with count)
   - Rejected (with counts per reason)
4. Show explicit disclaimers:
   - "These are pre-execution evaluations"
   - "No trade was placed unless marked Accepted"
   - "This does not represent live execution logic"

## A6. API Contract

### Endpoint: `GET /api/vts/passive-decisions`

**Query Parameters:**
- `limit` (optional, default: 100): Maximum decisions to return
- `date` (optional, default: today): Date to query (YYYY-MM-DD)

**Response Schema:**
```json
{
  "decisions": [
    {
      "timestamp": "2026-01-28T05:40:55.072Z",
      "symbol": "API3/USD",
      "signalType": "QUANT",
      "strategy": "mean_reversion",
      "regime": "BEAR_VOLATILE",
      "outcome": "REJECTED",
      "reason": "Low_ROI",
      "expectedReturn": 0.0164,
      "finalScore": null
    }
  ],
  "summary": {
    "total": 100,
    "accepted": 5,

  }
}
```

## Governance

- This schema is read-only with respect to system behavior
- No trading logic, learning logic, or threshold changes are permitted
- This directive enables observability only
