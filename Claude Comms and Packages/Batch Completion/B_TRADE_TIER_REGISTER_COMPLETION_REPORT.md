## THE TWO LOAD-BEARING ARGUMENTS LANGSTON REQUIRED THIS REPORT TO CARRY

**1. Why the resume-skip cannot lose rows (the append-frozen composition).** The plain lane's cutoff moves daily, slicing the boundary day across runs. Run 1 exports day D and gets it verified; run 2's `archiveOneObject` resume-skip (verified/active + checksum → `reused`) silently skips re-export while run 2's delete removes D's newly-eligible tail. **This composes safely for exactly one reason: the export is the UNCLAMPED FULL DAY `[D, D+1)` and `closed_at` is stamped at close time — so a day that has begun aging is APPEND-FROZEN; no new row can ever join it.** The skipped re-export therefore cannot miss rows: everything run 2 deletes from day D was already inside run 1's verified export. If either premise ever changes (a clamped export, or a mutable timestamp), this argument dies and the resume-skip becomes a data-loss path — which is why it is written here and pinned to its premises.

**2. The crash-window reconciliation path.** Between the tally UPDATE and the delete's completion there is a crash window: survivors of an interrupted delete get RE-tallied next run — a permanent over-count in the anneal's denominator. Direction is conservative (an over-count TIGHTENS the exploration floor — the lane subsidizes less, never more), magnitude is bounded by one run's exploration closes, and **the truth is recountable at any time from the warm JSONL objects themselves** (each archived range's exploration-close count is derivable by replaying the reader's predicate over the exported rows; the manifest rows locate every object). Reconciliation is thus an offline audit, never a live emergency.
