## C. The REAL firing change — removing the floor-LIFT (not the RR consolidation)
Today the lift inflates a sub-floor target UP to 4% BEFORE the RR gate, so a signal with a sub-4% RAW target + sub-2.5 RAW RR can be **rescued** (lift raises target → RR clears 2.5). Remove the lift → the raw target faces RR 2.5 directly → those rescued signals DROP. Per the VTS study this concentrates on **xStock** (median target 3.5%, ~60% sub-4%): **removing the lift reduces xStock signal flow by dropping the sub-floor targets that were only passing because the lift inflated them past RR.** This is CORRECT-tightening (don't fabricate reward to clear a gate) but MATERIAL, and it ties directly to xStock per-class calibration (#336 / Phase-25 25-17 — xStock minRR/floor/reach set on real data). **Crypto largely unaffected** (study: ~78% of crypto targets already ≥4%, rarely lifted). This is the headline behavioral effect of the batch and must be in the completion report + surfaced in the VTS Filter-Diagnostics tabs (the drops become visible by-reason).

## D. Per-detector formula-fit / carve-out check (Langston add #2)
RR (`(target−entry)/(entry−stop)`) and reachability (`(target−entry)/ATR ≤ reachAtrMax`) are **formula-AGNOSTIC quality/feasibility measures** — a low-RR or volatility-unreachable target is genuinely lower-quality regardless of how the strategy set it — so neither "misapplies" in the sense of wrongly dropping a GOOD signal; they apply correctly across all target methods (ATR-multiple / R-multiple / measured-move / structural-ceiling / percent). **Decision-rule result (per Langston):** we found NO case of the guard misapplying to a formula it doesn't fit → **no strategy needs a formula-aware CARVE-OUT for correctness.** What we DID find is a THRESHOLD-calibration question for two families (NOT a consolidation regression — the normalizer already applies these today): (a) **measured-move** strategies (breakout `entry+rangeHeight`, volatility_edge `min(measuredMove, atrTarget)`) can carry a legitimately large target → `reachAtrMax` could flag a genuine wide-range breakout as "unreachable"; (b) **2.5 minRR** may sit above some measured-move/ceiling strategies' natural RR. Both are PRE-EXISTING (live since reorg-B2) and are **per-class/per-strategy threshold-calibration items → Phase-25** (fold into 25-17), NOT blockers for the placement move. Per-detector wiring still gets the VTS before/after continuity check, read against this rule (correct-tightening = acceptable; no misfit found).
