## 2. Objectives — each with its verification
**OBJ-1 — the backups, proven by REPRODUCTION, not by a scheduler result.** For each of the two backups: restore one known transcript from the Drive copy (oldest, largest, newest of a session) and match its SHA-256 against the laptop file; for the zip, list the archive and extract one entry. State which sessions each backup covers. If a backup fails its restore, that is a finding with its own disposition, not a silent re-run.
**How a match is judged (Langston C-1):** transcripts are append-only and both backups run hours before any check, so a whole-file hash of a file still being written proves nothing either way. Per file: the backup copy's **size**, the laptop file's **size and modified time**, and SHA-256 of the laptop file's **first N bytes, N = the backup copy's size** — on an append-only file a prefix match is the proof. A whole-file hash only where the sizes are equal, which means a closed conversation; each pick is labelled closed or live. **`DT-SHARED-MEMORY` is rewritten, not appended, so no memory file is one of the three for backup 1.**
*Verify:* three prefix matches per backup (or the named failure), with sizes, mtimes and commands in the change list.

**OBJ-2 — the distiller and redaction, and a ONE-DAY SAMPLE TO KYLE BEFORE ANYTHING ELSE RUNS (Kyle's gate).** A new read-only tool turns one raw `.jsonl` into the readable form: Kyle's messages and the replies, timestamped; each action as ONE line (time · tool · the session's own description · the file edited, commit sha, or command cut to one line · a one-line error on failure); compaction summaries whole; raw tool output dropped. **Redaction before anything is written:** base64 blobs and the secret patterns (Anthropic tokens `sk-ant-…`, B2 keys, bearer tokens, private-key blocks, `oauth.env` values) become `[REDACTED <kind>]`. The raw file is never modified.
**Where the kind list comes from (Langston C-3):** derived at Step 2 from the credentials this project actually holds — `CLAUDE.md`, `B_CREDENTIALS_PRIVATE_REPO` scope, the `.env` key names on both servers and the laptop's `~/.claude` key files — each kind named with its source, not recalled.
*Verify:* (a) a redaction test with planted secrets of every kind, each found, plus a mutation run that removes each pattern and is caught; (a2) **`[REDACTED <kind>]` counts per kind over the real corpus, published** — a kind at zero is either absent or a pattern that cannot match, and the planted test cannot tell those apart, so each zero is named and looked at; (b) the tool run on one real day of one session, the output read in full by me, and **sent to Kyle as the sample; nothing in OBJ-3 runs before he says it is right.**

**OBJ-3 — the full archive, the index, the action list and the search command.** `C:\Users\kyleg\.claude\transcript-archive\` (outside every repo: transcripts carry Kyle's private messages): `<alias>\<YYYY-MM-DD>_<session-id8>.md`, `INDEX.md` (one line per conversation), `ACTIONS.tsv` (every action line, all sessions). `dt-recall "<words>" [--alias] [--since] [--batch] [--actions]` returns `file:line`, time and two lines of context. **A hit is a lead, never a fact; "not found" is never evidence** (#453) — printed in the tool's own output. Kyle's *"one-page index in the shared memory folder"*: that folder is mirrored into git (Langston verified: `.claude/memory/` carries the session memory files), and the full index names conversations with Kyle's private messages. **DECIDED — Kyle, KD-49 (2026-11-06, `1-system-manual/pm/DECISIONS.md:72`): option (iii), the index in the shared memory folder WITHOUT the topic text** — alias, date, session id, batch ids, line count; nothing private reaches the git mirror. The full index (with topics) stays in the archive outside every repo. Kyle still reviews the one-day sample at P4 before P5 runs.
**File names must be injective (Langston C-5):** before anything is written, the full raw set's target names are computed and checked for collisions; a collision stops the run loudly (a `.md` overwrite is silent).
*Verify:* the collision check run first, with a planted collision caught; every raw `.jsonl` on the laptop has an archive file (count matched per session folder, with the folder list read from disk, not typed); a planted phrase in a known conversation is found with the right `file:line`; a search for a phrase that exists only in a redacted secret returns nothing and says so.

**OBJ-4 — capture at every forgetting event.** (a) nightly, incremental from a stored byte offset per file, as a Windows scheduled task; (b) at compaction, a `PreCompact` hook distils the live conversation up to that point; (c) at a restart, the handoff procedure (OBJ-5) distils the ending conversation before the new one starts. Hooks fail open, so (a) is the backstop.
**One owner for the offset (Langston C-2).** All three triggers distil the same raw file into the same archive, so one module owns the per-file offset and every trigger goes through it, under a per-file lock. **The write is idempotent on the raw entry's `uuid`:** an entry already archived is skipped, so a re-run duplicates nothing. **The offset advances only after the archive write is durable** (written, flushed, renamed into place); a trigger that dies before that leaves the old offset and the next run re-reads the same bytes, which the `uuid` check makes harmless. Nothing advances an offset past bytes that were not written.
*Verify:* each trigger alone in a scratch run; **then the interleave — a compaction distil followed by the nightly pass over the same file, asserting no duplicate `uuid` and no gap (every entry of the raw file present once); then the crash case — a distil killed after the archive write and before the offset advances, then re-run, asserting the same**; the nightly task's first SCHEDULED run read back, not the hand run (`#1132`: a hand run does not test a scheduled unit).

**OBJ-5 — the restart handoff, its injection and the drift guard (design §4-§5).** `handoff\<alias>\<UTC>.md` with the 14 fields (including withdrawn claims, owned triggers with their instruments, the active pack, the archive link; every live value as pointer plus stamped reading). A new `SessionStart` hook (the `load-own-memory.mjs` pattern: fail open, inject nothing on an unmapped folder) injects the latest handoff and prints `DRIFT` lines; `STALE (drift)`, `AGED (backstop, no drift found)` and `GUARD FAILED — <leg> not checked` are distinct, a missing banner counts as STALE, and STALE clears only on a corrected re-derived field. Break points only at a finished step. **The hook's independent dispatch source (Langston C-4):** the open dispatches are enumerated from the inbox log on Helsinki (`/var/log/cc-discord-inbox.jsonl`: this session's `cc_outbound` rows since the previous handoff, minus those with a later reply addressed to it), never from the handoff it is grading. If that source cannot be read at hook time, the hook prints `GUARD FAILED — open-dispatch leg not checked`, never a green.
*Verify:* the five-run drill exactly as design §5 states it — omitted gate-holding dispatch (`MISSING_OPEN_DISPATCH <id>`, from an independently enumerated population), stale ref, guard failure, aged backstop, and a positive control for every leg — each green → red for the right reason → green. Any leg failing stops the trial.

ALL history is kept.
*Verify:* the duplicate list with hashes; the move recorded with before/after counts.
