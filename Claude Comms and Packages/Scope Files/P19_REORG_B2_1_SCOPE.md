## Premise (the converged decision)
The reorg-B2 helper `signal-target-normalizer.ts` did three things to a freshly-built signal: floor-LIFT, RR-gate, reachability-gate. Investigation across all 19 strategies showed: (a) the floor-LIFT is a **target mutation** that for measured-move/ceiling strategies (breakout, volatility_edge, range_trade, mean_reversion) manufactures a target the strategy never chose, AND is redundant with the **Net-Expectancy gate (11.8B)** which already enforces beat-friction per-signal (the floor's intent); (b) the RR-gate **already exists** for 10 file-based strategies via the shared `strategy-helpers.applyGlobalGuards` (RR≥1.5) — the normalizer re-gates at per-class 2.5, a **live split-brain** (stricter silently wins, the helper's guard becomes dead code misreporting the threshold); (c) reachability is genuinely new + formula-agnostic. Because VTS calls `strategyEngine.detect*` directly, gates living in the **shared strategy-guard layer** auto-cover BOTH active and VTS, killing the helper's dual-wiring. **Kyle decision 2026-06-21:** rely on the Net-Expectancy gate as the cost-coverage judge for now (its judgment-quality validation is a named Phase-25 item — see Governance); do NOT keep a flat 4% floor as a separate gate.

## Objectives
1. **DROP the floor-LIFT entirely** (not relocate). **TWO BLOCKING pre-pull verification gates (Langston) — must pass in Step-2 before the removal lands:** (1a) prove NO downstream consumer keys off the LIFTED target value (trace RTB pool, TEC sizing, diagnostics, VTS logging, sizing) — or migrate it in this batch; (1b) confirm the NetEV gate genuinely fires on EVERY path the normalizer guarded (active + VTS + any cold-start/VTS-only path) — else removal opens an ungated hole. If (1b) finds an uncovered path, that path keeps a check rather than opening a hole.
2. **CONSOLIDATE the RR-gate to ONE per-class SSOT** in `strategy-helpers.applyGlobalGuards` — read the per-class `min_rr` (the reorg-B2 `expectancy_gates.min_rr` rows) instead of the hardcoded `MIN_RR_RATIO=1.5`; the 1.5 becomes a config floor or is removed. Kills the split-brain.
3. **MOVE the reachability-gate** into `applyGlobalGuards` (per-class `reach_atr_max`; formula-agnostic).
4. **WIRE the ~9 in-class detectors** (`strategy-engine.ts` — vwap_pullback, abcd_long, sma_trend_ride, breakout, mean_reversion, range_trade, vwap_bounce, dhma, + liquidity_trap[disabled]) into `applyGlobalGuards` (they bypass it today). **Per-detector: a Step-2 read of its current target/RR/stop behavior + a VTS before/after continuity proof** that the guard did not silently change firing. This is the bulk of the work + the regression risk.
5. **RETIRE the normalizer LAST** — keep `signal-target-normalizer.ts` as the BRIDGE (today it is the ONLY RR/reachability coverage for the in-class detectors + VTS); retire it only once shared-guard coverage has fully moved and is proven equivalent.
6. **Filter-Diagnostics visibility (Kyle hard requirement — no-hidden-gates).** Surface the gate drops BY-REASON in BOTH VTS Filter Diagnostics tabs (crypto + xStock). Requires: (6a) add an `asset_class` field to the skipped-signals telemetry so reasons split per-class; (6b) route the active-path drops through the same `logSkippedSignal` path (today active uses `console.warn`/`console.error` so its drops never reach the rejection telemetry); (6c) the diagnostics read from wherever the gates finally live (the shared guard), NOT the soon-retired helper. (Active-trading Filter-Diagnostics tabs are built later when those tabs exist; this batch does the VTS tabs.)
7. **Fix the normalizer's wrong "21 strategies (12 file-based + 9 in-class)" comment → 19 (≈9 in-class + 10 file-based).**
