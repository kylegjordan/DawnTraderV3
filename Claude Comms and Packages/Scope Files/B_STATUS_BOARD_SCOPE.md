## 5. JUDGEMENT CALLS FOR ATTACK
1. **Descriptions in a separate keyed file rather than a §4 column.** A column breaks the checker's strict parse on every edit and widens a hand-maintained table that already drifts. A keyed file is a second document, but it holds words, not state, and a missing key is visible.
2. **Status from commit subjects.** It relies on the batch-id-first naming rule. A batch that breaks the rule reads `no step recorded`, which is honest but could under-report. The alternative, a typed status, is exactly what made the GitHub board go stale.
3. **The checker as the writer.** It already runs on staging every 30 minutes at the graded ref, so it adds no new timer. It is the gate's own process, so a bug in the writer could cost a tick. The writer runs last in the tick and is wrapped so a failure never stops the gate's rules.
4. **Hosting inside the app rather than a static page.** The app already has a login; a static file served by Caddy would need its own. The cost is a deploy of the app for page changes.
5. **The pre-sprint table beside, not instead of, the prose stage table.** Keeps the history readable; the risk is two lists in one section. The new table is the authority and the old one is labelled history.
