## PROBLEM (verified in current code + live data — the orphan trace)
Three exploration crypto trades (MET 07-15, ETH + AVAX 07-18) are **orphaned**: a `closed_trades` record with entry data, NO live position, and never closed (`closed_at` NULL, `close_reason` NULL). They are the only 3 true orphans in all history (census confirmed), and each is one half of a **same-second duplicate pair** (identical entry_price + quantity, 30-48ms apart), all `chosen_entry_mode=maker`, all exploration.

**Root cause (two verified parts):**
1. **Concurrency source — `checkRtbPromotion()` (`active-execution-engine.ts:2277`) has NO concurrency lock** and is triggered by BOTH a continuous timer (`continuousPromotionInterval` `setInterval`, `:421`) AND event handlers (TRADE_CLOSED / TCL_ACTIVATED, doc `:2273`). When two triggers fire near-simultaneously, two promotion cycles run concurrently, read the same queue snapshot (`getRankedSignals` `:2307`), and promote+open the same signal. The double-activation guard (`:2386-2388`, RTB-remove-before-execute) prevents re-promoting the *same signal-id within one cycle* but does NOT serialize concurrent cycles.
2. **Orphan mechanism — the open path is not atomic, AND the loser is silently deduped (Langston Corrections 1 & 2, verified at the ref).** The duplicate guard (`:3069`) reads `active_open_positions`; the position isn't inserted until `createActiveOpenPosition` (`:3288`), ~220 lines / ~30ms later. Two concurrent same-symbol opens both pass the guard (no position yet), both write the trade record (`createClosedTrade` `:3203`). Then the **`UNIQUE (symbol)` constraint** on `active_open_positions` (`active_open_positions_symbol_idx`, `shared/schema.ts:1875` — symbol ALONE; the `unique_symbol_side (symbol,side)` is the *paper* table `paper_sim_open_positions`, not this one) rejects the second insert — **but `createActiveOpenPosition` (`storage.ts:3323-3341`) CATCHES the 23505 and silently RETURNS the winner's existing row (I8E-DB-DEDUP).** So the loser gets a valid-looking position back and **continues as if it opened**; its already-written record is **orphaned (its "position" is the winner's row, linked to the winner's tradeId) with no failure ever surfaced.** ⇒ a "delete-on-throw" trigger can never fire — **the silent dedup-return is itself the second defect.** This is the accurate mechanism (#508's "merged/overwrote" field observation was right; the earlier "loser throws" framing was wrong).

**Status:** still-present vulnerability (rare — needs a ~30ms trigger collision on the same signal). None since 07-18, likely because #532's retirement (07-22) removed a third concurrent queue-driver, lowering the collision rate — but the flaw remains.

## OBJECTIVES (design RULED by Langston 2026-07-28; M3/M4 answered — Step-4-ready)
1. **Serialize promotion — RULED (1b) coalescing re-run flag on `checkRtbPromotion`.** On entry, if `promotionInProgress` is set → set `rerunRequested=true` and return; else set the flag, run the body in a `try`, and in `finally` clear the flag + if `rerunRequested` was set, clear it and run once more. Closes the "a freed slot waits ~30s for the next timer tick" gap a mid-pass TRADE_CLOSED free would otherwise hit. Per-instance (per-mode) boolean; single event loop → no concurrency primitive needed. The three triggers serialized: TCL_ACTIVATED (`:380`), TRADE_CLOSED (`:400`), setInterval (`:444`).
2. **Compensate the silent dedup-return — the SECOND, independent defect.** RULED **(2a-corrected):** `createActiveOpenPosition` returns a discriminated `{ position, created: boolean }` (`created=false` on the I8E dedup-return path) instead of silently swallowing; the open path, on `created===false`, DELETES the `closed_trades` record it wrote at `:3203` and returns `opened:false / DUP_POSITION`. **Zero blast-radius — `createActiveOpenPosition` has exactly ONE real caller (`:3288`)** (the rest are comments/interface/test), so the explicit source-signal is clean; update the interface (`storage.ts:547`) + the one caller + any mock storage. Rejected (b) finalize-with-reason (preserves a phantom fill + couples to the anneal exclusion) and (c) reorder-position-first (the position row stores `tradeId=trade.id` in metadata `:3336` → position-first needs the trade first; confirmed coupled). **★ Required because `processSignal:3630` is PUBLIC — the lock closes today's only caller, but this compensation closes the landmine for any future direct caller. Not optional defense-in-depth; it is the fix for defect #2.** **M3 (balance) — NO unwind needed:** the paper balance is COMPUTED (`realizedBalance = startingBalance + realizedPnl` over `getClosedTrades(closedOnly:true)` filtered to `t.closedAt`, + open-position mark-to-market — `routes.ts:12306-12323`); an orphan (closed_at NULL + no position) is in neither sum, and there is no debit-on-open, so DELETE is balance-neutral. Closes #508(a).
3. **Clean up the 3 existing orphans** (MET/ETH/AVAX) — DELETE the records (balance-neutral per M3), verified by id before/after. **M4 (budget) — no reconciliation needed:** `usedBudgetToday` counts opened-TODAY only (orphans are 07-15/07-18); the A4 anneal driver already excludes them (`closed_at IS NOT NULL`); the (2)-fix keeps today's budget exact going forward. Closes #508(c). Kyle-authorized.
4. **Reconcile #508** (Langston M1): this batch OWNS #508 (currently homed P19-B8.5) — repoint it to B-PROMOTION-RACE-FIX, fold (a)=M3 / (c)=M4, and record the merge-not-throw mechanism correction.
