## 4. OBJECTIVES — each with its verification

**OBJ-1 — THE CLOSE-DIFF RULE (the plan-line check).** When a batch's completion report first lands, the checker opens `gov-planline:<batch-id>` unless a commit leading with that batch id changed **the batch's own line** of `SPRINT_TO_LIVE_PLAN.md`.
- Shaped like the #1009 precedent: its own table and a pure check function with injected readers (not a new `docPresent` kind — an unknown kind reads as absent everywhere and would flood `gov-docgap`, `checker.mjs:116`); graded only behind the completion-report sentinel; a `sinceMs` gate on the report's first-add that the environment cannot override, so the four already-closed in-plan batches in the window are not graded after the fact; `na-skip` honoured with a key disjoint from every DOCS and `LEDGER_ROWS` key; a `decideOrphanSweep` branch that KEEPS by default (an unknown key type is never swept, `poller.mjs:194`).
- **"Own line"** = the §4 row whose batch cell carries the id, or the §0 plate line that names it — not any line containing the id. Measured reason: 38 of the 98 ids in batch cells also appear on other lines, and in a backtest the loose predicate passes `B-XSTOCK-FEE-CONTRACT` only through successor row 107a (`cb948417f`) while its own §0 line was never touched. (Q1)
- **Required only when** the batch id is in a batch cell or a §0 line at the ref (`REQUIRED_IF`, Langston).
- **The diff data is new:** the checker today reads no patch at all (all 12 git invocations checked) and drops commit hashes (`poller.mjs:57`). A bounded read — `git log <ref> -U0 -- 1-system-manual/SPRINT_TO_LIVE_PLAN.md` over the commits that lead with the batch id — keeps the tick inside its 120-second budget (baseline 2026-09-29 20:29Z: ~11 s wall, 8.6 s CPU). (Q2)
- **Fails closed:** if the plan cannot be read (renamed, missing, empty), the tick raises its own alert rather than reading "not in the plan, owes nothing" — the plan was already renamed once.
- **Push = deploy, so it lands switched off:** a per-rule enable flag, off at the first push; Langston's Step-4 review happens at the ref with the rule dormant; a one-line flip enables it after an offline preview (the `ledger-rows-preview.mjs` pattern) has printed exactly what the first live tick will open.
