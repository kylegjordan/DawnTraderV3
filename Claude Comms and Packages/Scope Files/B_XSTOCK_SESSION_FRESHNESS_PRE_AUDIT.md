### A2. Identity and archive boundaries

- The xStock cycle writes a VTS `admitted/net_ev_floor` row, then registers the VTS trade, then invokes active dispatch. The dispatch input carries neither an archive ID nor the returned VTS trade ID and can run when registration yields no ID (`server/asset_classes/xstock_spot/eval-cycle.ts:1303–1317,1380–1388,1424–1452`). This row still means VTS admission.
- `archiveSignalEval` returns void. Its optional archive ID links its own provenance sibling. With no reserved ID, the base row takes the database default (`server/services/data-archive/signal-eval-archiver.ts:315–349,389–410`). The active signal ID is minted later (`server/services/signal-orchestrator.ts:945–947`). The explicit queue metadata list already carries P10's dispatch copy (`:1700–1715`). That list and the promotion boundary must both preserve the future common attempt key.
- The active archive has adjacent entry outcomes and a terminal admit, distinct from the upstream SQE queue admit and the four decision reaches (`active-execution-engine.ts:6571–6607,7060–7085`). Successful immediate opens carry depth and consumption ages (`:6840–6844`). Those measurements omit accepted checks followed by a later refusal, and the closed-trade surface delays visibility until close.
- Dispatch and depth diagnostics expose process-local stats and identify the serving process (`server/routes.ts:13419–13451`). The depth evaluation count applies to depth only. Its block counters also include liveness and consumption reasons. The archive writer can drop queued rows on overflow and drop unflushed rows after an insert failure. Caller-side success alone cannot prove persistence (`server/services/data-archive/archive-batch-writer.ts:135–153,192–213`).
