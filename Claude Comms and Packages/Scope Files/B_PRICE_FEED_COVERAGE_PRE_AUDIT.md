## PART 0 — INCREMENT 0: THE xSTOCK DISPATCH FRESHNESS GATE READS THE IN-MEMORY TICK

### Audit
**A0-1 — the mechanism (re-derived at `1c4a776c5`).** `equity-spot-archiver.ts` sets the in-memory tick's age (`tsMs`) and `observed: true` ONLY on an `update` frame (`:302-314`); a `snapshot` (the venue replaying a book on every subscribe) or an unrecognised frame keeps the prior `tsMs` and `observed` (`:322-325`), and with no prior entry is born `observed: false` (`:323-325`); a frame with NO mark keeps both too (`:327-331`, Langston F-1). But `bufferTickerSnap({ … capturedAt: new Date() … })` (`:334-338`) is OUTSIDE those branches and runs on EVERY frame. The DB row has no frame type and no `observed` column (`shared/schema.ts:5110-5137`; `metadata` jsonb with `schema_version` exists, `:5136`).
**A0-2 — the dispatch gate (census #1).** `getLatestTickAgeMs` is `NOW() − MAX(captured_at)` per symbol (`active-dispatch.ts:74-85`); the admission predicate is `if (ageMs === null || ageMs > safety.activeFillMaxAgeMs)` → skip (`:184`), with `activeFillMaxAgeMs` = 15,000 ms (`xstock_fill_safety`, Kyle-settled, unchanged). **Measured by Langston 2026-11-07:** 13 replay bursts in the retained window, each `snapshot:467` with `rows_persisted_60s=467`, 11 of 13 with `update:0`; `AAPL/USD` 9 byte-identical rows 13:20:58Z→20:09:21Z while its last genuine change was 05:14:29Z (15.68 h). ⇒ each burst reads every symbol's age ≈ 0 on a book up to ~15.7 h old — **false-fresh and fail-OPEN**. Magnitude ~15 s × 13 ≈ 195 s/day fleet-wide; **no realised harm observed** (4 xStock opens in 30 h, none inside a burst) — exposure, unexercised.
**A0-3 — the open depth gate (census #2/#3), assessed as Langston asked.** `getDepthSnapshot` for `xstock_spot` reads the NEWEST `xstock_spot_ticker_snap` row and its age `NOW() − captured_at` (`depth-source.ts:96-104`), and the entry fill walks that row's ask. Same false-fresh shape. Two further facts: (i) **an invalid age reads as ZERO** — `const ageMs = ageReadValid ? rawAgeMs : 0` (`:110`) and `assessWarmth` reads `ageMs` only (`depth-source.ts`, `assessWarmth`: `snap.ageMs > config.warmthMaxAgeMs`), so an unreadable age is warm — a second fail-open; (ii) a dispatched xStock signal does NOT open directly — `dispatchExternalSignal` → `buildSizedSignalForStrategy` (`signal-orchestrator.ts:535-542`) → SQE → the RTB queue → promotion → the open, and the RTB refresh judges xStock rows on the in-memory tick with the cold check and the per-symbol ceiling (`rtb-retirement-ask.ts:58-77`, `xstock_cold_mark` / `xstock_stale`). **NOT YET ESTABLISHED:** whether a newly queued xStock row can be promoted before its first refresh pass (increment B's priced-pass requirement, P7, is OFF for xStock — no seed). If it can, the depth gate is the only age check between a replay and a fill.
**A0-4 — the condition Langston bound (verbatim):** *"The reader must test `observed === true` AND the age, or refuse."* A tick born from a replay after a restart reads `tsMs: _now, observed: false` — age ≈ 0 — so an age-only reader is exactly as false-fresh as the DB.
**A0-5 — the template already in production:** `rtb-retirement-ask.ts:58-64` — `if (!tick || !tick.raw) → xstock_no_tick`; `if (tick.observed === false) → xstock_cold_mark`; `ageMs = nowMs − tick.tsMs`.
**A0-6 — consumers / blast radius.** `getXstockActiveDispatchStats()` (counters) and the `xstock-stale-fill-block` alert. **KD-48 (`1-system-manual/pm/DECISIONS.md:71`):** CC-A is building per-reach archive rows at this gate carrying "the measured age and the pipeline lag floor" — this increment changes WHICH age that is; coordinated before code (Plan P0-4). Crypto is untouched (xStock-only module).

### Plan
- **P0-1 (A0-2, A0-4, A0-5) — `active-dispatch.ts` gate (b):** replace `getLatestTickAgeMs` with the in-memory tick: `null` or no `raw` ⇒ refuse as today (`absent`); `observed === false` ⇒ refuse with its own counter and alert text (`cold`); `ageMs = now − tick.tsMs`; `ageMs > activeFillMaxAgeMs` ⇒ refuse (`stale`). The 15,000 ms bound and the alert key are unchanged. The DB query function `getLatestTickAgeMs` has exactly one caller (`:183`, census at the ref) and is deleted with it (rule 18, `DELETED_COMPONENTS_LOG`).
- **P0-2 (A0-3) — RECOMMENDED, for Langston and Coltrane to rule in or out of increment 0:** the xStock ENTRY depth read (`_evaluateOpenDepthGate` → `getDepthSnapshot`, `engine:615`) takes its age as the larger of the DB row's age and the in-memory tick's age, and refuses when the tick is `observed === false` or absent; and an invalid age refuses rather than reading as 0 (`:110`). **Closes and the flatten are unchanged** (`engine:4628`, `active-portfolio-manager.ts:305` — they record, never block). Alternative: leave the depth gate to OBJ-6 and establish A0-3's open question first.
- **P0-3 — tests:** replay after a restart (tick `observed: false`, DB row fresh) ⇒ dispatch refuses `cold`; replay on a known tick (old `tsMs`, DB row fresh) ⇒ refuses `stale`; genuine update ⇒ admits; absent tick ⇒ refuses. Mutation: an age-only reader (drop the `observed` test) must go red on the restart case. Same set for P0-2 if adopted, plus "invalid age refuses".
- **P0-4 — coordination before code:** CC-A (builds the KD-48 rows at this gate) and CC-C (scope owner) told that gate (b)'s age becomes the in-memory receipt age of the last observed change; the KD-48 "measured age" field records that, and its "pipeline lag floor" no longer applies to this gate.
- **P0-5 — deploy timing, proposed for Langston's ruling:** not before B-ENTRY-GATE increment A's pre-registered read (alert `801330ae`, 2026-11-09 21:30Z), which reads xStock admissions; and NOT in the same deploy as increment B (each needs its own read). Proposal: increment 0 deploys first after that read, increment B the next session — or increment B first, per Langston.
- **P0-6 — Step 7, pre-registered:** after the deploy, the first restart (every restart replays ~467 books) shows `cold` refusals > 0 at the dispatch gate on any xStock dispatch inside the burst window, and zero admissions whose tick is `observed === false`; `closed_trades.entry_book_age_ms` before/after for xStock opens. Successor test owed because the path has never fired: a forced restart on a closed market with a dispatch attempt (or a unit-level replay if no dispatch occurs).
