## Lead (2) — Flag A isolation: adopt the proven `archive-batch-writer` pattern (SIM-sanctioned, survives sink-DOWN).
`server/services/data-archive/archive-batch-writer.ts`: `enqueueArchiveRow(table,row)` (`:135-154`) is **synchronous, no awaits**, drop-OLDEST on a bounded 50k queue (`:141-151`); a 5s `setInterval` flush (`:219-232`) drains through a 2-slot semaphore; **every flush is try/caught and DROPS-not-throws** (`:208-214`, header `:21`). Callers wrap the enqueue in a fire-and-forget `try/catch` (e.g. `eval-cycle.ts:810/835`, `signal-orchestrator.ts:820-834`) so a telemetry write **can never throw into the decision** — the catch arm falls through and the decision returns normally. SIM confirms it (row 2, `:1844`): "Archive batch writer (5s flush, 2-slot semaphore, 50k bounded queue, drop-OLDEST) — ✅ LIVE"; hot-path hooks (`:1860-1867`): "all try/catch wrapped, never block host paths." **Decision:** the sink writes via `enqueueArchiveRow` behind a centralized `capturePreFilterReject`-style helper (`signal-eval-archiver.ts:271-296` is the reference) with its own internal try/catch; on any failure it degrades to the existing `console.log`, never up into the decision. This satisfies "off the awaited path AND caught before the decision return."
