## 0. The defect, measured at the code
- **The refresh fetches the live price and throws it away — and has since the day it was built.** RRS calls `priceCache.getBatch('readyToBuy', symbols, { restEligible })` (RRS:449) and builds `validPrices` (RRS:463-491), then uses it only as a run/skip switch (`if (validPrices.size > 0)`, RRS:492) and calls `readyToBuyService.refreshAndRank(mode, bucketKeysAtIndex)` (RRS:498) — no price. Inside `refreshAndRank` (RTB:898) the only market reads are the spread, the regime bars and the costs; geometry is recomputed **on the stored entry, stop and target** (`computeNetGeometry`, RTB:775-785) and the SQE input carries no `entryPrice` or `targetPrice` (RTB:1093-1123), so the SQE's ROI gate, which runs only when they are set (`signal_quality_evaluator.ts:373`), never runs here. **A queued signal is never compared with where the market is.**
- **Consequence on the record (`#1168`):** STZ, CEG, INTC and CRCL waited 1.5-8.5 h in the pool on levels frozen at queue time and opened below their stops. Row 59 increment 1 now refuses that at the fill; the pool still holds such signals, ranks them and spends promotion attempts on them.
- **[C1], two windows, both confirmed at the code (`#1189`):** (a) **inside a refresh** — a rejected row's latch is cleared in `finally` (RTB:1213) but the row is deleted only after every remaining chunk finishes (RTB:1221), and each chunk awaits a bar fetch; in that gap the row is in the table, unlatched, status unchanged, and `getRankedSignals` (filter at RTB:1833) selects it. (b) **before a refresh** — `checkRtbPromotion` (AEE:4926) reads the ranked list once (AEE:4963) and loops over in-memory objects; a refresh that starts after selection can reject and delete the row, `promoteSignal` warns and returns void on the missing row (RTB:1538-1543), the caller ignores it, and `executePromotedSignal` (AEE:5065) opens from the in-memory object. **A signal the refresh rejected can be opened.**

## 2. Objectives
1. **Reconnect the price.** The refresh receives, per symbol, the **transactable** price a long would pay — the ASK (price-side rule, `SYSTEM_MANUAL` §18.0.1: *buy on the ask*) — from a **fail-closed** source: crypto through `selectCryptoTouch` + `transactableSide` (`core/trading/crypto-touch.ts`, age policy `ENTRY_FILL_TOUCH_MAX_AGE_MS`), xStock through `getDepthSnapshot`'s per-side verdict (`execution/depth-source.ts`). **No price ⇒ no price decision** (the signal is neither retired nor reconfirmed on price; counted as `price_unavailable` with its reason). Never the midpoint, never a fail-open witness. *Verify:* unit tests per class on each source outcome; a source fence that the refresh reads these and not `getTickerWitness`.
2. **LIVE — retire a queued signal whose live ask is at or through its stop or its target**, through `refuseTakerBooking(ask, stop, target)` — the same primitive and reasons as the open. Retirement goes through the refresh's existing delete path, counted (`rejectedInRefresh` with a new reason) and written as a durable `signal_eval_archive` row (`source='rtb-refresh'`, a new `reject_stage`). *Verify:* the four `#1168` cases replayed at refresh time ⇒ retired; a signal strictly inside ⇒ unchanged; on staging, the counter and the archive row once one fires (positive control: the unit test).
3. **SHADOW — measure, never act:** at each refresh with a price, reward-to-risk at the live ask against the strategy's live `min_rr` (`entryFillShadow`, the floor read through `getPerClassTargetGate`, one read per signal per pass, inside a catch), the adverse move from the planned entry in R, and **the stop room against the live spread** (`(ask − stop)` and the spread side by side — the plan's "minimum stop distance vs the live spread" bound, measured here before any number is chosen). One line per signal per pass (sampled if Step 2 shows volume needs it), the same keys as row 59 increment 1. *Verify:* tests on the computation; on staging the line.
4. **[C1] closed in both windows (`#1189`).** (a) A signal rejected in a pass stays unselectable until its delete has run — the rejected state is held through the delete (latch kept set, or a durable rejected mark the promotion filter reads), not cleared in `finally`. (b) The promotion re-validates immediately before the open: `promoteSignal`'s missing-row outcome is returned and honoured, so a signal deleted or rejected after selection is not opened. *Verify:* unit tests driving each interleaving (mock the chunk await; mock a delete between selection and promotion) ⇒ not opened; a fence on the latch's clear.
5. **The latch map is cleaned.** Entries for deleted signals are removed with the delete; `purgeInactiveClassSignals` is deleted (rule 18, `DELETED_COMPONENTS_LOG`). *Verify:* test that a deleted signal's entry is gone.
6. **Documented:** System Manual (the refresh's price check, what it retires, what it only measures, and the five stale claims found at Step 1 — `SM:2633` TTL and "BOTH run", `SM:1435` `fetchFreshMetrics`, `SM:540` "3 call sites", `SM:7494-7501` starts only with the engine, the `index.ts:348` citation) and System Impact Map (S6, the latch's single writer and the closed window; the refresh's new price input; `refuseTakerBooking`'s fifth caller).
