## The model (LOCKED)
- **Taker-chosen promotion** → opens IMMEDIATELY at the current fill (unchanged — today's behavior).
- **Maker-chosen promotion** → creates a **PENDING** open trade that **holds a slot** (does NOT fill yet), resting at the maker limit (= the signal's entry price) with the maker fee reserved.
- **Fill (paper + VTS, SIMULATED):** honest **trade-through of the REAL price** — a pending buy fills ONLY when a real print trades through the limit (`price ≤ limit`); on fill → PENDING→OPEN at the limit + maker fee. Never optimistic.
- **Timeout = tiered diminishing-returns** (DB-governed): the longer a maker order sits unfilled, the less favorable the eventual fill (adverse selection). **First cut (Kyle):** a conservative single **hard-drop max-age** (~1h crypto) + the tiered structure as DB placeholders, calibrated in Phase-25 on real fill data. On the hard-drop timeout → **convert-to-taker if `[11.8B]`/`evaluateTradeExpectancy` is still EV-positive** (fill at current price + taker fee), **else DROP** the slot (never open a known loser).
- **LIVE (Phase-21):** the real Kraken post-only place/reprice/timeout/cancel resting order + real fill events + the pending-slot in live mode.

## ★ STEP-1 RESOLUTIONS (Langston reviewed + signed off to Step-2, 2026-07-01 — all adopted)
1. **Q1 — maker limit = signal entry price: AGREE.** ★ Make the trade-through comparator **SIDE-AWARE** (buy fills iff `price ≤ limit`, sell/short iff `price ≥ limit`) — build it correct, do NOT hardcode buy-side (§5 #11), even though we're long-dominant today.
2. **Q2 — marketable-at-placement: REVISED (Langston, adopted) — do NOT fill-at-limit-with-maker-fee.** That is the one optimistic fill the honest-trade-through model swears off (a real post-only REJECTS when the market is already through the limit → simulating a maker fill there manufactures economics live can never reproduce = a sim-to-live parity break + poisons VTS/ML with impossible fills). **Instead: marketable-at-placement is an immediate trigger into the OBJ-4 convert valve** — re-check taker EV on current inputs via `evaluateTradeExpectancy`; if `> 0` open TAKER now (current price + taker fee), else DROP (`maker_marketable_dropped`). ONE convert valve, TWO triggers (hard-drop timeout + marketable-at-placement). Post-only-reject-then-reprice stays Phase-21; taker-fallback-now is the parity-honest build-now behavior.
3. **Q3 — typed cols: AGREE, extended to VTS.** `maker_limit_price` + `maker_deadline` as TYPED columns on BOTH `paper_sim_open_positions` AND `vts_open_trades` (NOT the `context` JSON blob — the fill pre-pass reads them every ~1.5s monitor cycle; typed keeps them hot-loop cheap + testable + the two stores symmetric).
4. **Q4 — build-now/calibrate-later: AGREE + guard.** Hard-drop now; adverse-selection tiers are INERT DB placeholders (calibrated Phase-25). ★ Add a test asserting **fill price == limit EXACTLY** (no tier haircut applied) so a future accidental wiring of the placeholder knobs is caught at CI, not in production fill data.
5. **Q5 — knob taxonomy: keep two + a robustness invariant.** `maker_time_budget_ms` (60s, soft tier/T1 telemetry — keep the name, document its NEW meaning in ADJUSTMENT_FRAMEWORK) + NEW `maker_max_pending_ms` (~1h hard-drop). ★ Add a per-class **load-time invariant `maker_max_pending_ms ≥ maker_time_budget_ms`** (reject/clamp on config load — a hard-drop earlier than the expected-fill window is incoherent config, caught at load not runtime).
6. **Q6 — dropped = non-trade: CONFIRMED (strong).** A dropped pending never opened → no position, no P&L. Both drop reasons (`maker_timeout_dropped`, `maker_marketable_dropped`) go to a **SEPARATE non-trade telemetry stream, INVISIBLE to the trade-outcome learning set** (a phantom closed trade poisons win-rate/expectancy AND mislabels VTS ML training) — must free the slot WITHOUT touching any "trade closed" counter.
