## 1. What exists today — re-derived at `9e3d4636b` and on staging 2026-11-05 ~03:55Z (read-only)

**The close finds its record by symbol alone.** `active-execution-engine.ts:4678-4679`: `storage.getClosedTradesBySymbol(this.mode, position.symbol)` then `trades.find(t => t.openedAt && !t.closedAt)`. `storage.ts:3581-3591` filters `symbol` and `close_reason IS DISTINCT FROM 'never_filled'`; it accepts `mode` and never uses it, and has no asset-class filter. The engine line is its only production caller.

**A close that finds no record deletes the position anyway — and by then the close has already acted.** Between the fill contract's last refusal (`:4378`-`:4501`) and the lookup (`:4678-4679`) the close books the learning aggregate (`:4595`), enqueues the B70 exit-decision archive row (`:4609-4672`) and the outcome-feedback update; after the lookup it clears the trailing state for `position.id` and `${position.id}:fg2bid` (`:5050`/`:5052`, which decrements the concurrent-moonbag counter). `active-execution-engine.ts:5061` (`if (!trade)`) logs `[CLOSE_NO_TRADE_ROW]` (`:5062`) and raises `close-no-trade-row-<mode>-<symbol>`; `:5082` then deletes the open position, so that position's P&L is recorded nowhere. Measured never to have happened (0 alerts all-history; 0 log lines in 14 days) — so this is a **fence, not a repair** (Langston, rule 24 outcome 2). Since `51e35b195` the kill switch, close-all and stranded-clear also close through this method.

**The open-side duplicate guard ignores mode.** `active-execution-engine.ts:6222-6223`: `getActiveOpenPositions(this.mode)` then `.find(p => p.symbol === signal.symbol)` → `DUP_POSITION`. `storage.ts:3847-3851` is a bare `select` with no `WHERE`: the `mode` argument is unused.

**The database's one-open-per-symbol rule is a different object from the one the code declares.** Live (`pg_constraint`, measured now): `unique_symbol_side UNIQUE (symbol, side)`, plus the primary key and a strategy index. The declared `active_open_positions_symbol_idx` on `symbol` alone (`shared/schema.ts:2060`) **does not exist in the database.** Active trading is long-only today (20 open rows, all `buy`: 3 crypto, 17 xStock, 20 distinct symbols), so `(symbol, side)` behaves as one-per-symbol. ⚠️ The System Manual (`SYSTEM_MANUAL.md` §19.1, "Open-path atomicity") states the opposite — that the active table carries `UNIQUE (symbol)` and `unique_symbol_side` belongs to the old paper table. That text is wrong against the database and is corrected at Step 10.

**`active_open_positions` has no mode column** (43 columns; only `trade_mode` = TARGET/TRAILING_TAKE and `chosen_entry_mode`). `closed_trades.mode` exists, `NOT NULL`, no default, stamped since B-BALANCE-TRUTH Step F (`#618`); all 1,570 rows are `paper`.

**Records and positions agree today:** 20 unclosed trade records (never-filled excluded), 20 distinct symbols, every one with an open position of the same asset class (0 missing, 0 class mismatches). `DASH/USD` exists in both classes in `closed_trades` history (Langston, 2026-11-05: crypto 3 rows, xStock 2), so the asset class is load-bearing.

**Fees can be an invented zero.** `closed_trades` declares `fees`, `slippage`, `entry_fee`, `exit_fee`, `total_fee`, `entry_slippage`, `exit_slippage`, `total_cost`, `gross_pnl`, `net_pnl`, `net_pnl_percent` all nullable with `DEFAULT 0` (`shared/schema.ts`, the `closed_trades` table at `:1674`; the live defaults match). A close that never wrote its fee reads exactly like a real zero. Today the only zero-fee rows are 178 `never_filled` (no fill, no fee owed); 0 filled closes carry a zero or null fee. No database view reads `closed_trades` (`pg_views`, measured: none), so the reader census is TypeScript and raw SQL in routes.

**`asset_class` defaults to `crypto_spot`** on both tables (`NOT NULL DEFAULT 'crypto_spot'`), the same shape as the fee defaults: a writer that forgets it books a crypto row.

**`getActiveOpenPositions` is called on 72 lines:** 68 in 16 production files (26 `routes.ts`, 15 the engine, 5 `active-portfolio-manager.ts`, 4 `aj19b-lifecycle-diagnostic.ts`, 3 `active-engine-service.ts`, 3 `index.ts`, 2 `trailing-exit-controller.ts`, 2 `kraken-websocket-adapter.ts`, and one each in eight more) plus 4 tests. **`getActiveOpenPositionBySymbol`** (`storage.ts:3839`, interface `:569`) has no callers.

## 3. Provenance (MANDATORY 1.b) — searched: `BATCH_CATALOG.md`, `RUNNING_ISSUES.md`, the completion reports (by symbol and by former names — the `paper_sim_*` tables and `paper-execution-engine.ts` before the 2026-07-03 rename), `git log -S` unrestricted by path

**TIER 1 — the close lookup (`getClosedTradesBySymbol`).** Its body carries `Phase 27.F.15.B.2: Global query, mode-based only`, introduced by `3bd227d1c` (2025-10-25), whose message reads: *"Refactor paper trading simulation to query and store data globally per trading mode ('live' or 'paper') instead of per user ID, simplifying data management and aligning with system architecture changes."* The method was renamed with its table in `1c5c8839f` (2026-07-03, P19-B-RENAME W3-B1). **Intent:** one query per trading mode. **What happened:** the user-ID filter was removed and the mode filter was never added — the comment says "mode-based" and the code is global. **Disposition (2): relevant, updated to today's intent** (symbol + class + mode, KD-24), as a new method; the old one is deleted (4) once it has no caller.

**TIER 1 — the no-record close (`CLOSE_NO_TRADE_ROW`).** Introduced by `51e35b195` (2026-09-19, B-FEED-MISMATCH-FIX Step 3), whose code comment reads: *"a position whose open trade row cannot be found is still closed and deleted here — but NOT SILENTLY. With close-all now routed through this method, this is the only place such a deletion can happen, so it is made loud."* **Intent:** make a silent loss loud, at a time when close-all had just been routed through the canonical close. **Disposition (2):** loud was the right first step; KD-17 ("never drop a trade") now requires the position to be kept, not deleted.

**TIER 1 — the duplicate guard (`DUP_GUARD_BLOCK`).** Introduced by `1742af43a` (2025-12-09): *"Update the PaperPortfolioManager and PaperExecutionEngine to correctly handle duplicate positions, ensure accurate trade exits, and provide more detailed diagnostic information for runtime issues."* Its in-code purpose: *"Check for duplicate BEFORE creating trade. This prevents orphan trade records when duplicate is detected."* **Intent:** one position per symbol, checked before the record is written. **Disposition (2):** still correct within a mode; made per mode (KD-24).

**TIER 1 — the unique constraint (`unique_symbol_side`).** Introduced by `a5cf331ef` (2025-12-09): *"Implement a unique constraint on the `paper_sim_open_positions` table to prevent duplicate entries."* The table was renamed in `e79b3c8d1` (2026-07-03, P19-B-RENAME W3-B2), which declared `active_open_positions_symbol_idx` in Drizzle; B-PROMOTION-RACE-FIX (`2fa7ecca1`, 2026-07-28) ruled the intended rule was *"unique(symbol) not (symbol,side)"* and wrote the System Manual text on that basis — but the declared index was never applied, and the database still holds the December constraint. **Intent:** stop duplicate open positions. **Disposition (2):** the rule is right; the object and its key change to `(symbol, mode)`.

**TIER 1 — `getActiveOpenPositions`.** Same origin and comment as the close lookup (`3bd227d1c`, "Global query, mode-based only"). **Disposition (2):** filter by mode, as the comment always claimed.

**TIER 1 — the fee and cost defaults.** `entry_fee`/`exit_fee`/`total_fee` arrived with the comment `Phase 8.8.3-C1: Granular fee tracking`; `fees`/`slippage` predate it. **Intent:** record the real costs. The `DEFAULT 0` is `INFERRED-FROM-CODE` — no commit states why a missing fee should read as zero. **Disposition (2):** required, NULL until known (KD-17: no fallbacks).

**TIER 1 — the `asset_class` default.** Added with the B65/B69 per-underlying columns, when only crypto traded. **Disposition (2) or (1), decided by the Step-2 writer census.**

**TIER 2:** `#508` compensation delete (`deleteClosedTrade`, B-PROMOTION-RACE-FIX — evicts the losing open's unclosed record; kept and pinned) · `getLastClosedAtForSymbol` (`#1093`, the exact symbol+mode+class idiom; copied) · `createClosedTrade` (B-BALANCE-TRUTH Step F stamps `mode`; unchanged).
