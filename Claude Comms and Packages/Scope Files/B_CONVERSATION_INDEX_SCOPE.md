## Purpose and access boundary

Give DawnTrader crew members a search index that leads them back to the conversation, document or commit behind a decision. Cover DawnTrader’s surviving history and keep new approved material searchable on a defined cadence. The index and the evidence required to verify its results stay within the access limits of the corresponding sources.

| Approved source class | Population to establish in the pre-audit once source access is authorized | Result must point to |
| --- | --- | --- |
| Legacy ChatGPT-era conversations | Surviving DawnTrader material, including before April 2026. Require evidence of a DawnTrader association and log ambiguous records as gaps. | A stable conversation and message or passage reference in the approved copy. |
| Claude crew conversations | OLD, NEW, ANALYST, INFRA and PM, with historical aliases. Start from the existing redacted Transcript Archive. | A stable archive and message or passage reference. |
| Codex stand-in conversations | DawnTrader stand-ins for the same five roles, including INFRA and PM. Capture at each authorized crew switch and refresh nightly. | A stable archived conversation and message or passage reference. |
| Governance and historical documents | The DawnTrader document inventory approved under KD-102. Enumerate the exact document boundaries and revision policy before ingestion. | The exact repository revision and document section. |
| Git commit messages | Relevant DawnTrader commits from a declared ref set, with duplicates collapsed by commit identity. | The exact commit. |

Separate permission from Kyle is required to inspect or include Langston’s or Coltrane’s histories. Command Center, private Drive, email, WhatsApp and other projects are excluded. This Step 1 action uses DawnTrader governance, documents describing the existing tooling and Git metadata. It does not open source conversations, launch collection, change access settings or install anything. The later pre-audit must confirm the authorized path for each population before a source is read or copied.

## Objectives and verification

1. **Inventory the approved corpus.** Identify the source owner, access boundary, available time span, source identity, duplicate rule and gaps for each of the five approved classes. **Pass:** At a named cutoff, the pre-audit reconciles the eligible input population to one disposition per record (included, duplicate, excluded, or unreadable), with missing periods or roles explicitly identified. **Fail:** Unexplained drops, unclassified records, or any restricted source admitted. Test the boundary with allowed, ambiguous and excluded fixtures before a source run.
2. **Provide a dependable, restricted source trail.** Keep the existing Claude archive as a source. Establish an approved raw backup and a readable, searchable copy for each Codex role. Preserve exact source identity and passage location through indexing. **Pass:** A frozen sample from each approved class links back to the same approved original or archive passage. For each of OLD, NEW, ANALYST, INFRA and PM, verify the raw backup and readable copy and restore at least one representative archived record with matching content and identity. The same restricted search fixture returns the expected snippet and result metadata to an authorized reader and exposes neither to a denied reader. Record the 5/5 Codex result on #1238 and retain the remaining obligations in the after-live backup batch. **Fail:** A missing or unverified Codex role, a broken source pointer, a restore mismatch, or disclosure of a restricted record or planted secret in output, diagnostics or shared evidence. Report the coverage of the sampled tests separately from the full-corpus inventory.
3. **Make provenance searches useful.** Establish keyword and passage search as the baseline. In Step 2, freeze a known-miss suite with governance-document and commit-message cases, expected sources, ranking and latency criteria, and cost limits. **Pass:** The shipped search passes that frozen suite whether or not it uses local semantic vectors. Retain vectors only if they meet a preregistered improvement over the same keyword baseline on the same corpus and queries without exceeding the limits or regressing required controls. **Fail:** A shipped search that misses the registered criteria, an irreproducible baseline, a result without a verifiable source, criteria changed after scoring, or vectors retained without passing the improvement test. Record any lower-cost model assistance and its cost in the pre-audit.
4. **Keep the index current and detect gaps.** Prove approved Codex capture in both crew-switch directions and nightly refresh for approved sources. In Step 2, register the verification window, expected source coverage and freshness deadline for each trigger. **Pass:** Reconcile every expected crew switch and nightly run in the window to a matching, timely capture or refresh receipt with the expected source coverage. An empty run records an explicit no-change receipt. Positive inputs arrive once, a replay produces no duplicate, and an interrupted refresh preserves the last good view and records the failure. **Fail:** A skipped trigger, missing receipt, omitted source, duplicate record, expired freshness deadline, stale or partial view reported healthy, or change to the existing Claude archive’s behavior.
5. **Make the index usable in Step 2 provenance work.** Verify a crew member can use the published search command to find an earlier DawnTrader decision and open its original passage. **Pass:** After that run, update the `workflow-02` aids row to mark the index delivered and list the exact search command and its coverage limits. Attach the search and opened-source receipt to #1262 and record PM’s independent re-check. **Fail:** An unpublished or untested command, an unopened source, a missing coverage limit, a missing PM re-check, or an aids entry marked delivered before verification.
