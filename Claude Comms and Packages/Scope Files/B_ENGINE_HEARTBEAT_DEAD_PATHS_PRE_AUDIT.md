## 2. PLAN — each item ← its finding
1. **Heartbeat collapses to the heal, done right.** Delete `checkSession`, `recoverSessions`, the boot `recoverSessions(autoResume)` call + `AUTO_RESUME_SIMULATIONS` read (`index.ts:1484-1490`), `getStatus()`, and the per-row loop. The heal: query `storage.getRunningEngineSession('paper')` (mode-specific), and if a `'paper'` manager exists with no running paper row, **`await manager.stop()` then clear** (try/catch; a failed stop still clears and logs `console.error`). End shape (Langston C2): *fetch the running paper row; if none and a paper manager exists, stop and clear it; return.* **Stated in the code and SIM:** deleting the boot recovery removes, by construction, a second boot-time path that could start the engine concurrently with `resumeActiveEngines`. ← A1, C1, C2
2. **Liveness bound (C2), stated not instrumented:** with the dead warn gone the 30-second loop is silent. A stalled heartbeat costs only a delayed orphan clean-up, and every path that matters already clears orphans itself — the start path (`!existingSession && existingManager` → clear), the stop path (no running row → stop + clear the orphaned manager), and the boot reset. So the heartbeat is a backstop; no new instrument. ← C2
