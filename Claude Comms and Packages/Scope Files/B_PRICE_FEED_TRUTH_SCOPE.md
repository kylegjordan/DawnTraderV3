## The four increments
### I1 — a bound on how old a re-served price may be (rows 32/33; `#743`)
`fetchLivePrice` (`server/services/live-pricing-adapter.ts`) re-serves the cached price as `last_known_good` on three paths — the xStock REST gate (`:669-683`), "all APIs failed" (`:728-742`), the fetch exception (`:765-779`) — checking only `price > 0`, stamping `timestamp: now`, and the writer (`:619-641`) re-caches it with `cachedAt: Date.now()`, so a price that never moved reads fresh on every 15 s poll. `observedAt` is carried through unchanged (`#743`), so the true age is recoverable — **nothing compares it against a limit.** On staging today the xStock gate re-served `last_known_good` **33,531 times** in the current `out.log` (by design — it is the xStock poll path). Readers of the result: `getPriceWithFallback` (`routes.ts` ×5, `active-execution-engine.ts:1465`, `:2386`, `active-engine-service.ts:447`, `active-portfolio-manager.ts:294`) and the cache readers (`peekCachedPrice`, `getAllPrices`, `isPriceVenueQuiet`).
**Objective:** a governed maximum age on `observedAt` for a re-served price used by any decision; past it, no price (the decision refuses, as a missing side does). The re-serve stops refreshing `cachedAt`. *The bound and its per-class value are Step 2's question* (the open entry deliberately separated "recoverable" from "bounded").
### I2 — every price-cache key is the Kraken primary key (row 14a; `#1076`, `#1146`)
REST replies keyed by Kraken's primary pair key are stored under `normalizeKrakenPair(pair)`; for a primary key missing from the static map the resolver's suffix-strip fallback (`server/markets/kraken-symbol-resolver.ts:108-114`) mints a phantom (`ZGBPZ/USD`, `XETHZ/CAD`, `XLTCZ/JPY`, `XXRPZ/CAD`), and `symbolsMatch` (`price-cache.ts:359-363`) normalises both sides with the same function, so the reply never maps back — the symbol asked for has no fresh REST price. Sites: `price-cache.ts:285-294`, `:458-472`, `:586-597`; phantom ledger `market-data/rest-write-keys.ts:56-72`.
**Objective:** no phantom key — the design (A resolve by primary key in the resolver / B fix `symbolsMatch` / C complete the static map) is Step 2's, with the full census of affected pairs. Plus the `🔒 LOCKED MODULE … formal directive` header reworded to point at the eleven-step workflow (Langston's option (b), 5 files).
### I3 — the WS adapter stops dropping whole messages (`#1047`)
`server/exchanges/kraken/kraken-websocket-adapter.ts` wraps all of `handleMessage` (`:640-716`) in one catch (`:713-715`), so one throw drops the message. The `toUpperCase` is the resolver's `mapKrakenPairToInternal` (`kraken-symbol-resolver.ts:193`) on an undefined pair — candidate call sites: a subscribe-ack `result.symbol` (`:779-780`), the instrument handler `pr?.symbol` (`:1013`), a book update `update.symbol` (`:1037-1038`, no validation guard), legacy v1 `pair` (`:729`, `:748`). Staging: **2** on 10-06, **4** so far on 10-07 (`error.log`; the entry's ~11/day was September).
**Objective:** find the message that throws (log its shape once), guard the absent pair where it enters, and isolate the catch so one bad message cannot drop a sibling's data.
### I4 — the xStock recorder follows the daily trading list (row 31; `#960`, `#950`)
`startEquitySpotArchiver` copies the list once (`equity-spot-archiver.ts:499`); `subscribe()` resends that copy on every reconnect; the trading set is replaced daily at 06:00 UTC (`xstock-universe-cron.ts` → `refreshFromDB` → `_replaceXstockUniverse`, `shared/asset-classes.ts:428-435`) and nothing tells the recorder. Consumers of the recorder's feed: `active-execution-engine.ts:2029`, `book-state-tracker.ts:537`, `venue-quiet-alerting.ts:71`, `drift-dashboard-aggregator.ts:893`.
**Objective:** after each universe refresh the recorder subscribes the added symbols and unsubscribes the removed ones (no reconnect), and the design note records it as the xStock trading feed (Kyle 2026-10-07: the source is right; this is plumbing). *Step 2 measures `#960`'s open question* — whether a member with no feed can reach selection — on staging today.
