## 2. Objectives
1. **Persist the scheduled result in the fire row that already exists.** The cron callback (`formula-auto-audit.ts:200-225`) today discards `runFormulaAudit`'s return; it keeps it and writes into the `formula_audit_cron` row's `meta` (free-form, `scheduled-jobs-audit.ts:35-43`): `totalFormulas`, `passed`, `warnings`, `failed`, `auditTimestamp`, and the per-test `name` / `status` / `deviationPercent` the card lists (10 entries). No new table and no new writer — the fire row is already the authoritative "it ran at T". A failed scheduled run keeps writing its `status = 'error'` row, with no counts.
2. **The read route stops running the audit — the rule, then every state (Langston, r2 and r3 BLOCKERs).** **M** = the last admin manual run, held in memory since the process started (losing it on restart is correct — it is not the scheduled record); **C** = the latest `formula_audit_cron` row whose `meta` carries counts; **L** = the latest `formula_audit_cron` row of any status. **Shown = the newest of M and C by timestamp. Only when neither exists, the audit runs on this read** — re-run on every such read, never held, so the label is always true. **Then one note, from L alone, when L is newer than what is shown, OR what is shown is an on-read run and L exists** (in that branch the note drops "later": it is about the last scheduled run, not a run after the one shown).
