## §1 — PLAIN LANGUAGE: WHAT THIS DESIGN DOES (the Kyle read)

**Today** one switch decides which single system runs — and turning on active trading kills the VTS. **After this build:** the VTS runs always, on its own, no matter what; paper mode has its own on/off switch; live mode has its own separate on/off switch (and stays off until Phase 21 — when it's on, it places real orders, period); none of the three affects the others.

**The mode tag (your design):** every pair gets stamped with its system-of-origin at the moment it enters a pipeline, and the tag rides with it through every stage to final storage. No part of the system ever has to ask "what mode are we in?" — the answer travels with the data. The audit proved this is mostly already true in the paper pipeline; the simulator needs its stamp built (we found the exact spot); and exactly two endpoints drop the tag today (the learning memory and the storage writers) — those are the two repairs.

**Learning (your framing, jointly designed with Langston):** the system learns from BOTH worlds, labeled, never mixed. The simulator teaches how all signals in a regime family trade and whether pairs are being classified into the right regime. Paper teaches how well the real filtered, selective system actually performs on wins and losses. Each result is stored with its source label, what stage of selection it came from, and which calibration generation produced it — so learning can never blend two different worlds by accident, and a calibration change never muddies old data with new.

**Shared services (MCE, the scanners, pattern detection, strategy math, TEC):** computed once per pair per cycle, results handed read-only to every system. No duplicate computing, no copies that can drift.

**Storage:** one set of books per system, strictly separated; the shared scan data stored once for all. The throughput study then measures — not guesses — whether the current server carries the simulator and paper running together, and sizes any upgrade from real numbers.

## §2 — THE TWO DECISIONS AT THIS GATE (updated with Kyle's 2026-06-09 responses)

1. **How learning reads across the two worlds — REFINED per Kyle's middle-ground question ("maybe part of the data is blended... the filters and the results of strategy and signal creation... but actual trading outcomes kept separate — you guys debate it").** CC + Langston debated it with code evidence; the converged **three-tier answer**:
   - **Tier 1 — shared market data (scans, MCE context, raw strategy detections): one copy for everyone.** Nothing to blend — both worlds literally read the same computed result. (Already the design.)
   - **Tier 2 — the filters / signal-scoring layer: COMPARISON yes, POOLING no.** Cross-world comparison joins (simulator-would-admit vs paper-admitted vs realized) become a **first-class part of the design** — they're exactly how we validate the SQE filter and tune the gate, and comparison *surfaces* differences between the worlds rather than hiding them. But statistically **pooling** the two worlds' scores into one average is OUT, because the code-check killed its premise: the two worlds' signal-scoring turn out to be **two different implementations fed by different inputs on 3 of the 4 score components** (not the same machinery at all), and the paper path currently only records its *accepted* signals (the rejected ones aren't captured), so its sample is skewed by construction. Pooling is **parked** behind two named prerequisites: unify the scoring onto one implementation, and capture paper's rejects symmetrically.
   - **Tier 3 — actual trading outcomes: strictly separate, same-world learning.** As recommended and as Kyle leaned. The Welford (count/mean/spread) record + calibration-epoch resets stand as designed.
   **→ The debate paid for itself twice:** it surfaced (a) **two parallel signal-score implementations that have silently drifted apart** — a latent split-brain worth fixing regardless (registered in §6), and (b) **paper's missing reject-capture** — which Phase 19 would have turned on as-is, blinding exactly the comparisons we want (registered in §6).
2. ✅ **Retention — DECIDED (Kyle 2026-06-09): uniform policy stays**; the per-system knob exists if ever needed.
3. ✅ **Kill switch — DECIDED (Kyle 2026-06-09, refining his earlier live-only ruling): paper KEEPS its kill switch** alongside live's ("it tells us something if in paper mode we can trade for long periods without flipping the switch" — live-mirror + diagnostic). VTS gets none. Zero code change — the existing per-mode mechanism is already right.

**FYI (flagged, not decided now):** the same simulator-vs-paper question exists one level up in the scoring-weights layer (it's simulator-locked today; paper outcomes never reach it). A Phase-19+ decision — recorded so it can't ride silently.

Hard gates: zero cross-stamped rows, single-writer-per-partition, exactly 1 MCE compute/(symbol,cycle). Producers driven through their REAL selection→queue→storage paths (the false-headroom hazard).
