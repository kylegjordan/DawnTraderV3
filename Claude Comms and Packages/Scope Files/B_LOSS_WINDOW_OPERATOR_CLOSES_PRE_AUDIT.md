**The design choice, weighed (Langston asked for it):** the anchor test truncates the window at every re-anchor, and `auto_divergence` re-anchors with no operator act — truncating there would drop genuine losses from the budget: a permissive change. **r2 takes the anchor test for OPERATOR re-anchors only (`start_new`, `measurement_override`, `launch_snap`) and leaves `auto_divergence` out.** Effect: the window is never narrower than today's except after an operator re-baseline, so no automatic event can loosen the switch. `#1171` (the automatic re-anchor trips EARLY) is therefore NOT discharged here and stays at row 183b1 as its own question — deciding whether an automatic re-anchor may shorten the window is a loosening, which is not this batch's to take. Measured reach of the excluded reason: 1 event all-time (A12).
**Accepted consequence, stated:** an operator reset now also clears the previous 24 h of losses from the kill switch, not only its own closes. That is the purpose of a re-baseline, and only an operator act can trigger it.

**Census (§9.5(a)):** new option on `getLastAnchorAt` — writer none; readers: the numerator only; the evaluator's cooldown keeps the default (all reasons) and its exact population. `resolveLossWindowStart` — one caller (`compute24hSnapshot`), reached by `evaluateDailyLossBudgetOnClose` and `computeDailyLossVerdict`. The label column `close_reason` is no longer read by this batch, so Langston's C3 writer census dissolves here (its general case is homed, §13 below).
