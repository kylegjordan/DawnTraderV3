## Previously stated vs now

- **Previously stated:** an overwrite count would size how often REST displaced a newer WS quote. **Now:** the count and eligible overwrite denominator measure only local receipt/capture ordering. **Reason:** normal direct-adapter and poller/batch captures are set just before the synchronous write. In a monotonic local clock an inversion is expected to be rare or impossible at these normal setters. A delayed caller-supplied stamp or a wall-clock regression can invert them. There is no parsed exchange-event time for REST. Coltrane Step 1, point 1.

## Implementation plan and proof

1. **P1 (A1/A2/A4): measure at the committed side assignment.** Thread the incumbent and next row through the existing three write sites. At a newly stated, named REST pair displacing a named WS pair with two finite local stamps, increment one eligible overwrite denominator. Within it increment the one `#1146` inversion counter only for `incoming < incumbent`. Surface counts by existing writer source, so both setters are observable. Separately accumulate counts of actual stated pairs by canonical crypto symbol and the existing `SidesWriter` source for all six writer kinds at their write boundary. Feed the diagnostic accounting after the actual write. Carry-only, unnamed, cold-synthetic, and unlisted/unresolved records cannot become evidence of a stated side. Preserve the input, all setters, incumbent selection, ages, key or alias writes and cache fields. Make diagnostics non-throwing and synchronous with no I/O, queue or retry on the write path.
2. **P2 (A2–A5): capture the symbol at the existing walk, serialize on demand.** Pass each of the seven recorder calls the exact quote or position instrument before outcome branching. Resolve canonical crypto identity with the same venue map as the writer coverage. Record additional compact counters for that symbol in the existing stage/rung partition, with counts for attempts and accepted sources. Do not change the original two-cell recorder, stage names, reason names, existing endpoint field or JSONL rows. Keep the parallel counts bounded to known listed crypto pairs with explicit coverage loss for unknown or overflow identities. Freeze a common diagnostic cohort for a process once the venue map is ready, derive the bound from that finite map, and disclose unmapped, pre-ready or changed identities and any dropped attempts. A positive unresolved or overflow count cannot be interpreted as evidence of an absent competing writer. A cache clear leaves lifetime counts alone. A process restart resets both instruments and starts a new generation. Return the two new counters and targeted symbol breakdown only when requested on the existing authenticated diagnostics endpoint. This avoids expanding the existing 15-minute file or ordinary API responses. Return both sides of the cohort join in one synchronous snapshot with an explicit coverage status and generation/instant.
3. **P3 (A3–A6): grade the evidence in the same lifetime.** Form a candidate only from positive `rest_adapter` stated-side coverage and zero other stated-side writers under a complete common coverage interval. Exclude mixed and ambiguous symbols. Use `ticker_bbo:rest_adapter` ladder accepts divided by ladder attempts (all outcomes) over that exact cohort for each `(lane, asset class, stage)` separately. Report the covered interval and missing or excluded attempts. Use one point-in-time staging verification of the counter/readout contract and the natural opportunities present then. A denominator of zero or incomplete coverage yields no grade. The plan does not specify a soak, minimum live count, fresh timed observation or restart for verification. It adds no observation-register row at this step. Any later repeat of historical V6/V9 as a separate observation would need its own scoped registration and coordinated staging slot. The protected 8c Phase A/B and OLD read remain ahead of any staging use here.
