Langston's arithmetic (192×15m=48h …) is the comparability check; the scale-identity doesn't even depend on it.

The xStock eval-cycle sets the cache via `computeContext` (`eval-cycle.ts:368`) immediately before dispatching the signal to the orchestrator, so at carry-time the context is **warm** — PROVEN by the existing `:671`/`:1207` xStock reads already producing regime category+label at exactly this point (xStock regime renders live). **Distinct from the B-REGIME-REFRESH-PIPE cold-cache defect:** that read EXCLUDED (queued/traded) pairs the scanner drops from the survivor set; this reads the pair the eval-cycle JUST computed in the same dispatch flow. **Fail-safe design:** if the read returns null (slow-pipeline TTL expiry, or a thin pair whose `propagatedDbs` was undefined → synthesized `score:0`), fall through to null → the kernel's documented default — **identical to today's behavior, never worse.** So the change is strictly additive: capture the real DBS when warm (the common case), unchanged fail-safe otherwise.
