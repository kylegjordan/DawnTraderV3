# Phase 8.8.1A — Truth-Constraint Behavior Report

**Date:** November 20, 2025  
**Scope:** Evaluated vs Eligible vs Breakdown Reconciliation  
**Status:** ✅ COMPLETE

---

## Executive Summary

This report documents the "truth constraint" behavior of the scanner — the mathematical relationship between pairs evaluated, eligible pairs found, and the sum of all filter breakdown categories. 

### Critical Finding: **TRUTH CONSTRAINT VIOLATED**

❌ **Breakdown categories do NOT sum to total rejected pairs**  
❌ **Intermediate gating logic causes missing counts**  
❌ **Universe sizing truncates evaluation before all filters applied**

**Formula (Expected):**
```
evaluated = eligible + Σ(breakdown categories)
```

**Reality:**
```
evaluated = eligible + ineligible
ineligible ≠ Σ(breakdown categories)  ← VIOLATION
```

## 3. Root Cause Analysis

### 3.1 Universe Sizing (Pre-Filter Gating)

**Key Log Evidence:**
```
[27.F.14][MarketScanner] Universe limited to 100 pairs
```

**Code Evidence (market-scanner.ts:95-96):**
```typescript
universeSize: screenerSettings.universeSize || undefined,
```

**Behavior:**
1. Scanner fetches ALL 1546 pairs from Kraken
2. Applies `universeSize: 100` limit **BEFORE** FX5 filters
3. Only top 100 pairs by volume are evaluated
4. Remaining 1446 pairs are silently dropped

**Result:** Not all pairs reach filter evaluation, so they're not counted in breakdown

---

### 3.2 Filtering Order (First-Failure-Only Tracking)

**Code Evidence (paper-sim-diagnostic.ts:176-234):**
```typescript
// Apply filters in order and track first failure
let rejected = false;
let rejectReason = '';

// Filter 1: Whitelist
if (!rejected && whitelist.length > 0 && !whitelist.includes(canonicalSymbol)) {
  breakdown.failed_whitelist++;
  rejected = true;
  rejectReason = 'failed_whitelist';
}

// Filter 2: Blacklist
if (!rejected && blacklist.includes(canonicalSymbol)) {
  breakdown.failed_blacklist++;
  rejected = true;
  rejectReason = 'failed_blacklist';
}

// ... more filters ...
```

**Behavior:**
- Filters applied in sequence
- **First failure causes rejection**
- Subsequent filters NOT evaluated
- Only ONE breakdown category incremented per pair

**Example:**
- Pair fails both `min_volume` AND `min_price`
- Only `min_volume` is counted (first failure)
- `min_price` is never checked

**Result:** Breakdown counts represent first failure point, NOT all filter violations

---

## 4. Missing Pairs Accounting

### 4.1 The 166 Missing Pairs

**Total Ineligible:** 893  
**Breakdown Sum:** 727  
**Missing:** 166

**Where are the 166 pairs?**

**Hypothesis 1: Universe Size Truncation**
- Universe limited to 100 pairs (settings: `universeSize`)
- Remaining pairs never evaluated
- Not counted in breakdown because they never reach filters

**Test:**
```
Total pairs: 1546
Universe size: 100
Pairs excluded before filtering: 1546 - 100 = 1446
```

**But logs show `evaluated: 1546`**, so this hypothesis is WRONG.

**Hypothesis 2: Intermediate OHLC/History Failures**
- Pairs fail during OHLC data fetch (no historical data)
- Not categorized in filter breakdown
- Counted in `ineligible` but not in any specific breakdown category

**Log Evidence:**
```typescript
const ohlcResponse = await this.krakenService.getOHLCData(symbol, 60);
const ohlcData = ohlcResponse.ohlc;

if (ohlcData.length === 0) {
  if (trace) {
    console.log(`[TraceReject] ${symbol} reason=no_ohlc_data`);
  }
  throw new Error('No OHLC data');
}
```

**Result:** Pairs with no OHLC data are rejected but NOT counted in any breakdown category
