## Implementation Components

### 1. **Stage-3 State Cache** (`server/services/stage3-state-cache.ts`)

**Purpose:** In-memory per-mode state cache with cycleId generation.

**Architecture:**
- Isolated paper/live snapshots (no cross-mode contamination)
- Automatic cycleId generation on each update (timestamp-based UUID)
- Snapshot includes:
  - `cycleId`: Unique identifier for each scan cycle
  - `evaluatedCount`: Total pairs evaluated
  - `eligibleCount`: Pairs passing all filters
  - `ineligibleCount`: Pairs failing any filter
  - `activePoolCount`: Current active trades
  - `topNCount`: Top-N universe size
  - `tierBCount`: Tier-B universe size
  - `rotation`: Rotation configuration (topEndUniverseSize, tierBUniverseSize)
  - `latestEligibleSymbols`: Top 10 eligible symbols from latest scan
  - `lastUpdated`: Timestamp of last update

**Key Methods:**
```typescript
updateState(mode: 'paper' | 'live', data: Partial<Stage3State>): Stage3State
getState(mode: 'paper' | 'live'): Stage3State | null
```

**Performance:**
- Lightweight (holds only latest snapshot per mode)
- No disk I/O (pure in-memory)
- Cache invalidation on each scan cycle

---

### 2. **Stage-3 Event Emitter** (`server/services/stage3-emitter.ts`)

**Purpose:** Emit scan_tick (lightweight) and scanner:breakdown (heavy diagnostic) WebSocket events.

**Event Types:**

#### **scan_tick (Lightweight Heartbeat)**
- Payload: `{ timestamp, mode, cycleId }`
- Size: ~50 bytes
- Frequency: Once per scan cycle per mode (every 10 minutes)
- Purpose: Frontend heartbeat to show scanner is alive

#### **scanner:breakdown:<mode> (Heavy Diagnostic)**
- Payload: `{ mode, cycleId, breakdown: FilterBreakdown, truthConstraintOk }`
- Size: ~2KB (includes full filter breakdown)
- Frequency: Once per scan cycle per mode (every 10 minutes)
- Purpose: Detailed diagnostic for UI display and debugging

**Truth Constraint Validation:**
```typescript
const truthConstraintOk = 
  breakdown.evaluated === 
  (breakdown.passed_all_filters + 
   breakdown.failed_volume + 
   breakdown.failed_volatility + 
   breakdown.failed_daily_range + 
   breakdown.failed_rsi + 
   breakdown.failed_liquidity + 
   breakdown.failed_bid_ask_spread + 
   breakdown.failed_quote_currency + 
   breakdown.failed_market_cap + 
   breakdown.already_active);
```

**Context Bridge Integration:**
- Added `scan_tick`, `scanner:breakdown:paper`, `scanner:breakdown:live` to `context-bridge.ts`
- Mode-aware broadcasting (per-user, not global)
