### Objective
Ensure cache updates always precede event emissions.

### Code Location

**Method**: `scanMode()`  
**Lines**: 165-180

### Implementation

```typescript
// Update Stage-3 cache FIRST
await updateStage3Cache(mode, {
  evaluatedCount,
  eligibleCount,
  ineligibleCount,
  topNCount,
  tierBCount,
  rotation: {
    topEndUniverseSize: universeSize,
    tierBUniverseSize: 0,
  },
  activePoolCount,
  latestEligibleSymbols: result.filteredPairs.slice(0, 10).map(p => p.symbol),
});

// Emit Stage-3 WebSocket events SECOND
await emitStage3Events(mode, breakdown);
```

### Ordering Analysis

1. **Step 1** (Line 165): `await updateStage3Cache(mode, {...})`
   - Updates singleton cache with new scan data
   - Increments cycle counter
   - Returns updated state

2. **Step 2** (Line 180): `await emitStage3Events(mode, breakdown)`
   - Reads state from cache (via `stage3Cache.getState()`)
   - Emits `scan_tick` event with cached state
   - Emits `scanner:breakdown` event with cached state

### Why This Order Matters

**Correct Order** (current implementation):
```
Cache Update → Event Emission
```
- Events always reflect the LATEST state
- cycleId is guaranteed to be incremented before events fire
- No race conditions
- Single source of truth maintained

**Incorrect Order** (would cause bugs):
```
Event Emission → Cache Update
```
- Events would use STALE state
- cycleId would be off-by-one
- Truth constraint could fail
- Race condition risk

### Verification Summary

| Requirement | Implementation | Status |
|-------------|----------------|--------|
| Cache updates FIRST | Line 165 executes before line 180 | ✅ PASS |
| Events use latest state | `getState()` called after `updateState()` | ✅ PASS |
| No race conditions | Sequential `await` ensures ordering | ✅ PASS |

**Conclusion**: Event ordering is correct and deterministic.

## Singleton Pattern Conformance

### Design Pattern Analysis

**Pattern Used**: Module Singleton

```typescript
// Definition
class Stage3StateCache { /* ... */ }
export const stage3Cache = new Stage3StateCache();

// Consumption (via helper)
export async function updateStage3Cache(...) {
  return stage3Cache.updateState(...);
}
```

**Benefits**:
1. ✅ Single instance guaranteed (module scope)
2. ✅ No global namespace pollution
3. ✅ TypeScript-safe imports
4. ✅ Lazy initialization (only when module loaded)
5. ✅ No need for getInstance() boilerplate

**Risks Mitigated**:
- ❌ Multiple instantiations (prevented by private class, exported singleton)
- ❌ Race conditions (sequential await ensures ordering)
- ❌ State desynchronization (single cache shared by emitter)
- ❌ Duplicate cycle counters (counters live in cache singleton only)
