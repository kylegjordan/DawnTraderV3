## Strategy Inventory

### 1. **VWAP Pullback** (`vwap_pullback`)
**Status:** ✅ Active  
**File:** `server/services/strategy-engine.ts` (lines 27-104)

**Description:**  
Detects price pullbacks to VWAP level with bullish reversal confirmation and volume spike.

**Entry Conditions:**
- Price above VWAP
- Near VWAP (within user-configured pullback threshold, default 2%)
- Bullish reversal pattern detected
- Volume confirmation (current volume >= avgVolume * volumeMultiplier)

**Exit Conditions:**
- Target hit (+2R or high24h)
- Stop hit (below VWAP or pullback low)
- Price closes below VWAP (strategy-specific exit)

**Technical Indicators:**
- VWAP (Volume Weighted Average Price)
- 24-hour high/low
- Volume (20-candle lookback for average)

**User-Configurable Parameters:**
- `vwapPullbackThreshold` - Default: 2.0%
- `vwapVolumeMultiplier` - Default: 1.5x
- `vwapMaxHoldingPeriod` - Default: 24 bars

**Confidence Score:** 0.7 (base) + 0.2 (if reversal confirmed)

**Dependencies:**
- `detectBullishReversal()` - Helper method for reversal pattern detection
- Price history data (minimum 10 candles required)

**Known Issues:** None

### 2. **ABCD Long** (`abcd_long`)
**Status:** ✅ Active  
**File:** `server/services/strategy-engine.ts` (lines 106-198)

**Description:**  
Identifies ABCD chart patterns (spike → pullback → higher low → breakout) with volume confirmation.

**Entry Conditions:**
- A-point: Spike detected (high volume)
- B-point: Pullback from A-point
- C-point: Higher low above VWAP
- D-point: Breakout above C-high with volume confirmation

**Exit Conditions:**
- Target hit (fixed target % OR measured move + 2R)
- Stop hit (below C-low)
- Price returns below entry -0.5% (pattern failure exit)

**Technical Indicators:**
- VWAP
- Volume (A-point spike used as reference)
- Pattern points (A, B, C detection)

**User-Configurable Parameters:**
- `abcdMinConsolidation` - Default: 10 bars
- `abcdBreakoutThreshold` - Default: 1.5%
- `abcdVolumeMultiplier` - Default: 1.5x
- `abcdExitType` - Default: 'target' (options: 'target', 'trailing')
- `abcdTargetPercent` - Default: 3.0%
- `abcdTrailingStopPercent` - Default: 2.0%

**Confidence Score:** 0.75 (fixed)

**Dependencies:**
- `findSpike()` - Detects A-point (highest volume bar)
- `findPullback()` - Detects B-point (lowest price after A)
- `findHigherLow()` - Detects C-point (higher low after B)

**Known Issues:** None

## Strategy Orchestration Architecture

### Signal Orchestrator (`signal-orchestrator.ts`)

**Purpose:** Hybrid signal-orchestration loop for mode-aware market evaluation.

**Key Components:**
1. **Periodic Evaluation:** 30-second interval (configurable)
2. **Symbol Loading:** From FilteredPairsService
3. **Strategy Execution:** Calls all enabled strategies for each symbol
4. **Signal Deduplication:** Scores and ranks signals
5. **Signal Forwarding:** Sends winning signals to TradingEngine

**Enabled Strategies (8 active):**
```typescript
[
  'vwap_pullback',
  'abcd_long',
  'sma_trend_ride',
  'breakout',
  'mean_reversion',
  'range_trading',
  'vwap_bounce',
  'liquidity_trap'
  // DHMA disabled pending proper parameter loading
]
```

**Evaluation Flow:**
```
Signal Orchestrator
  → FilteredPairsService.getValidPairs(mode, filters)
  → For each eligible symbol:
    → Fetch price history & indicators
    → Call all enabled strategies
    → De-duplicate signals
    → Forward signals to callback (TradingEngine)
```

**Statistics Tracked:**
- `symbolsEvaluated` - Number of symbols processed
- `strategiesRun` - Total strategy executions
- `signalsGenerated` - Raw signal count
- `signalsForwarded` - Signals sent to engine
- `lastEvaluationAt` - Last cycle timestamp
- `nextEvaluationAt` - Next cycle timestamp

## Performance & Scalability Notes

### Signal Generation Overhead

**Per Symbol Evaluation Cost:**
- 8 strategy checks × ~5-10ms per strategy = ~40-80ms per symbol
- With 100 eligible symbols: ~4-8 seconds per evaluation cycle
- With 10-second interval: 40-80% CPU utilization during evaluation

**Optimization Opportunities:**
1. Parallelize strategy evaluations (currently sequential)
2. Cache indicator calculations (VWAP, SMA recomputed for each strategy)
3. Skip strategies with insufficient data earlier

### Memory Footprint

**Per Symbol:**
- Price history: ~200 candles × 100 bytes = ~20KB
- Indicators: ~1KB
- Signals: ~500 bytes each

**For 100 symbols:**
- Total memory: ~2.1MB (negligible)

**Conclusion:** Memory is not a concern, CPU optimization is priority.
