## 1. Scanner Output Structures Audit

### 1.1 eligibleSymbols Schema

**Location:** `server/services/kraken.ts::getEligiblePairs()`  
**Current Return Type:**
```typescript
{
  symbol: string;
  baseCurrency: string;
  quoteCurrency: string;
  marketCap?: number;          // ❌ Optional, not in expected schema
  volume24h: number;
  currentPrice: number;
  dailyRange: number;

}
```

**Expected Return Type:**
```typescript
{
  symbol: string;
  baseCurrency: string;
  quoteCurrency: string;
  volume24h: number;
  currentPrice: number;
  dailyRange: number;
```

**Issues Identified:**
1. ❌ `marketCap` field present but not in expected schema (should be removed or made backend-only)
2. ❌ `vwap` is optional (`?`) instead of explicit `number | null`

## 3. Stage 3 scan_tick Emission Audit

### 3.1 Current State

**Search Results:**
```bash
grep -r "scan_tick\|emitScanTick" server/services/
# No matches found
```

**Finding:** ❌ **Stage 3 scan_tick emission does NOT exist in current codebase**

### 3.2 Expected scan_tick Payload

According to FX5 architecture, Stage 3 should emit:
```typescript
{
  type: 'scan_tick',
  payload: {
    evaluated: number;           // Total pairs evaluated
    eligible: number;            // Total pairs passing all filters
    ineligible: number;          // Total pairs failing at least one filter
    breakdown: FilterBreakdown;  // Detailed breakdown by filter
    eligibleSymbols: Array<{     // Full list of eligible symbols
      symbol: string;
      baseCurrency: string;
      quoteCurrency: string;
      volume24h: number;
      currentPrice: number;
      dailyRange: number;
      vwap: number | null;
    }>;
    timestamp: string;
  }
}
```

**Finding:** This entire emission system is **not yet implemented** and must be built in Phase 8.8.2+.

## 7. Anomalies & Issues

### 7.1 Critical Issues

1. **Breakdown Mismatch**
   - 3 extra keys (blacklist/whitelist/strategy_none)
   - 4 missing keys (market_cap/universe_size/already_active/passed_all_filters)
   - Impact: Downstream systems cannot rely on breakdown for accurate filtering diagnostics

2. **Stage 3 Missing**
   - No scan_tick emission infrastructure
   - Impact: Real-time data pipeline incomplete, signals engine has no event stream

3. **Truth Constraint Violation**
   - Breakdown sum ≠ ineligible count
   - Impact: Filter diagnostics unreliable, UI displays incorrect statistics

### 7.2 Minor Issues

1. **Type Definitions**
   - `vwap` should be `number | null` not optional `number?`
   - `marketCap` field present but not documented

2. **Caching Behavior**
   - Diagnostic endpoint returns cached data (10-minute TTL)
   - Audit logging may not appear if cache hit occurs

   - Remove: `failed_blacklist`, `failed_whitelist`, `strategy_none_triggered`

2. **Implement Stage 3 Emission**
   - Create `stage3-state-emitter.ts` service
   - Emit `scan_tick` events after each FX5 scan cycle

## 11. Notes for Phase 8.8.2 (Signal Engine Audit)

The following issues discovered in 8.8.1 will impact Phase 8.8.2:

1. **Signal Engine Input Dependency**
   - Signal engine expects clean eligibleSymbols[] from scanner
   - Current eligibleSymbols schema is acceptable but needs type cleanup
   - Ensure vwap field is never undefined (use null explicitly)

2. **Event Stream Missing**
   - Signal engine needs scan_tick events to trigger evaluation cycles
   - Must implement Stage 3 emitter before testing signal engine

3. **Breakdown for Diagnostics**
   - Signal engine diagnostics may reference breakdown categories
   - Ensure breakdown keys match official spec before Phase 8.8.2

4. **Truth Constraint**
   - Signal engine may validate input data quality
   - Fix truth constraint violation to prevent downstream validation errors
