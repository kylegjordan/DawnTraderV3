## 1. Changes Implemented

### 1.1 FX5 Warm-Up Delay
- **File**: `server/services/fx5-scanner.ts`
- **Change**: Added 30-second delay after engine start before initiating the first FX5 scan
- **Expected Log**: `[FX5Scanner][A3.R8] Warm-up complete, starting first scan` appears ~T+30s after start

### 1.2 RTB Status Lifecycle
- **File**: `shared/schema.ts`
- **Change**: Added `active` status to `rtbSignalStatusEnum`
- **Status Flow**:
  - `active` → On insertion into RTBQ (newly validated signal)
  - `reconfirmed` → On successful SQE revalidation
  - `promoted` → When promoted by TCL
  - `expired` → On SQE failure or TTL exceed

### 1.3 Immediate Expiry on SQE Failure
- **File**: `server/core/rtb/ready_to_buy_service.ts`
- **Change**: Removed `MISSED_REFRESH_THRESHOLD` logic
- **Behavior**: Any failed SQE reconfirmation → immediate expiry and deletion
- **Verification**: No `[WARN] missedRefresh` logs should appear

### 1.4 Persistent Diagnostic Logs
- **Files**:
  - `server/lib/event-bus.ts` (TCL trace)
  - `server/core/rtb/ready_to_buy_service.ts` (RTB trace)
- **Log Files Created**:
  - `logs/tcl_event_trace_YYYYMMDD.log` - All TCL events
  - `logs/rtb_refresh_trace_YYYYMMDD.log` - All RTB status transitions
