## Fix Summary

### Problem
The `expireSignal()` function used a simple UPDATE to change a signal's status from 'queued' to 'expired'. However, the unique index `rtb_signals_symbol_strategy_idx` includes `status` in its composite key (mode, symbol, strategy, status), allowing multiple records per (mode, symbol, strategy) as long as they have different statuses.

When attempting to expire a 'queued' signal while an 'expired' record already existed for the same (mode, symbol, strategy), the UPDATE would create a duplicate key violation.

### Solution Applied
Modified `expireSignal()` in `server/core/rtb/ready_to_buy_service.ts` to:

1. **Fetch signal details** - Get the signal's mode, symbol, and strategy
2. **Pre-cleanup step** - Delete any existing expired records for the same (mode, symbol, strategy) combination BEFORE updating
3. **Safety logging** - Log when prior expired entries are cleared
4. **Then update** - Proceed with the standard UPDATE to mark the signal as expired

### Code Changes

#### server/core/rtb/ready_to_buy_service.ts (lines 736-765)
```typescript
async expireSignal(signalId: string, reason?: string): Promise<void> {
  const signal = await storage.getRtbSignalById(signalId);
  
  if (!signal) {
    console.warn(`[RTB] Cannot expire - signal ${signalId} not found`);
    return;
  }
  
  const deletedCount = await storage.deleteRtbSignals({
    mode: signal.mode as 'live' | 'paper',
    symbol: signal.symbol,
    strategy: signal.strategy,
    status: 'expired'
  });
  
  if (deletedCount > 0) {
    console.log(`[8.8.4-A3.R3][RTB_EXPIRE] Cleared ${deletedCount} prior expired entries for ${signal.symbol}/${signal.strategy}`);
  }
  
  await storage.updateRtbSignal(signalId, {
    status: 'expired',
    expiredAt: new Date(),
  });
  
  console.log(`[RTB] Expired signal ${signalId}: ${reason || 'TTL exceeded'}`);
}
```

#### server/storage.ts (line 711 interface + line 4422 implementation)
Extended `deleteRtbSignals` to accept optional filters:
```typescript
deleteRtbSignals(filters: { 
  mode: 'live' | 'paper'; 
  symbol?: string; 
  strategy?: string; 
  status?: string 
}): Promise<number>;
```

Implementation builds dynamic WHERE clause based on provided filters.

## Conclusion

The fix successfully resolves the expiration conflict by implementing a pre-cleanup step that removes stale expired records before updating a new signal to expired status. This approach:

1. **Preserves the unique index** - No schema changes required
2. **Maintains signal history integrity** - Only removes superseded expired records
3. **Adds observability** - Clear logging when cleanup occurs
4. **Handles edge cases** - Graceful handling when signal not found
