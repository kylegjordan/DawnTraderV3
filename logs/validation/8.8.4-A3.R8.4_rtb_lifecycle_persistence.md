# Directive 8.8.4-A3.R8.4: RTB Lifecycle Persistence and TCL Event Realignment

## Date: 2025-12-20
## Status: IMPLEMENTED (Pending Validation)

## Summary
Stabilizes the Ready-to-Buy (RTB) queue so signals remain visible until the Signal Quality Evaluator (SQE) explicitly accepts or rejects them, and synchronizes TCL promotions with RTB refresh events.

## Root Cause Analysis
After A3.R8.3 (NGC calibration), signals were passing SQE but disappearing within seconds due to:
1. **Immediate deletion of expired signals** - Signals were deleted right after SQE failure
2. **Premature TTL expiry** - No visibility period for status transitions
3. **TCL threshold trigger timing** - Fired before refreshed RTB data was visible

## Changes Implemented

### 1. RTB Lifecycle Behavior (ready_to_buy_service.ts)

**Before:** Expired signals deleted immediately after SQE failure
```typescript
if (!sqeResult.passed) {
  await storage.deleteRtbSignals({ mode, symbol, strategy, status: 'expired' });
}
```

**After:** Mark as 'expired' with timestamp, defer deletion
```typescript
if (!sqeResult.passed) {
  await storage.updateRtbSignal(signal.id, {
    status: 'expired',
    expiredAt: new Date(),
    metadata: { expiredAtMs: Date.now(), expiredReason: sqeResult.reason }
  });
  // Do NOT delete - deferred cleanup handles after one refresh cycle
}
```

### 2. Deferred Cleanup (ready_to_buy_service.ts)

**New behavior:** `cleanupExpiredSignals()` only purges signals that have been 'expired' for 60+ seconds (one full refresh cycle)

```typescript
const DEFERRED_CLEANUP_MS = 60 * 1000; // One full refresh cycle
for (const signal of expiredSignals) {
  const ageMs = now - expiredAtMs;
  if (ageMs >= DEFERRED_CLEANUP_MS) {
    await storage.deleteRtbSignals({ mode, id: signal.id });
  }
}
```

### 3. NGC 0.85 Scaling Factor (quality_index.ts)

Applied 0.85 scaling to restore balanced SQE filtering:
```typescript
const profitabilityInformedNGC = (baseNGC * 0.4) + (profitRate * 0.4) + ((1 - riskScore) * 0.2);
const ngc = clamp01(profitabilityInformedNGC * 0.85);
```

Expected NGC range after scaling: 0.34–0.60 (down from 0.40–0.70)
Expected SQE pass rate: 30–50% (balanced filtering)

### 4. TCL Promotion Event Synchronization (ready_to_buy_service.ts)

Moved `checkSignalThreshold()` to occur AFTER `executeRefreshCycle()` completes:
```typescript
// At end of executeRefreshCycle():
if (tclStatus.poolSize > 0) {
  tclWatchdog.checkSignalThreshold(mode, tclStatus.poolSize);
}
```

→ TCL now sees a populated RTB pool at promotion time.

### 5. UI Status Column (ready-to-buy-table.tsx)

**Status:** Already implemented with proper styling:
- `active`: Blue badge - Newly inserted signal
- `reconfirmed`: Green badge - Re-validated successfully
- `expired`: Red badge - Failed SQE re-evaluation, pending cleanup
- `promoted`: Amber badge - Passed to TCL for execution

## Known Limitations

### Legacy Data Handling
Signals that were expired BEFORE this directive was deployed may not have metadata.expiredAtMs set. The cleanup logic falls back to signal.expiredAt → signal.queuedAt. Legacy signals older than 60 seconds will be cleaned up immediately on the next refresh cycle. This is acceptable behavior as it prevents stale data accumulation.

### TCL Debounce
A 5-second debounce prevents redundant activation attempts during warm-up bursts. If the pool size fluctuates around the threshold, multiple threshold checks within 5 seconds are ignored. This is intentional to prevent event spam.

## Implementation Notes
- All NEW expired signals will properly persist expiredAtMs metadata
- The deferred cleanup honors the 60s window for properly-tagged signals
- TCL fires on both enqueue and post-refresh with debounce protection
