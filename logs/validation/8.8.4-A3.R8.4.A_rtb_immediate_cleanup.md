# Directive 8.8.4-A3.R8.4.A — RTB Expiry Immediate Cleanup Amendment

## Status: IMPLEMENTED
**Date**: 2025-12-20

## Purpose
Ensure failed SQE revalidations remove signals immediately from the Ready-to-Buy queue, eliminating the 60-second persistence window.

## Changes Made

### 1. refreshAndRank() - Immediate Deletion on SQE Failure
**File**: `server/core/rtb/ready_to_buy_service.ts`

Before (A3.R8.4):
- SQE failures marked signals as `status: 'expired'` with `metadata.expiredAtMs`
- Signals persisted for 60 seconds before cleanup

After (A3.R8.4.A):
- SQE failures immediately delete signals via `storage.deleteRtbSignals({ mode, id: signal.id })`
- Logs status transition as 'deleted' for audit trail
- No residual status updates or deferred cleanup

### 2. cleanupExpiredSignals() - Simplified Legacy Cleanup
**File**: `server/core/rtb/ready_to_buy_service.ts`

Before (A3.R8.4):
- Complex 60-second deferred cleanup logic
- Multiple fallback paths for expiredAtMs derivation

After (A3.R8.4.A):
- Immediately deletes any remaining 'expired' status signals (legacy cleanup)
- Immediately deletes TTL-exceeded 'queued' signals
- No deferred cleanup window

### 3. expireSignal() - Direct Deletion
**File**: `server/core/rtb/ready_to_buy_service.ts`

Before (A3.R8.4):
- Marked signals as 'expired' with expiredAtMs metadata
- Relied on cleanupExpiredSignals() for actual deletion

After (A3.R8.4.A):
- Immediately deletes signal from database
- No intermediate 'expired' status

### 4. storage.deleteRtbSignals() - ID Parameter Support
**File**: `server/storage.ts`

Added `id?: string` parameter to interface and implementation for precise single-signal deletion.

## Validation Criteria

| Criteria | Status |
|----------|--------|
| Expired signals disappear instantly after re-evaluation | ✅ |
| TCL threshold reflects only active/reconfirmed signals | ✅ |
| No expired signals linger beyond current tick | ✅ |
