2. Problem Statement (Treat as Facts)

After REB 2.4 & REB 2.5, the user verified:

Engine startup was < 10s

FX5Scanner was running and producing:

60 evaluated pairs per cycle

Top-N/Tier-B split (36 + 24)

Survivors in paper mode

Filter Insights was seeing scan updates (even if UI wasn’t fully correct)

After REB 2.6:

Engine still starts quickly (thanks to REB 2.5)

But logs show no FX5 scanner cycles

ReB 2.6 concluded “FX5 scanner not initialized” — this directly contradicts the previously-working behavior

Conclusion:
REB 2.6’s passive learning enforcement changes accidentally disrupted scanner bootstrap / scheduling / mode gating. REB 2.7’s job is to restore scanner bootstrap so we get:

FX5Scanner running again (every 30s)

While still correctly enforcing passive learning semantics from REB 2.6.
