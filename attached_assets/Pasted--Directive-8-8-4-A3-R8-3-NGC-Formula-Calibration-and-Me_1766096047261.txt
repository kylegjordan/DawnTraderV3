This directive recalibrates the NGC formula, prevents double normalization, adjusts metric weighting, and adds a profit floor safeguard.

🎯 Objectives

🔧 Implementation Tasks
1️⃣ File: shared/metrics/signal_metrics.ts

Problem: All metrics (CWQI, ProfitRate, Risk) are normalized again even though strategy outputs are already 0–1 scaled, causing compression of midrange values.

Fix:
Replace unconditional normalization with conditional normalization only when out of bounds.

export function normalizeMetric(value: number, min: number, max: number): number {
  if (value == null || isNaN(value)) return 0;
  // Only normalize if outside [0,1]
  if (value < 0 || value > 1) {
    const clamped = Math.max(min, Math.min(max, value));
    return (clamped - min) / (max - min);
  }
  return value;
}

2️⃣ File: server/core/sqe/signal_quality_engine.ts

Problem: Current NGC weighting (0.4/0.4/0.2) undervalues CWQI and over-normalizes final NGC.

Fix: Update the weighting formula and remove final normalization.

// Recalibrated NGC weighting
const ngc =
  (signal.metrics.cwqi * 0.5) +
  (signal.metrics.profitRate * 0.3) +
  ((1 - signal.metrics.riskScore) * 0.2);

// Remove extra normalizeNGC() call
signal.metrics.ngc = parseFloat(ngc.toFixed(4));

// Trace log
console.log(`[A3.R8.3][SQE] ${signal.symbol}/${signal.strategy} cwqi=${signal.metrics.cwqi.toFixed(3)} profit=${signal.metrics.profitRate.toFixed(3)} risk=${signal.metrics.riskScore.toFixed(3)} → ngc=${signal.metrics.ngc.toFixed(3)}`);


This preserves linear scaling and yields realistic NGC distributions (0.25 – 0.6 typical).

3️⃣ File: server/strategies/vwap_pullback.ts

Problem: ProfitRate rounds to zero when takeProfit ≈ entry, triggering ProfitRate < 0.1 rejection even for valid setups.

Fix: Add minimum floor to avoid zeroing due to rounding.

profitRate = (takeProfit - entry) / entry;
if (Math.abs(takeProfit - entry) < 0.0001) {
  profitRate = 0.0001; // Prevent zero floor
}
