Directive 11.8V-D2 — DSS Canonical Alignment & Deterministic Strategy Selection (Full Technical Specification)

Status: APPROVED FOR IMPLEMENTATION Scope: Live/Paper Trading Engine Only Out of Scope: VTS, Expectancy Math, SQE Logic Changes, Indicator Redesign

SECTION 1 — ROOT CAUSE & ARCHITECTURAL DRIFT
1.1 Intended Architecture (Original Design)

The intended canonical decision chain is:

Indicators → Regime Detection → Strategy Selection → Signal Generation → SQE → RTB → Execution

Core Principles:

DSS selects ONE strategy before signal generation.

Canonical regime–strategy map is the single authority.

No post-signal ranking.

No strategy pruning via hidden maps.

1.2 Verified Drift (Code-Level Audit Findings)

The following issues were confirmed:

SYSTEM_GUARDS.STRATEGY_MAP was still controlling eligibility.

dynamic-strategy-selector.ts still used legacy regime types.

The canonical map was imported but not used in selection.

DSS compared generated signals instead of selecting pre-generation.

enabledStrategies restricted execution to legacy quant strategies.

Hybrid strategies were category-based (H1–H4) instead of canonical.

Impact:

Canonical map not authoritative.

DSS functionally reduced to signal filter.

Hybrid logic implicit instead of explicit.

Silent narrowing of strategy breadth.

This directive eliminates those failures.

SECTION 4 — CANONICAL REGIME SYSTEM

File: server/services/dynamic-strategy-selector.ts

4.1 Canonical Regime Enum (Replace Legacy)

Define:

export type CanonicalRegime =
  | 'BULL_STABLE'
  | 'BEAR_VOLATILE'
  | 'LOW_VOL_CHOP'
  | 'HIGH_VOL_IMPULSE';

TRANSITION intentionally excluded in this phase.

4.2 Legacy Normalization

Immediately after legacy regime detection:

function normalizeLegacyRegime(regime: string): CanonicalRegime {
  switch (regime) {
    case 'BULL_VOLATILE': return 'HIGH_VOL_IMPULSE';
    case 'BEAR_STABLE': return 'BEAR_VOLATILE';
    case 'EXTREME_NOISE': return 'LOW_VOL_CHOP';
    default: return regime as CanonicalRegime;
  }
}
4.3 EXTREME_NOISE Handling

Remove veto behavior. Instead:

if (legacyRegime === 'EXTREME_NOISE') {
  confidenceMultiplier *= 0.5;
}

No early return allowed.

Retrieve ordered list:

SECTION 7 — PRECONDITIONS (OPTION B, STRICTLY CONTROLLED)
7.1 Preconditions Derived From detect() Gating

Each strategy must define a precondition function:

function isEligible_vwap_pullback(ctx: IndicatorContext): boolean {
  return ctx.price < ctx.vwap && ctx.trendSlope > ctx.thresholds.bullTrend;
}

RULES:

Boolean only

Minimal necessary logic

No TP/SL

No EV

No scoring

Must not be stricter than detect()

All preconditions must be declared in DSS and documented inline.

7.2 Selection Loop
for (const strategyKey of strategyList) {
  if (isEligible(strategyKey, indicatorContext)) {
    return {
      regime,
      selectedStrategyKey: strategyKey,
      signalType: getSignalType(strategyKey)
    };
  }
}


return null; // No strategy selected

Must stop immediately after first eligible strategy.

SECTION 8 — ORCHESTRATOR EXECUTION FLOW

File: server/services/signal-orchestrator.ts

Replace multi-strategy execution with:

const selection = dss.selectStrategy(indicatorContext);


if (!selection) return;

routeToSQE(scored);

No fallback execution.

9.1 Hybrid Execution
const quantSignal = executeQuant(baseQuantStrategy);

return buildHybridSignal(quantSignal, patternMatch);

No category-based logic. Remove H1–H4 labels entirely.

SECTION 10 — PATTERN HANDLING

Pattern strategies have no DSS precondition.

When reached in priority order:

Execute pattern detection

If no pattern → return null

Cycle ends

No pattern pre-scan inside DSS.
