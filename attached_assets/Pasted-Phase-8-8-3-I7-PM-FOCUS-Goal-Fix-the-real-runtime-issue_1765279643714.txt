C. Fix Duplicate Positions (backend + UI)
C1. Backend duplicate guard in PaperExecutionEngine
In paper-execution-engine.ts:


Identify the method that creates a new position in paper mode. (Wherever a row is inserted into the open-positions store / paper_sim_open_positions).


Before inserting / creating a new position for symbol X:


Query the canonical source of open positions for paper mode (likely paper_sim_open_positions table or in-memory structure).


Count the number of open positions for that symbol.


If count > 0 (and the strategy dictates max 1 per symbol), then:


Do not create a second position.


Log a clear diagnostic:


[I7-PM-FOCUS][DUP_GUARD_BLOCK] symbol=<symbol> existingCount=<count> action="skip_new_position"








Ensure this check is centralized:


It should sit in the lowest-level “create position” function, not only in a higher-level signal handler.


That way, any call path that tries to open a position for that symbol runs through the same guard.




This guard must be synchronous and atomic in logic (within a single-threaded Node loop), so that two back-to-back signals in the same tick still see the updated state.
