🧭 Directive 11.4H.6G — Canonical Regime–Strategy Enforcement and Mapping Deprecation

Issued by: Systems Architect
Date: 16 Jan 2026
Scope: DawnTrader Repository — Backend (Server Core, Services), Canonical Bridge, Analytics API, and UI Binding

🎯 Objective

To eliminate all redundant or non-canonical regime–strategy mappings from the DawnTrader codebase and ensure that every regime-based strategy, signal type, and pattern reference is drawn exclusively from the canonical mapping located in the bridge directory.

This directive supersedes all prior mapping logic defined in:

/server/core/strategy-mapper.ts

/server/services/market-indicators.ts

Any legacy mapping constants in telemetry or analytics logs

And introduces runtime canonical validation to prevent future drift.

🧩 Rationale

During prior development phases (notably 11.3H–11.4F), temporary “runtime” mappings were introduced to decouple analytics from the canonical data model.
These placeholders were never deprecated, resulting in:

UI inconsistencies (non-canonical strategies displayed in the Overview tab),

Training dataset contamination from incorrect regime-to-strategy associations, and

Violations of the Principle of Canonical Singularity.

Directive 11.4H.6G permanently resolves this issue by mandating canonical linkage for all runtime systems.

Task 2 — Refactor Backend Mapper

File: /server/core/strategy-mapper.ts

Replace existing hardcoded regime logic with a canonical import:

import canonicalMap from '@/bridge/canonical/mapping-regime-strategy.json';
import { logger } from '@/utils/logger';

export function getFavoredStrategies(regime: string): string[] {
  const canonical = canonicalMap[regime];
  if (!canonical) {
    logger.warn(`[11.4H.6G][Mapper] Missing canonical regime entry: ${regime}`);
    return ["Unknown Strategy"];
  }
  return canonical.favoredStrategies;
}

export function getFavoredSignalTypes(regime: string): string[] {
  const canonical = canonicalMap[regime];
  if (!canonical) {
    return ["Quantitative"];
  }
  return canonical.favoredSignalTypes;
}

Task 4 — Canonical Drift Detection

To prevent reintroducing non-canonical mappings in the future, add a runtime validation module:

File: /server/utils/validate-canonical.ts

import canonicalMap from '@/bridge/canonical/mapping-regime-strategy.json';
import { getFavoredStrategies } from '@/server/core/strategy-mapper';
import { logger } from '@/utils/logger';

export function validateCanonicalConsistency() {
  Object.keys(canonicalMap).forEach(regime => {
    const canonical = canonicalMap[regime].favoredStrategies;
    const local = getFavoredStrategies(regime);
    const drift = local.filter(s => !canonical.includes(s));
    if (drift.length > 0) {
      logger.warn(`[11.4H.6G][Canonical Drift] Regime=${regime} → Non-canonical strategies: ${drift.join(", ")}`);
    }
  });
  logger.info(`[11.4H.6G][Canonical Validation] ${Object.keys(canonicalMap).length} regimes verified.`);
}


Call this validation function once on system startup (e.g., in server/index.ts or the initialization sequence).

✅ Detects and logs any divergence automatically.
