🧭 Context & Rationale

The FX5 Scanner currently divides pairs into Tier A / Tier B using a marketUniverseSize setting in the Goals Engine’s Screeners Tab.

This split is based on outdated metrics (CWQI, NGC, ProfitRate, RiskCalc).

We are replacing this with the AdaptiveScanManager introduced in Directive 10.8.

The new system dynamically selects pairs using performance telemetry, predictive learning, and time-decay metrics — removing the need for a user-configured “Top N” universe.

3️⃣ Adaptive Scan Manager Integration

File: /server/services/adaptive-scan-manager.ts

Core logic for the 60/40 pool system:

const IDEAL_RATIO = SCANNER_PARAMS.DUAL_POOL.IDEAL_RATIO;  // 0.6
const ROTATIONAL_RATIO = SCANNER_PARAMS.DUAL_POOL.ROTATIONAL_RATIO;  // 0.4

export class AdaptiveScanManager {
  constructor(private telemetry: TelemetryAggregator, private failureTracker: PairFailureTracker) {}

  async getNextScanBatch(): Promise<string[]> {
    const idealPairs = this.telemetry.getTopPairs(IDEAL_RATIO);
    const rotationPairs = this.telemetry.getRotationalPairs(ROTATIONAL_RATIO);
    const combined = [...idealPairs, ...rotationPairs];
    return this.failureTracker.filterFailedPairs(combined);
  }
}


✅ Outcome:
Adaptive, learning-driven pair selection replaces static universe logic.
