⚙️ Phase 27.F.14.UI-SYNC.7 — Goal Feasibility + Cooldown Synchronization + Average-Return Removal

(Full No-Code Directive for Replit)

🎯 Objective

Create a single, risk-aware goal framework that:

Prevents unrealistic “Target per Trade ($)” values.

Keeps the Symbol Cool-Down value synchronized everywhere it appears.

Cleans up legacy “Average Return” remnants.

Requires no manual code editing or migrations.

🧱 Automated Execution Steps
1️⃣ Field and Label Alignment

Rename every “Earnings per Trade” → “Target per Trade ($)”.

Add missing “Trades per Day (1 – 20)” numeric input directly above it.

Delete the obsolete “Average Return (%)” field from both Goals Tab and Performance Tracking Metrics.

Recalculate button persists as the sync trigger between Pace ↔ Performance.

2️⃣ Goal Feasibility Validation

(Logic identical to Phase 27.F.14.UI-SYNC.6, now extended to include cooldown cross-reference.)

Condition	Result	Feedback Example
Target per Trade ≤ safe limit	✅ OK	“Goals saved – within current risk limits.”
Target per Trade ≈ 50 % over limit	⚠️ Warn	“Goal exceeds Max Risk / Trade by 50 %. Adjust guardrails.”
Target per Trade ≫ limit	❌ Block	“Goal rejected – violates Position Size Cap or Risk Limit.”

All feedback logged under [GoalFeasibility].

3️⃣ Cooldown Synchronization

Create a shared cooldown registry between Guardrails → Tuning → LATTI:

onCooldownUpdate(newValue):
    guardrails.cooldown_minutes = newValue
    tuning_policy.cooldown_period = newValue
    broadcast("cooldown_synced", newValue)


Behavior

Editing “Symbol Cool-Down (min)” in Guardrails immediately updates the Tuning section.

When LATTI adjusts cooldown during nightly optimization, UI refreshes to show the new value.

Single truth source =guardrails.cooldown_minutes.

Startup log example:

[PolicySync] Cooldown period synchronized: 15 min (guardrails ↔ tuning)

4️⃣ Exploratory Mode (unchanged)
