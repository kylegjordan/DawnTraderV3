🧭 Directive 8.8.4-L9
Title: Strategy Confidence Weighting Integration
Phase: 8.8.4 (L-series)
Status: Ready for Implementation
Objective

Leverage the per-strategy calibration coefficients introduced in L8 (αₛ, βₛ) to derive live strategy-confidence weights and inject those weights directly into the Ready-to-Buy (RTB) and Signal Orchestrator ranking logic.
This creates a true data-adaptive prioritization layer where strategies that historically perform more accurately receive proportionally higher influence in trade selection.

1 | Design Goals
Goal	Description
1. Dynamic Ranking Bias	Incorporate per-strategy reliability into every trade’s finalRank.
2. Data Feedback Continuity	Continuously update weights from the most recent calibration dataset.
3. Compatibility	Preserve existing NGC, CWQI, and MLConfidence blending logic.
4. Transparency	Expose strategy weights via API + health endpoints for observability.

2.3 Final Ranking Formula
finalRank =
   (NGC * 0.30) +
   (CWQI * 0.25) +
   (MLConfidence * 0.25) +
   (StrategyWeight * 0.20)


Weights auto-normalize to 1.0 per cycle to preserve total influence balance.

3 | Implementation Tasks
3.1 Backend Services

Files:
server/services/rtb-refresh-service.ts, server/services/signal-orchestrator.ts, server/utils/strategyWeights.ts, server/routes/health.ts

Tasks

Create strategyWeights.ts utility:

Load latest vts_calibration.json coefficients.

Compute Rₛ and Wₛ for all strategies.

Expose getWeight(strategy: string) API.

In signal-orchestrator.ts:

When building the sized signal, fetch strategyWeight.

Include it in finalRank computation.

Append strategyWeight to signal object for RTB display.

In rtb-refresh-service.ts:

Ensure ranker sorts by finalRank.

Log each cycle’s strategy weights for traceability.

3.2 Adaptive Risk Advisor (ARA)

File: server/routes/ara.ts

Add strategyWeight field to calculation response object.

Display in UI with tooltip: “Relative reliability of this strategy based on recent calibration data.”

3.3 ML Microservice

File: ml_service/app.py

When predicting profit, multiply output by Wₛ for the given strategy:
predicted_profit *= Wₛ

Log: [L9][WEIGHT_APPLY] DHMA=0.17 Breakout=0.22 …

3.4 RTB Table Enhancement

File: client/src/components/RTBTable.tsx

Add column “Strategy Weight (%)”.

Tooltips explain it represents relative confidence of strategy’s profit accuracy.

Color-coded indicator (🟢 High > 0.75, 🟡 Medium 0.5–0.75, 🔴 Low < 0.5).

3.5 Health Endpoint Enhancement

Append strategyWeights object to /api/health response:

"strategyWeights": {
   "DHMA": 0.17,
   "Breakout": 0.22,
   "Reversal": 0.15,
   ...
}


Flag if any strategy’s weight deviates > 50 % from previous cycle.
