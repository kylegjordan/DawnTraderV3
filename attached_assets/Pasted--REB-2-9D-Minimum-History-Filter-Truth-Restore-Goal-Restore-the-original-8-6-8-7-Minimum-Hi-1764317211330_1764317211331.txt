1.1 Add cached daily OHLC history helper

Add a small, focused helper to compute “trading age in days” for a given pair using daily (1440m) OHLC candles.

Implementation outline (TypeScript / pseudo-code-level):

// At top-level of kraken.ts (near other caches)
const historyDaysCache = new Map<string, { days: number; fetchedAt: number }>();
const HISTORY_CACHE_TTL_MS = 30 * 60 * 1000; // 30 minutes

// Utility to get a stable cache key
function makeHistoryKey(pair: string, mode: 'paper' | 'live' | 'backtest' | undefined) {
  // mode mainly to avoid mixing configs; you may already have a canonical symbol form
  return `${mode || 'unknown'}::${pair}`;
}


Then add an async method to the Kraken service:

// Inside KrakenService class
async getPairHistoryDays(
  pair: string,
  mode: 'paper' | 'live' | 'backtest' | undefined
): Promise<number | null> {
  const cacheKey = makeHistoryKey(pair, mode);
  const now = Date.now();
  const cached = historyDaysCache.get(cacheKey);

  if (cached && now - cached.fetchedAt < HISTORY_CACHE_TTL_MS) {
    return cached.days;
  }

  try {
    // 1440 = 1-day candles (matches the 8.6 / 8.7 truth)
    const candles = await this.getOHLC(pair, 1440); 
    if (!candles || candles.length === 0) {
      // No history → treat as NULL (caller decides pass/fail semantics)
      return null;
    }

    // 8.6/8.7 behavior: number of daily candles == history days
    const days = candles.length;

    historyDaysCache.set(cacheKey, { days, fetchedAt: now });
    return days;
  } catch (err) {
    // Log once per pair per TTL window at WARN level
    console.warn('[REB2.9D][History][Error]', { pair, error: (err as Error).message });
    return null;
  }
}


Important: Re-use any existing getOHLC/fetchOHLC helper you already have in kraken.ts if it exists. Do not duplicate HTTP logic.

2.1 Add a small “passes history filter” helper

Near your other filter helpers (minPrice, volatility, etc.), add:

// Types depend on existing code, adjust to local types
type HistoryFilterContext = {
  minHistoryDays?: number | null;
  mode: 'paper' | 'live' | 'backtest';
  krakenService: KrakenService;
};

let reb29dHistoryCheckCount = 0;
const REB_2_9D_HISTORY_LOG_LIMIT = 50;

async function passesHistoryFilter(
  pair: string,
  ctx: HistoryFilterContext
): Promise<{ passed: boolean; reason?: 'failedHistory'; days?: number | null }> {
  const { minHistoryDays, mode, krakenService } = ctx;

  if (!minHistoryDays || minHistoryDays <= 0) {
    // No minimum configured → pass
    return { passed: true, days: null };
  }

  const days = await krakenService.getPairHistoryDays(pair, mode);

  // If we cannot determine history, be conservative & fail (matches original safety behavior)
  const passed = typeof days === 'number' && days >= minHistoryDays;

  // REB 2.9D diagnostics (limited for performance)
  if (reb29dHistoryCheckCount < REB_2_9D_HISTORY_LOG_LIMIT) {
    reb29dHistoryCheckCount++;
    console.log('[REB2.9D][HistoryCheck]', {
      pair,
      mode,
      days,
      threshold: minHistoryDays,
      result: passed ? 'PASS' : 'FAIL',
    });
  }

  if (!passed) {
    return { passed: false, reason: 'failedHistory', days };
  }

  return { passed: true, days };
}


If you already have a breakdown.failedHistory category in your aggregation, reuse that label string 'failedHistory' so it flows into Filter Insights correctly.
