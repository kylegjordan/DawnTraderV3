1) Filtered Pairs — Single Source of Truth & “Live Validity”

Issues Seen

Divergent eligible counts across Filter Insights, Filtered Pairs, and Filter Health.

Only 10 rows showing despite a higher eligible count.

Counts changed with Refresh even while Trading = Stopped.

“Quote Currency” appeared as top failure despite being removed.

Suspected Causes

Mixed endpoints with different limits/caches.

Legacy diagnostic cache and/or hardcoded page limits.

Refresh calling an endpoint with a different limit.

Old failure reasons read from a table instead of live diagnostic.

What to implement

Use one diagnostic service for all three surfaces with the same universe limit (full Kraken universe).

Ensure no hidden .slice or limit on filtered-pairs API responses.

When Trading is Stopped, Refresh must read the latest scan output cache but must NOT trigger a fresh market scan; counts should only change if validity windows expired.

Replace legacy failure-reason reads with live computation.

Add real-time invalidation rule for Filtered Pairs:

Pair is valid only if last-seen market tick (price/vol/range) used in the diagnostic is ≤ 12 minutes old AND all active filters still pass AND it hasn’t been explicitly blacklisted.

The moment any condition fails, the pair falls out immediately (don’t wait for the 10-min cleanup).

Expected Outcome

All three surfaces show identical eligible count and identical rows.

Filtered Pairs table shows all eligible rows (no silent limit).

Refresh while Trading=Stopped only drops items that expired by staleness/filters—not random swings.

Validation

Add a one-line diagnostic footer on both tabs:
eligible={N} ineligible={M} by_rule={vol:X, spread:Y, range:Z, history:H} universe=1447 limit=1447 at=<UTC timestamp>

Log lines for any immediate invalidation (pair + reason).

Screenshot of all three surfaces with the same N.

2) Ready-to-Buy Table — Deduping, Numeric Safety, Real-Time Expiry

Issues Seen

Blank white page (JS error: .toFixed on non-number).

Thousands of signals accumulating and repeating.

Signals not expiring quickly enough relative to current market.

Suspected Causes

Mixed types (string numbers) feeding formatting.

Signals persisted without strict dedupe keys.

Expiry tied to a 24h horizon, not to current validity.

What to implement

Type safety on all numeric fields before formatting (price, vwap, range, entry/stop/target, confidence).

Idempotent persistence: ensure userId + mode + symbol + strategy + detected_at bucket (or a hash of entry/stop/target + symbol + strategy) dedupes. Store a dedupe_key column if helpful.

Immediate expiry rule for signals in “Ready to Buy”:

A signal is valid only while all strategy preconditions stay true and entry window remains within bounds (e.g., price proximity to entry, range intact, volume confirmation not stale).

If preconditions fail for 5 consecutive minutes (or two full scan cycles), mark expired and hide from the table immediately (don’t wait for periodic cleanup).

Keep Active/Dismissed/Expired/Executed statuses and surface “Why it expired” in a hover/help cell.

Expected Outcome

No blank page; table loads consistently.

Duplicate signals cease; visible list only contains current opportunities.

The Ready-to-Buy count drops naturally as conditions fall off.

Validation

Add a small “data types OK” metric on the table footer: typed=true once all fields are numbers.

Log lines for dedupe prevented (with dedupe_key) and signal expired (with reason).

Screenshot showing Ready-to-Buy count decreasing as conditions roll off.
