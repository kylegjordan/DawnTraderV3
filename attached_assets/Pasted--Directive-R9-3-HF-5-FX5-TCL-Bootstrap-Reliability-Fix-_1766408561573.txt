🧭 Directive R9.3.HF-5 — FX5 & TCL Bootstrap Reliability Fix
📘 Purpose

Directive R9.3.HF-5 addresses a persistent reliability issue where the FX5 Scanner and TCL Watchdog fail to initialize or silently stop receiving ticks from the Central Clock, while other subsystems (RTB Refresh, SQE Evaluation) continue running.

The issue is caused by:

A stale singleton bootstrap flag (bootstrapped = true) preventing the FX5 Scanner from reinitializing after workflow reloads or VM restarts.

The TCL Watchdog not re-subscribing to the Central Clock when the scanner fails to start.

The fix guarantees deterministic startup for FX5 Scanner, Central Clock, and TCL Watchdog in the correct order — ensuring continuous scan cycles, signal flow, and trade promotion events.

/**
 * R9.3.HF-5: Resilient FX5 Bootstrap
 * Ensures the FX5 Scanner initializes deterministically after restarts or reloads.
 */

let bootstrapped = false;
let lastBootstrapAttempt = 0;

export async function bootstrapFX5Scanner(force = false): Promise<void> {
  const now = Date.now();

  // Prevent duplicate inits unless explicitly forced or last attempt > 60s ago
  if (!force && bootstrapped && now - lastBootstrapAttempt < 60000) {
    console.log('[FX5Bootstrap] Skipping reinit (already bootstrapped <60s ago)');
    return;
  }

  try {
    bootstrapped = true;
    lastBootstrapAttempt = now;
    console.log('[FX5Bootstrap] ⚙️ Initializing FX5 Scanner...');

    const { startFX5Scanner } = await import('../services/fx5-scanner.js');
    await startFX5Scanner();

    console.log('[FX5Bootstrap] ✅ FX5 Scanner started successfully');
  } catch (err) {
    bootstrapped = false;
    console.error('[FX5Bootstrap] ❌ Failed to start FX5 Scanner:', err);
  }
}


✅ Purpose

Ensures FX5 scanner initialization even after prior “bootstrapped” state.

Adds explicit logging for each bootstrap cycle.

Allows forced reinitialization via bootstrapFX5Scanner(true) from server startup.
