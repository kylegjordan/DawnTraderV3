🧾 Directive 8.8.4-A4.R10R-4 — Core System Hardening
📘 Purpose

This directive hardens the Dawn Trader server runtime and service infrastructure.
It locks the system modules (Central Clock, Price Cache, RTB Refresh, FX5 Scanner, and Ready-to-Buy Service), ensures clean shutdown and startup behavior, introduces health monitoring, and enforces architectural integrity ahead of live-mode development.

This is the final step of the A4.R10R cycle, transitioning the system from a “diagnostic/tuning state” to a production-ready, fault-tolerant state.

4️⃣ Introduce Health Monitor

File: server/services/system-health.ts

Create a lightweight health monitor with real-time metrics.

import os from 'os';
import { EventEmitter } from 'events';

class SystemHealth extends EventEmitter {
  metrics = { cpu: 0, memory: 0, lag: 0, uptime: 0 };

  async sample() {
    const load = os.loadavg()[0];
    const mem = process.memoryUsage().rss / 1024 / 1024;
    const uptime = process.uptime();
    this.metrics = { cpu: load, memory: mem, lag: global.__eventLoopLag || 0, uptime };
    this.emit('update', this.metrics);
  }
}

export const systemHealth = new SystemHealth();
setInterval(() => systemHealth.sample(), 10000);


Expose via /api/health (GET) → returns {cpu, memory, lag, uptime}
Purpose: allow real-time monitoring without external profilers.
