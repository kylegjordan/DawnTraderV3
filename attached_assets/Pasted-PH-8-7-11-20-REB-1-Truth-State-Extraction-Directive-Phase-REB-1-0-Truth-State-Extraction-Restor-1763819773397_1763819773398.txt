📌 Context

This restoration directive is part of the master recovery program defined in:

/docs/restoration/PH_8.7-11.20-REB_0_MasterBlueprint.md

A rollback incident occurred due to a GitHub sync mistake, where Replit pulled older files from GitHub and overwrote several weeks of development work inside the Replit workspace. As a result, major systems including:

FX5 Scanner

Filter Insights

Screeners Tab (Goals Engine → Screeners)

Active Filtered Pool (dedupe + expiry)

UI → Endpoint Mapping

Filter Breakdown categories

Rotation logic

Universe / batching logic

…were unintentionally reverted to older states.

Our goal is to reconstruct the correct 11/18 → 11/20 state of the system using a structured multi-phase rebuild process.

This is NOT a refactor.
This is forensic extraction of the truth, so we can restore the system to the correct configuration before the rollback occurred.

🎯 Objective of REB 1

REB 1 must produce a complete truth-state report for all systems touched by the rollback.
NO CODE CHANGES are allowed in REB 1.

You must only audit, extract data, analyze, compare, and produce documents.

This truth-state report will then be reviewed by the Architect.
If anything is missing, you will be asked to produce additional extractions until the full truth is obtained.
