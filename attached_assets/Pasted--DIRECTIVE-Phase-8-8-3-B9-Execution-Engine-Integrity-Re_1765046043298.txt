✅ DIRECTIVE — Phase 8.8.3 – B9 “Execution Engine Integrity + Real Pricing Enforcement”
CONTEXT

DawnTrader V3 must run exclusively on the modern execution engine (paper-execution-engine.ts).
Paper simulations must never use mock pricing unless explicitly in a developer/testing mode.

Recent findings show:

The correct V3 engine is being used, but old legacy engine code (paper-execution.ts) remains in the repository and can cause confusion or regressions.

Mock pricing is being used during paper trading, causing fake prices such as $100 or $170 for altcoins (e.g., LDOUSD, NANOUSD, ADAAUD), which produced massive and unrealistic P&L percentages (+12,000% to +20,000%).

Fallback pricing behavior is unsafe:

When WS/REST price is unavailable → system uses mock → dangerous.

Entry prices are not stored as “last known good” reference.

This leads to fantasy exits even though the engine logic is correct.

To stabilize DawnTrader V3 and ensure accurate strategy behavior, these issues must be corrected in a coordinated way.

🎯 GOALS
A. Ensure only the V3 engine (paper-execution-engine.ts) is ever used in runtime

Eliminate or isolate the legacy paper-execution.ts.

Add guardrails to prevent accidental legacy imports.

Confirm all runtime imports use the V3 engine.

B. Disable mock pricing in real paper simulation workflows

Mock pricing should be used only for explicit developer testing, not for normal trading simulations.

For production-like paper mode:

Do NOT fall back to $100 or $170 fabricated mock prices.

If real pricing is unavailable → mark the symbol as “no reliable price” → skip trade entry or skip closing rather than fabricate a price.

Continue logging diagnostics, not using mock price for live simulation.

C. Strengthen price-cache behavior for reliability

When a trade opens:

Seed the price cache with the entry price as lastKnownGoodPrice.

When attempting to close:

Prefer:

Fresh Kraken WS price

Fresh REST price

lastKnownGoodPrice, NOT mock

Retain B8.PNL anomaly logs.

This prevents price “teleportation” during brief data gaps.
