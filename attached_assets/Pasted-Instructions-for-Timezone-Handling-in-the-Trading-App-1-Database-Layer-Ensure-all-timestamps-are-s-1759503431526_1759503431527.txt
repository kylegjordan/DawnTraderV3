Instructions for Timezone Handling in the Trading App
1. Database Layer

Ensure all timestamps are stored in UTC:

Confirm Neon/Postgres server is set to UTC (default).

Migrate existing timestamp columns to timestamptz so they’re timezone-aware:

ALTER TABLE trades 
ALTER COLUMN created_at 
TYPE timestamptz 
USING created_at AT TIME ZONE 'UTC';

ALTER TABLE transactions 
ALTER COLUMN executed_at 
TYPE timestamptz 
USING executed_at AT TIME ZONE 'UTC';


Repeat for any other date/time columns.

This ensures PostgreSQL now knows timestamps are UTC.

2. Backend / API Layer

Always write timestamps in UTC when saving trades, reports, or transactions:

When inserting, explicitly use UTC:

INSERT INTO trades (created_at, ...) VALUES (NOW() AT TIME ZONE 'UTC', ...);


Or enforce UTC at the application level (e.g., JavaScript/TypeScript new Date().toISOString() → always UTC).

Always fetch in UTC, then convert at display time.

3. Frontend Display Logic

Conversion rule:

Raw data comes back as UTC.

Use a library like luxon or dayjs (with timezone plugin) to handle conversion.

Example (using dayjs):

import dayjs from 'dayjs';
import utc from 'dayjs/plugin/utc';
import timezone from 'dayjs/plugin/timezone';

dayjs.extend(utc);
dayjs.extend(timezone);

const userTZ = getUserTimezonePreference(); // e.g., "America/New_York"
const utcTime = dayjs(trade.created_at).utc();
const localTime = utcTime.tz(userTZ);

// For display
utcTime.format("YYYY-MM-DD HH:mm:ss [UTC]");
localTime.format("YYYY-MM-DD hh:mm A [Local Time]");


Apply consistently:

Trades list

Transaction history

Reports

Dashboard widgets

4. Dual-Time Widget (Dashboard & App Header)

Create two side-by-side time widgets:

UTC Clock

Label: UTC Time

Value: Current UTC time (live updating).

Local Clock (User-Selected)

Label: Local Time (${user’s timezone name})

Value: Current local time based on user’s selected timezone (live updating).

Example layout (pseudo-code JSX):

<div className="time-widgets">
  <div className="time-widget">
    <span className="label">UTC Time</span>
    <span className="value">{dayjs().utc().format("HH:mm:ss")}</span>
  </div>
  <div className="time-widget">
    <span className="label">Local Time ({userTZ})</span>
    <span className="value">{dayjs().tz(userTZ).format("HH:mm:ss")}</span>
  </div>
</div>


Make sure both auto-update (e.g., re-render every second).

5. User Preferences

Confirm there’s a stored user timezone setting (e.g., "America/New_York", "Asia/Dubai", etc.).

Use that for:

Historical trade display.

Local time widget.

Formatting in 12h/24h preference.
