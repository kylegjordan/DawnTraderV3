DawnTrader currently exhibits a “frozen prices” problem:

You correctly identified the root cause:

❗ The WebSocket never starts

because paper-sim-service.ts contains this block:

if (existingSession && existingManager) {
  console.log('[PaperSimService] Paper trading already running...');
  return {...};       // ❌ EARLY RETURN
}


This early return prevents:

manager.start()
  → executionEngine.start()
     → krakenWebSocketAdapter.start()


from ever being called.

As a result:

No WS connection

No symbol subscriptions

No live prices

Last Known Good prices stay frozen

No TP/SL triggers

The system appears “frozen”

You already confirmed the V3 engine is running correctly.
The only error is in simulation start/stop control flow.

This directive fixes that issue, adds diagnostics, fixes restart behavior, ensures proper WebSocket subscriptions, and instructs you on verification.

🔧 PART 1 — Add Diagnostic Logs to Identify Control Flow
File: server/services/paper-sim-service.ts

Inside the early-return block, add:

console.log('[DEBUG-B9][EARLY_RETURN_TRIGGERED]', {
  existingSession: !!existingSession,
  existingManager: !!existingManager,
  managerIsRunning: existingManager?.isRunning ?? null,
});


This helps confirm how often this branch fires.

🔧 PART 2 — Replace Early-Return With Correct Start Logic

Remove or overwrite:

if (existingSession && existingManager) {
  console.log('[PaperSimService] Paper trading already running...');
  return {...};
}

Replace with the following:
const manager = existingManager ?? createNewManager(session);

if (manager.isRunning) {
  console.log('[PaperSimService] Manager already running, returning status.');
  return {
    status: 'already_running',
    sessionId: session.id,
  };
}

console.log('[PaperSimService] Starting or restarting paper trading manager...', {
  hadExistingSession: !!existingSession,
  hadExistingManager: !!existingManager,
});

await manager.start();

return {
  status: 'started',
  sessionId: session.id,
};


This ensures:

We never skip starting the engine when we shouldn’t

WebSocket startup is always reached

🔧 PART 3 — Instrument Manager and Engine Startup Chain
File: server/trading/paper-portfolio-manager.ts

At construction:

console.log('[DEBUG-B9][MANAGER_CREATED]', {
  createdAt: new Date().toISOString(),
  sessionId: this.sessionId,
});


Inside start():

console.log('[DEBUG-B9][MANAGER_START_CALLED]', { sessionId: this.sessionId });

File: server/trading/execution/paper-execution-engine.ts

Inside start():

console.log('[ENGINE][EXECUTION_START]', {
  sessionId: this.sessionId,
});

File: server/pricing/kraken-websocket-adapter.ts

Inside start():

console.log('[KrakenWS][START]', {
  startedAt: new Date().toISOString(),
});


After subscriptions update:

console.log('[KrakenWS][SUBSCRIPTIONS_UPDATED]', {
  symbols: Array.from(this.subscribedSymbols),
});

🔧 PART 4 — Ensure WebSocket Subscriptions Include Proper Symbol Groups

Symbols with currently open positions

Merge these:

const requiredSymbols = new Set([
  ...fx5ActivePoolSymbols,
  ...symbolsWithOpenPositions,
  ...rtbSignalSymbols,

this.subscribeTo(requiredSymbols);


Kraken WebSocket subscription rate limits:

They do not restrict number of subscribed symbols in practice

Subscribing to 20–50 symbols is typical

Our pools are <25 symbols → safe
