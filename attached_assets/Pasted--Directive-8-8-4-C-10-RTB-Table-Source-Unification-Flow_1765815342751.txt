⚙️ Directive 8.8.4-C.10 — RTB Table Source Unification & Flow Validation
Objective

Unify the Ready-to-Buy (RTB) data source across the backend and frontend so all SQE-qualified signals appear in the UI immediately after trading starts, and ensure trades open only via the RTB promotion process (no direct bypass).

Background

Current state:

The backend correctly populates the rtb_signals table (51 queued signals confirmed).

The /api/trading-signals endpoint still queries tradingSignals, which is empty.

The UI calls that endpoint, so it renders an empty placeholder even though valid data exists.

Simultaneously, some signals bypass RTB entirely and execute trades directly (dual-path issue).

Tasks for Replit
1️⃣ Fix API Data Source

File: server/routes.ts → endpoint /api/trading-signals

Replace:

with:

const signals = await storage.getRtbSignals(...);


Ensure the query fetches from the correct table and excludes expired signals.

2️⃣ Add RTB Query to Storage Layer

File: server/storage.ts

export async function getRtbSignals(mode: string) {
  return await db('rtb_signals')
    .select('*')
    .where({ mode })
    .andWhereNot('status', 'expired')
    .orderBy('cwqi', 'desc');
}

SignalOrchestrator → SQE → RTB Queue → TCL → Execution
