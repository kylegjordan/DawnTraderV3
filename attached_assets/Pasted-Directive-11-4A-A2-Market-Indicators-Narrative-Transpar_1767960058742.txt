Issued by: Architectural Core
Applies to: DawnTrader Core + UI Layer (Signal Orchestrator, Cost Metrics, RTB, VTS, TEC, Analytics UI)
Schema Target: v1.6.0
Status: Approved for Implementation

I. Objective

To establish a unified Market Indicators and Narrative Transparency Dashboard that provides both:

Global Market Intelligence — Market Regime and Global Market Friction.

Operational Transparency — Per-signal friction insights and a running narrative of trade activity.

This ensures the operator always understands what the market is doing, how DawnTrader is responding, and why trades behave as they do.

II. Core Goals
#	Goal	Description
1	Market Regime Transparency	Display the global regime with descriptive context and favored strategy guidance.
2	Market Friction Awareness	Quantify liquidity and execution pressure per-signal and globally (Top-100 pool).
3	Narrative Feed	Present a timestamped narrative of trading events and adaptive actions.
4	Unified Analytics Hub	Centralize diagnostics, goals, and telemetry into one operator console.
III. Implementation Tasks
Task 1 — Compute Market Friction per Signal

File: /server/core/metrics/cost-metrics.ts

Add:

export const computeMarketFriction = (spread: number, slippage: number, fee: number): number => {
  // Normalize and scale 0–100
  const base = (spread + slippage + fee) * 10000;
  const normalized = Math.min(base / 3, 100);
  return Math.round(normalized);
};


Usage Rules:

Cached in CostCache with 60s TTL.

Saved as marketFriction in all signal and trade objects.

Used both per-signal and in globalFrictionScore computation.

✅ Global Friction Calculation:

// Derived from FX5 Top-100 Active Scan Pool
globalFrictionScore = mean(
  computeMarketFriction(spread, slippage, fee)
  for symbol in FX5ActiveTop100Pool
);


If fewer than 50 pairs in FX5 pool → fallback to predefined Top-100 liquidity list.
Exclude delisted or ultra-low volume pairs.
