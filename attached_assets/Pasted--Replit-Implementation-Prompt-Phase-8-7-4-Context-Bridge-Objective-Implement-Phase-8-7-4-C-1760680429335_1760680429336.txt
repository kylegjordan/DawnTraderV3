⚙️ Replit Implementation Prompt — Phase 8.7.4 Context Bridge
🎯 Objective

Implement Phase 8.7.4 – Context Bridge, enabling real-time, bidirectional synchronization between Walter’s panel, chat widget, and backend systems.
Replace manual polling with WebSocket-based push notifications so every interface shares the same state, session, and conversation context.

🧩 Key Tasks

Service: server/services/context-bridge.ts

Create a unified subscription layer that listens for state changes (trades, configs, memory updates).

Publish updates to all connected clients via WebSocket channel ws://context/updates.

Support both event types:

{"type":"state_update","payload":{"tradingStatus":"running","openPositions":5}}
{"type":"chat_update","payload":{"newMessage":"Trade executed successfully"}}


Frontend Integration

Modify both panel and widget clients to subscribe to the same WebSocket endpoint.

On receiving updates, auto-refresh UI sections (trading status, balances, logs) within < 2 s.

Backend Hooks

Integrate the Context Bridge into the State Awareness Layer.

Trigger contextBridge.broadcast() after:

trade execution

config change

cache invalidation event

Session Unification

Maintain a single shared sessionContext object in memory that both chat interfaces read from.

Ensure consistent intent history and validation context across UI instances.

Error Handling

If a broadcast fails, retry × 3 and log to context_bridge_log.

Include traceId and timestamp for debugging.

Testing

Simulate concurrent updates from trading, config, and chat modules.

Verify both interfaces receive identical data and refresh automatically.

Documentation

Update replit.md with details of WebSocket events, reconnect logic, and example payloads.

🧠 Implementation Notes

Reuse existing WebSocket infrastructure (already present in system).

Ensure backward compatibility with existing REST polling endpoints (mark as deprecated).

Keep messages lightweight — send only deltas, not full payloads.

Validate that Context Bridge broadcasts always originate from the latest cached state (BobCore).

✅ Expected Outcome

Manual refresh eliminated — UI auto-updates in real time.

Both Walter chat interfaces show synchronized data and context.

context-bridge.ts service operational and fully logged.

All tests pass; documentation updated; architect review approved.
