4. Planned Changes (What you MAY change)
H9.1 — Fix decision_quality_audit.accuracy_score Overflow

Intent: keep the decision-quality auditing working, but stop numeric overflow errors.

Steps:

Inspect DB schema for decision_quality_audit.accuracy_score.

Confirm it is currently NUMERIC(3,2) (range ~ -9.99 to 9.99).

Inspect all usages in code (search for decision_quality_audit, accuracy_score, ReflectiveIntelligence).

Confirm these scores are diagnostic only (health %, cognitive score %, etc.), not used for trading decisions.

Confirm they are intended to be 0–100 style percentages.

If they are diagnostic only (no influence on guardrails / RTB / execution), then:

Apply a DB migration:

Change accuracy_score to NUMERIC(5,2) or equivalent, able to hold 0.00–100.00.

In reflective-intelligence.ts:

Ensure values written are clamped to a safe range, e.g. 0 ≤ score ≤ 100.

Guard against NaN / Infinity (log and skip rather than error).

If you find any path where accuracy_score or these scores influence trading decisions:

Stop. Do not change behavior.

Document the finding in the H9 audit doc and do not proceed beyond adding defensive try/catch that logs and skips the insert.

H9.2 — Tidy Autonomy Scheduler / Safety Sweeper Warnings

Intent: keep autonomy’s archival tasks working, but make logs honest and non-spammy.

Steps:

In autonomy-scheduler.ts and any “sweeper” / cleanup job:

Ensure log messages correctly report:

how many rows were scanned

how many were deleted

how often jobs run.

Ensure there is **no interaction with:

guardrails_v2

trading status

kill switches

trading engine start/stop.**

If you find any logic in autonomy scheduler that:

toggles kill switches,

modifies guardrails,

toggles engine state,

or alters trading data:

Do not modify it yet.

Clearly document it in the H9 audit doc under “Unexpected autonomy dependencies” and leave behavior unchanged.

You may:

Fix off-by-one counters,

Reduce log verbosity (e.g., log summary once per run instead of per-row),

Wrap non-critical errors in try/catch and log them as warnings instead of exploding the logs.

We already unified kill-switch state to guardrails_v2. SafetyGuardrails must remain:

Non-essential

You may:
