🖥️ Frontend Implementation — EngineTelemetry Tab

File: client/src/pages/system/EngineTelemetry.tsx

Add to navigation: System Monitoring → after LATTI Tuning.
Label: 🩺 Engine Telemetry (Health Monitor)

Data Sources

WebSocket feed health_engine (heartbeat every 5 s)

REST fallback GET /api/health/summary (every 15 s)

Display Structure

Top Row

System Status (✅ OK / ⚠️ Warn / 🚨 Critical)

Heartbeat Latency (gauge + sparkline)

Last Recovery Event (timestamp + type)

Sections

Queue Health (Paper & Live)
Metrics: depth, executingAgeMs, piggybackCount
Below tile:

Queue Depth — normal 0-3 ⚠️ > 10 = bottleneck
Executing Age — normal < 500 ms 🚨 > 3000 ms = stuck job (auto-recovery 60 s)

Engine Health
Metrics: isRunning, lastTickAgeMs, lastSignalAgeMs

Tick Age < 60 000 ms ✅ ⚠️ > 1 min = idle engine (auto-restart)

Market Data Status
Metrics: websocketStatus, lastUpdateAgeMs, fallbackActive

Normal: connected or fallback_rest; 🚨 blocked > 30 s → auto-recovery.

Cache & Database
Metrics: cache.hits, cache.misses, db.pool.active, slowQueries

Cache Hit Rate > 80 % ✅ < 60 % = latency risk.
Slow Queries < 2/min ✅ > 10 = index review.

Broadcast Latency & Recovery Log
Metrics: lastLatencyMs, lastEvent, plus table from /api/health/recovery.

Broadcast Latency < 100 ms ✅ High values = network load.

Each tile has collapsible “ℹ️ Learn More” section with these guidelines.
