🚨 REB 2.10 — Passive Learning Deep Tests
Context (MANDATORY — DO NOT SKIP)

The purpose of REB 2.10 is to fully restore the Passive Learning Deep Test system that existed in Releases 8.6 and 8.7 before the regressions.

Passive Learning is not the same as LATTi learning logic.
It does not adjust filters, modify trading behavior, or perform inference.

Its sole purpose is:

“Verify that the FX5 engine is producing complete, consistent, deeply structured learning data that future LATTi models will consume.”

This includes:

Complete cycle diagnostics

Per-pair filter evaluation snapshots

Correct filter pass/fail reasons

Correct market data capture

Correct trading-age (history days) detection

Correct state snapshots for each FX5 cycle

No missing fields

No malformed structures

No regressions from the 8.6 / 8.7 implementation

REB 2.10 is 100% diagnostic & read-only, with no changes to trading behavior and no changes to LATTi.

📦 (A) Required Additions — Data Snapshots

REQUIRE the FX5 engine to produce three passive-learning snapshot objects per cycle:

1. CycleStart Snapshot

Create a JSON object per cycle:

{
  cycle: number,
  mode: "paper" | "live",
  timestamp: ISO8601,
  filters: {
    minVolume: number,
    minLiquidity: number,
    minPrice: number,
    maxPrice: number,
    rsiMin: number,
    rsiMax: number,
    volatilityMin: number,
    volatilityMax: number,
    maxBidAskSpread: number,
    universeSize: number,
    activeTimeframes: string[],
    minHistoryDays: number,
    excludeStablecoins: boolean,
    allowRegulatedOnly: boolean
  }
}


This is logged as:

[REB2.10][CycleStart] { ...snapshot }

2. Per-Pair Evaluation Snapshot

For every pair evaluated in FX5:

{
  cycle: number,
  mode: string,
  pair: string,
  timestamp: ISO8601,
  marketData: {
    price: number,
    spreadPct: number,
    volume: number,
    liquidity: number,
    rsi: number | null,
    volatility: number | null,
    historyDays: number | null,
    quoteCurrency: string
  },
  filterResults: {
    failedVolume: boolean,
    failedLiquidity: boolean,
    failedPrice: boolean,
    failedRange: boolean,
    failedRSI: boolean,
    failedVolatility: boolean,
    failedSpread: boolean,
    failedStablecoin: boolean,
    failedHistory: boolean,
    passed: boolean
  }
}


Logged as:

[REB2.10][PairSnapshot] { ...snapshot }

3. CycleSummary Snapshot

Create a final summary object:

{
  cycle: number,
  mode: string,
  timestamp: ISO8601,
  totals: {
    evaluated: number,
    survived: number
  },
  breakdown: {
    failedVolume: number,
    failedLiquidity: number,
    failedPrice: number,
    failedRange: number,
    failedRSI: number,
    failedVolatility: number,
    failedSpread: number,
    failedStablecoin: number,
    failedHistory: number,
    passed: number
  },
  activePoolSize: number
}


Logged as:

[REB2.10][CycleSummary] { ...snapshot }
