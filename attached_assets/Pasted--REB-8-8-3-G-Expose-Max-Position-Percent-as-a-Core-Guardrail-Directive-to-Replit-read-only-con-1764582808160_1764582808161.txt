🧩 REB 8.8.3-G — Expose Max Position Percent as a Core Guardrail

Directive to Replit (read-only context + tightly scoped change)

0. Context (Do NOT skip)

This work is part of the REB 8.8.3 line of phases for DawnTrader:

Kill switch, trading state, Active Filtered Pool, Ready-to-Buy, and execution path have already been repaired and unified.

Guardrails now flow through guardrails_v2 → GuardrailPolicy → RiskManager → Strategy/Execution.

The risk per trade guardrail (portfolioRiskPerTradePct) is already in use; do NOT change its semantics.

There is already a hidden “max position” cap enforced in risk-manager.ts (e.g., 10% or 30% depending on mode).
Right now:

That max position cap is not visible in the UI.

It behaves like a silent, hard-coded guardrail.

Kyle wants this visible and adjustable, like the other guardrails.

From this phase onward:

Max Position Percent must become a first-class guardrail, visible and controllable in the UI, but we must NOT change the existing risk logic semantics.

We are not building any new strategy logic in this phase.
We are not changing scan cadence, FX5, or RTB in this phase.

1. Goals

Surface Max Position Percent as a Core Guardrail

Make the backend and UI treat “Max Position Percent” as an explicit guardrail, not a hidden constant.

It should participate in the same pipeline as other guardrails (dailyLossKillSwitch, portfolioRiskPerTradePct, symbolCooldownMinutes, maxOpenPositions).

Keep risk per trade logic exactly as-is

portfolioRiskPerTradePct remains the position-sizing input (“how much risk to plan”).

Max Position Percent remains a hard cap on actual position notional (“how large a position we actually allow”).

We do not change the core risk formula in this phase.

Add clear human-readable descriptions under each guardrail

For every core guardrail, including the new one, add a short description directly under the control on the Guardrails tab.

This is for Kyle (the user), not for LATTI — plain language, one–two lines each.

No architectural disruption

No changes to:

FX5 cadence

Active Filter Pool logic

Ready-to-Buy lifecycle

Trading engine start/stop

Only extend guardrail configuration and its UI reflection.

2. Non-Goals (Very Important)

Do NOT in this phase:

Change how portfolioRiskPerTradePct is interpreted or used.

Change the risk sizing formula beyond plugging in the already-existing max position cap.

Add new cadences or background loops.

Change anything about LATTi autonomy logic beyond allowing her to set this new guardrail value the same way she sets others.

Modify Ready-to-Buy behavior, execution logic, or cooldowns.

All of that is for later phases (8.8.3-H, 8.8.3-I, 8.8.3-J, 8.8.3-K / Phase 9).
