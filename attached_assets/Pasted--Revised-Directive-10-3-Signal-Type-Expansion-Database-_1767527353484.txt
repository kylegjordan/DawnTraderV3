✅ Revised Directive 10.3 — Signal Type Expansion (Database Persistence)
Objective

To extend the database schema, storage layer, and execution engines so that every trade — live or simulated — permanently stores its contextual identity:
signalType, patternType, and patternStrength.

This ensures all Quant, Pattern, and Hybrid trades retain their origin, enabling full historical analytics, model training, and hybrid performance visualization.

Dependencies

Phase 9: Math Core (NetEV, CWQI)

Directive 10.1: Dynamic Strategy Selector (Regime Detection)

Directive 10.2: Pattern Recognizer (Predictive-Ready)

server/types.ts: Centralized Type Dictionary (SignalType, PatternType)

Implementation Scope
1. UPDATE DATABASE SCHEMA

File: shared/schema.ts
ORM: Drizzle (PostgreSQL adapter)

Task:
Locate:

export const trades = pgTable("trades", { ... })
export const paper_sim_trades = pgTable("paper_sim_trades", { ... })


Add the following fields to both tables:

signalType: text("signal_type").default('QUANT').notNull(),
patternType: text("pattern_type"),
patternStrength: real("pattern_strength"),


Also:
Ensure the inferred types (InsertTrade, Trade) correctly reflect these new fields.

✅ Example:

export type InsertTrade = typeof trades.$inferInsert;
export type Trade = typeof trades.$inferSelect;


If necessary, regenerate them after the column additions so TypeScript infers signalType, patternType, and patternStrength automatically.

2. UPDATE TYPES

File: server/types.ts

Ensure TradeSignal interface includes:

export interface TradeSignal {
  // existing fields…
  signalType?: SignalType;          // 'QUANT' | 'PATTERN' | 'HYBRID'
  patternType?: PatternType;        // optional: pattern category
  patternStrength?: number;         // 0.0–1.0 clarity rating
}


Confirm SignalType and PatternType are already defined from Directive 10.2.

3. UPDATE STORAGE LAYER

File: server/storage.ts

Locate:

createTrade() (live)

createPaperTrade() (paper)

Modify input interface:

async function createTrade(data: {
  symbol: string;
  entryPrice: number;
  exitPrice: number;
  qty: number;
  signalType?: SignalType;
  patternType?: PatternType;
  patternStrength?: number;
  ...
})


Update the Drizzle insert logic:

await db.insert(trades).values({
  symbol: data.symbol,
  entry_price: data.entryPrice,
  exit_price: data.exitPrice,
  qty: data.qty,
  signal_type: data.signalType ?? 'QUANT',
  pattern_type: data.patternType ?? null,
  pattern_strength: data.patternStrength ?? null,
  ...
});


Repeat for createPaperTrade() using paper_sim_trades.

✅ Backward Compatibility:
If signalType is missing, automatically default to 'QUANT'.

4. UPDATE EXECUTION ENGINES

Files:

server/services/trading-engine.ts

server/services/paper-execution-engine.ts

Locate functions such as executeTrade() or createTradeRecord().

Extract fields from incoming signal objects:

const { signalType, patternType, patternStrength } = tradeSignal;


Pass them forward to the storage function:

await storage.createTrade({
  ...tradeData,
  signalType,
  patternType,
  patternStrength,
});


Log confirmation for runtime traceability:

console.log(`[10.3] Trade Executed: ${symbol} | Type=${signalType} | Pattern=${patternType || 'N/A'}`);


This ensures visual verification during live and paper-mode operation.
