🧭 Directive 11.7R — Regime Transition Governance & Strategy Influence Control

Phase: 11
Series: Predictive Stability & Risk Governance
Dependencies: 11.7B–11.7F
Applies To: VTS · Paper Trading · Live Trading
Status: Mandatory before paper trading resumes

1. Purpose

Introduce a deterministic governance layer that protects the system during regime transitions by:

Reducing influence of regime-fragile strategies

Preventing learning amplification during instability

Preserving all data collection for learning and diagnostics

Governance constrains influence, not data collection.

2. Correct Execution Order (MANDATORY)

Governance must not run on raw signal noise.

Required order (repo-accurate):

Signal generated

Regime detected

Global regime stability classified

Core deterministic filters

ROI / EV

Duplicate / cooldown

Governance applied

Scoring & ranking

Execution or skip

Learning attribution

Governance must execute after profitability filters and before scoring / execution.

➕ ADDITION — Stability Evaluation Cadence
Regime stability MUST be computed once per scan cycle and cached.
All signals processed within the same FX5 / VTS cycle MUST reference the same stability state to prevent intra-cycle thrashing.

3. Regime Stability Model
3.1 Stability States
type RegimeStability = "STABLE" | "TRANSITION" | "UNSTABLE";

3.2 Stability Thresholds (Authoritative)
Metric	STABLE	TRANSITION	UNSTABLE
DriftScore	≤ 0.8	0.8–1.5	> 1.5
VolZ	≤ 1.2	1.2–2.0	> 2.0
Regime Confidence	≥ 0.65	0.45–0.65	< 0.45
Regime Flip Rate (7d)	≤ 1	2–3	≥ 4
3.3 Classification Logic
if (driftScore > 1.5 || Math.abs(volZ) > 2.0 || flipRate >= 4 || confidence < 0.45)
  UNSTABLE;
else if (driftScore > 0.8 || Math.abs(volZ) > 1.2 || flipRate >= 2 || confidence < 0.65)
  TRANSITION;
else
  STABLE;

3.4 Regime Scope Resolution (MANDATORY)

Governance decisions MUST use:

Global regime → stability classification (authoritative)

Local (symbol) regime → compatibility checks only

Global instability ALWAYS overrides local alignment.

This prevents strategies from trading “locally correct” patterns during systemic collapse.

4. Strategy Governance Profiles
4.1 Dependency Levels
type StrategyDependency = "HIGH" | "MEDIUM" | "LOW";


Safety Default:
If governanceProfile is undefined → HIGH dependency (fail-safe).

4.2 Influence Rules
Stability	HIGH	MEDIUM	LOW
STABLE	100%	100%	100%
TRANSITION	30% weight	60% weight	100%
UNSTABLE	0% execution	20% weight	60% weight

➕ ADDITION — Weight Application Semantics (MANDATORY)
Governance weight reductions MUST be applied as a multiplier to the strategy’s contribution to the final signal score, after ROI / EV filters and before cross-signal ranking.

Governance MUST NOT:

Alter raw signal generation

Alter pattern detection

Alter feature calculation

Governance only constrains influence, not signal existence.

5. Governance Blocking Semantics (Explicit)
5.1 0% Execution Means

If a signal is blocked by governance:

❌ Must NOT be sent to:

VTS execution

Paper execution

Live execution

✅ Must be logged as:

{
  "resultType": "BLOCKED_GOVERNANCE",
  "reason": "UNSTABLE_REGIME"
}


✅ Must be forwarded to learning as a Skipped Signal
(Directive 11.7B)

This preserves learning context:

“Loss avoided due to instability.”

6. Learning Cooldown Enforcement
6.1 Cooldown Rules
Stability	Positive Reinforcement	Negative Learning
STABLE	Immediate	Immediate
TRANSITION	Batched (≥5 samples)	Immediate
UNSTABLE	Deferred & tagged	Immediate
6.2 Enforcement Location (MANDATORY)

File: /server/core/learning/learning-updater.ts

Requirements:

{

  "reason": "REGIME_INSTABILITY"

Deferred updates must be:

Stored

Replayable

Automatically applied when stability returns to STABLE
