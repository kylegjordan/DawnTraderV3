⚙️ Directive 11.4F.1 — Canonical Regime & Strategy Lock-In

Phase: 11.4F.1
Objective: Establish, enforce, and propagate the canonical regime–strategy–signal type–pattern mapping as the single source of truth across all DawnTrader systems.

I. Background & Purpose

Prior directives (11.4C through 11.4E) unified type definitions and naming conventions, but several subsystems—VTS, Signal Orchestrator, Telemetry Aggregator, and DSE—still infer regime and strategy logic locally.
This caused data mismatches, “fake hybrids,” and inconsistent signal labeling.

Directive 11.4F.1 corrects that permanently by:

Defining the canonical regime, strategy, and metric schema (truth model).

Building a single authoritative configuration file.

Removing all legacy or redundant local logic.

Auditing and enforcing usage across every system.

II. Implementation Tasks
Task 1 — Create Canonical Configuration File

File: /server/config/canonical-regime-strategy-map.ts

Action:
Create this file as the only authoritative definition of:

Regimes and regime metrics

Strategies and their secondary metrics

Signal type and pattern type associations

Valid regime–strategy mappings
