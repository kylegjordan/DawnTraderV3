2) Storage/service signatures: mechanical refactor

server/services/context-bridge.ts already has a context helper. Ensure we have:

// server/services/system-context.ts
import { storage } from '../storage';

export async function getSystemContextIdForMode(mode: 'paper'|'live') {
  const ctx = await storage.getSystemContext(mode); // existing helper or implement
  if (!ctx) throw new Error(`No system_context row for mode=${mode}`);
  return ctx.id;
}

2.2 Refactor pattern (apply to ~60 methods)

Before (example)

async function getScreenerFilters(userId: string, mode: 'paper'|'live') {
  return db.select().from(screenerFilters)
    .where(and(eq(screenerFilters.userId, userId), eq(screenerFilters.mode, mode)));
}


After

import { getSystemContextIdForMode } from './services/system-context';

async function getScreenerFilters(mode: 'paper'|'live') {
  const globalContextId = await getSystemContextIdForMode(mode);
  return db.select().from(screenerFilters)
    .where(and(eq(screenerFilters.mode, mode), eq(screenerFilters.globalContextId, globalContextId)));
}


Update ALL trading/paper/filters/goals/storage methods that currently take (userId, mode):

Change signature to (mode) (or { mode, ... }).

Replace eq(table.userId, userId) with eq(table.globalContextId, globalContextId) and eq(table.mode, mode).

Never pass userId into queries for Category-B tables.
