Phase: 11.7 | Category: Metric Calibration & Consistency

1 Objective

Eliminate the mathematically invalid returns-ratio VN formula used in passive learning mode and unify all Volatility Noise (VN) calculations under a single, validated function in analysis-utils.ts.
This ensures that both active trading and passive learning use the same canonical computation and thresholds, restoring data consistency to the predictive learning pipeline.

3 Implementation Tasks
H-01 Replace Flawed Formula in imf-metrics.ts

Old (flawed):

const returns = (currClose - prevClose) / prevClose;
const noiseRatio = stdDev(returns) / meanAbs(returns);


New (canonical):

// ⚠️ Verify exact export name in analysis-utils.ts before import
// Some codebases use `calculateVN` instead of `computeVolatilityNoise`
import { computeVolatilityNoise } from "@/server/utils/analysis-utils";

export function calculateVolNoise(cachedOHLC) {
  const closes = cachedOHLC.map(c => c.close);
  return computeVolatilityNoise(closes);
}


✅ Uses the price-difference method (stable, empirically validated).

H-02 Define Global Threshold and Align Imports
// system-guards.ts
export const MAX_VOL_NOISE = 0.8;


Remove local constants like VN_MAX or MAX_VOL_NOISE_LOCAL.

Import and use this shared constant in IMF, FX5, and DSS components.

H-03 Add VN Parity Test

/server/tests/unit/vn_parity.test.ts

import { computeVolatilityNoise } from "@/server/utils/analysis-utils";
import * as IMF from "@/server/core/metrics/imf-metrics";

test("IMF VN parity with analysis-utils", () => {
  const candles = [{close:100},{close:101},{close:102},{close:101.5}];
  const vnA = IMF.calculateVolNoise(candles);
  const vnB = computeVolatilityNoise(candles.map(c=>c.close));
  expect(vnA).toBeCloseTo(vnB, 2);
});


✅ Guarantees formula parity in all future updates.

H-04 Add Sanity Clamp in FX5 Scanner
if (VolNoise > 2 || VolNoise < 0) {
