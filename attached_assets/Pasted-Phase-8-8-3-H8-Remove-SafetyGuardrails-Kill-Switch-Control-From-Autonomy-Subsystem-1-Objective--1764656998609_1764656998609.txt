Phase 8.8.3-H8 — Remove SafetyGuardrails & Kill-Switch Control From Autonomy Subsystem
1. Objective

Fully remove SafetyGuardrails as a runtime component and strip AutonomyController of any ability to influence trading or kill the engine.

After this phase:

guardrails_v2.killSwitchTripped remains the single source of truth for kill switch.

trade-safety.ts + guardrail-settings.ts remain the only runtime risk / kill-switch enforcers for trading.

AutonomyController is preserved only as a non-blocking diagnostic/self-check module that cannot stop trading, now or in the future, unless explicitly re-wired in a later phase.

This phase must not introduce any new hidden filters, risk rules, or kill conditions.

2. Scope & Constraints

In scope

safety-guardrails.ts and its usage.

Kill-switch-related logic in:

autonomy-controller.ts

guardrail-policy.ts

Any other files that still call SafetyGuardrails or the legacy kill_switch table for runtime safety.

Logging and error behavior for autonomy/safety around kill-switch and policy hits.

Explicitly out of scope (document only, no changes)

decision_quality_audit schema and numeric overflow on accuracy_score.

Any future Walter / autonomy intelligence features beyond removing their ability to control trading.

Any changes to trade-safety.ts, guardrail-settings.ts, or the main trading pipeline other than deleting calls into SafetyGuardrails / legacy kill-switch.

If you find anything outside the defined scope that looks dangerous, document it clearly in the audit doc but do not modify it in this phase.

H8.3 – Strip Kill-Switch & Trading Control from AutonomyController

Goal: AutonomyController can observe and report, but never block or kill trades.

Open server/services/autonomy-controller.ts.

Identify ALL places where AutonomyController:

Checks a kill switch (directly or via SafetyGuardrails).

Returns a “blocked / denied / unsafe” outcome that could be hooked into trading.

References policyHits including "KILL_SWITCH" or similar semantics.

For each of these:

Convert blocking logic into diagnostic-only behavior:

Example transformation:

// BEFORE (hypothetical)
if (safetyResult.killSwitchActive) {
  logger.warn("[AutonomyController] Kill switch active - blocking action");
  return { allowed: false, reason: "KILL_SWITCH" };
}

// AFTER
if (safetyResult.killSwitchActive) {
  logger.warn("[8.8.3-H8][AutonomyController] Kill switch ACTIVE (diagnostic only)");
  // Do NOT block trading, do NOT influence guardrails.
  // Just log the situation for future Walter integrations.
}


Any allowed: false / “deny” return value that is not used anywhere can be simplified to “log + return diagnostic info”, not enforcement.

Ensure AutonomyController does not call any method that can mutate kill-switch state (no toggling, tripping, resetting).

In the H8 audit doc, add a short section:

“After H8, AutonomyController no longer participates in runtime enforcement. It is diagnostic-only.”
