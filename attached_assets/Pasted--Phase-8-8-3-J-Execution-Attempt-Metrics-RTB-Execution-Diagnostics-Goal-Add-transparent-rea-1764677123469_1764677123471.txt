J.2 – New Schema: Execution Attempt Audit Table

Create a lightweight, append-only table for execution diagnostics. You may name it, for example:

execution_attempt_audit

Define fields (adjust naming to fit existing conventions, but keep semantics):

id – primary key (UUID or serial)

created_at – timestamp with timezone

mode – paper | live

symbol – text (e.g., XDGUSD)

strategy – text (e.g., vwap_pullback, dhma, etc.)

signal_id – nullable text/UUID linking to RTB signal if available

decision – enum: OPENED | BLOCKED

block_reason – enum with a small, clear set of categories, for example:

GUARDRAIL_MAX_POSITIONS

GUARDRAIL_DAILY_LOSS_KILL_SWITCH

GUARDRAIL_RISK_PCT_TOO_HIGH

GUARDRAIL_MAX_POSITION_PCT

GUARDRAIL_COOLDOWN

LPCP_LOW_PRICE_OR_STOP_TOO_TIGHT

LPCP_MIN_NOTIONAL

DATA_NO_ENTRY_PRICE

DATA_NO_STOP_OR_TARGET

DATA_MISSING_CANDLES

DATA_INVALID_SPREAD

ENGINE_INTERNAL_ERROR

OTHER

block_detail – text or JSONB with a human-readable explanation (e.g., “Position size 364% > 30% cap ($3,000.00)”).

portfolio_value – numeric (snapshot at attempt time)

risk_amount – numeric (calculated risk per trade, if available)

Important: This table is strictly diagnostic. No code is allowed to read from it to make trading decisions.

J.4 – API: Read-Only Execution Metrics Endpoint

Add an internal API for the UI to query the new diagnostics, for example:

GET /api/trading-metrics/execution-attempts

Query parameters:

mode – required: paper | live

since – optional ISO timestamp (default: now − 24h)

limit – paging (e.g., default 100, max 500)

decision – optional filter: OPENED | BLOCKED

block_reason – optional filter

Response (example shape):

{
