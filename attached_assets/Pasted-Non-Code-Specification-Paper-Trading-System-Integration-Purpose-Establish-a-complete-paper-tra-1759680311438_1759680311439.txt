Non-Code Specification — Paper Trading System Integration
🎯 Purpose

Establish a complete paper trading environment that mirrors the live trading system in structure, behavior, and reporting — but is fully isolated in both data and analytics.

This allows you to test, tune, and optimize strategies safely before committing capital, while maintaining identical metrics, dashboards, and daily brief formats for clear side-by-side comparison.

1️⃣ Core Design Principles

Isolation of Data Streams

Paper and live trades must never share tables, identifiers, or calculation pipelines.

Each environment (live vs. paper) should maintain its own data store, metrics, and reports.

Identical Behavior

The paper system uses the same trading logic, strategies, and AI analysis pipelines.

Only data sources (prices, balances, execution handlers) differ.

Transparent Comparison

Metrics and briefings follow the same schema and visual format.

UI clearly labels each dataset: “Live Trading” or “Paper Trading.”

Safety First

Paper mode runs with no API calls capable of executing real orders.

It simulates fills, slippage, and latency deterministically.

2️⃣ Architecture Overview
Component	Live Trading	Paper Trading
Trade Execution Engine	Sends orders to exchange via Kraken API	Simulated fills using market data (no API calls)
Data Source	Real Kraken data stream	Same data feed (real prices)
Database Tables	trades, ai_reports, daily_briefs	paper_trades, ai_reports_paper, daily_briefs_paper
Risk Manager	Enforces real position sizing, stop-loss, limits	Uses same formulas, virtual balance
Scheduler / Brief Generator	Generates daily live brief	Generates daily paper brief
AI Analyst	Evaluates real trading results	Evaluates paper results separately
Dashboard UI	Displays live metrics	Displays paper metrics on a separate tab or toggle
Performance Analytics	Aggregates real trade data	Aggregates paper trade data separately
3️⃣ Data Model Adjustments
New Tables

paper_trades

ai_reports_paper

daily_briefs_paper

Each mirrors its live counterpart, with identical columns (entry, exit, pnl, strategy_id, timestamp, etc.).

Key Identifiers

All paper-related data should include:

is_paper = true flag (or stored in dedicated tables)

Unique sequence IDs (no overlap with live trade IDs)

Link to strategy and settings snapshot for backtesting reference

4️⃣ Execution Flow
Paper Trade Lifecycle

Signal Generation

Strategies generate buy/sell signals as usual.

These signals are routed to the Paper Execution Engine.

Simulated Execution

Paper engine “executes” trades at current market prices.

Supports configurable slippage (e.g., ±0.05–0.2%) and simulated latency (e.g., 200–500ms).

Data Recording

All trades recorded in paper_trades table.

PnL, R-multiple, drawdowns calculated using same risk engine.

Metrics & Reporting

At end of day (23:59 UTC), the system:

Finalizes all open paper trades

Calculates paper portfolio performance

Generates Daily Paper Trading Briefing

Analysis & Feedback

The AI Analyst processes paper trading data through the same GPT-4o pipelines, producing narrative insights and recommendations tagged as simulated results.

5️⃣ Daily Paper Trading Briefing

7️⃣ Strategy Testing & Optimization Workflow

Run strategies in paper mode for N days.

Review Daily Paper Briefings for performance trends.

Adjust variables (stop-loss %, entry filters, take-profit rules).

Validate improvements over rolling 7-day ADE.

Promote optimized strategy to live mode once consistent profitability achieved.
