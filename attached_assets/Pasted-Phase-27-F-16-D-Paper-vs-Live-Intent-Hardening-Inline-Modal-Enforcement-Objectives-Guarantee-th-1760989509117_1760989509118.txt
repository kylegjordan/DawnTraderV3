Guarantee that prompts containing “paper”, “simulation”, “simulated”, “demo”, or “practice” are routed to paper (and never to live).

Enforce inline modals for live start/stop (no notification-only fallback).

Add trace logging so we can see what intent the parser chose and why.

2) Parser precedence (PAPER must win)

Add hard override rules:

If message contains any of: paper|simulation|simulated|demo|practice → intent=start_paper_sim even if “live” is present.

If message contains stop and paper is active → intent=stop_paper_sim.

Use word-boundary regex and case-insensitive matching to avoid substring traps (e.g., “lives”, “delivery”).
