Phase 8.8.3-H11 — Autonomy / Walter / Safety Isolation Verification (Diagnostic-Only)
Objective

Verify that all Autonomy / Walter / Safety subsystems are:

Fully isolated from the live trading pipeline (FX5 → Active Filter Pool → Ready-to-Buy → Guardrails → Trade Execution).

Not able to:

Trip or reset any kill switch.

Change guardrails or portfolio settings.

Block or alter trades directly or indirectly.

Safe to keep in place as dormant/observability-only components while DawnTrader V3 continues toward the future-state blueprint.

This phase is diagnostic-only.
No behavioral changes may be introduced to the trading engine, guardrails, or autonomy/Walter logic in this phase.

Hard Constraints (Do NOT violate these)

No new legacy re-enablement

DO NOT re-enable any legacy system (RiskManager, V1 kill switch paths, old safety pipelines, etc.).

DO NOT rewire anything to go through risk-manager.ts.

No functional behavior changes

You may not change how trades are accepted/rejected, how kill switches behave, or how guardrails block trades.

You may not add or change any database columns, enums, tables, or constraints.

You may not change any function signatures used by the trading engine, guardrails, or RTB pipeline.

Code edits allowed only for:

Adding narrowly-scoped diagnostic logging (with a clear [8.8.3-H11] prefix) if and only if existing logs are insufficient.

Adding comments or updating the audit markdown.

No other changes.

If you discover anything that contradicts the future-state blueprint or user’s stated intentions (e.g., some hidden kill-switch path, or Walter affecting trades):

STOP immediately.

Do not “fix” it in this phase.

Document it in the audit file with file + function + line references.

Report it as a “blocking finding” for Kyle and the architect.

Do not change:

guardrails_v2 schema.

Kill switch behavior.

Guardrail thresholds or defaults.

Any strategy logic.

Any FX5 filter logic.

Any Ready-to-Buy lifecycle logic.
