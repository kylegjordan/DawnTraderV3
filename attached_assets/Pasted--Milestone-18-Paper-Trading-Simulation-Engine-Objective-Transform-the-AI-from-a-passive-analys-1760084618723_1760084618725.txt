⚙️ Milestone 18 – Paper-Trading Simulation Engine

Objective:
Transform the AI from a passive analyst into an active simulated trader — capable of executing, tracking, and learning from paper (virtual) trades in real time — without any connection to live funds or exchanges.

🧩 1. Architecture Overview

The Paper-Trading Simulation Engine (PTSE) sits between the strategy signal generators and the learning layer (CLE + CWA + Semantic Memory).

Market Data → Strategy Engine → PTSE → Portfolio Ledger → Learning Feedback
                                     ↓
                               AI Transparency Panel


Purpose:
Provide a continuous “real-world rehearsal” loop using current market data so the AI can validate and refine strategies before live deployment.

🔧 2. Core Components to Implement
2.1 Paper Trading Ledger (Database Layer)

Create three new tables:

Table	Key Fields	Purpose
paper_trades	trade_id, symbol, side, entry_price, exit_price, qty, pnl, opened_at, closed_at	Historical record of closed trades
open_positions	position_id, symbol, qty, avg_price, stop_loss, take_profit, opened_at	Track currently active positions
trade_logs	log_id, timestamp, trade_id, message, event_type	Chronological event log for transparency

All tables include user_id and strategy_name for multi-user and per-strategy traceability.

2.2 Execution Engine (Core Service)

File: server/services/paper-execution-engine.ts

Responsibilities:

Subscribe to live Kraken OHLC or ticker stream (same data feed used in backfill).

For each tick/candle:

Query active strategies for signals (buy, sell, hold).

Execute simulated trades according to signal type.

Apply order-fill logic:

Immediate fill at current price ± configurable slippage.

Simulated fee (e.g., 0.1 % per trade).

Update ledger tables accordingly.

Safety:

All trades are stored locally; no external API calls for execution.

No private keys, no order placement, no network calls to brokers.

2.3 Portfolio Manager (Risk & Guardrails Integration)

File: server/services/paper-portfolio-manager.ts

Handles:

Position sizing using Milestone 17B rules (fractional vs. whole-unit logic).

Portfolio constraints:

max_positions

max_drawdown

max_position_size

daily_loss_limit

Automatic position closure when guardrails breached.

Logs guardrail events to the Transparency Panel.

2.4 Learning Feedback Hooks

Each simulated trade outcome (pnl, duration, accuracy) → logged as PredictionOutcome event.

CLE (Confidence Learning Engine) consumes these outcomes.

CWA (Cognitive Weight Adjuster) adjusts source weights for:

strategy_engine

semantic_memory

paper_trading_feedback

Results appear in Learning Health tab metrics automatically.

2.5 Transparency Integration (UI)

Add new “Paper Trading” tab in AI Transparency Panel:

Metrics displayed:

Active positions

Closed trades (count)

Total P/L (daily, weekly, cumulative)

Win rate %

Average return per trade

Strategy performance comparison (bar chart)

Guardrail trigger count

Last execution timestamp

Each trade expands to show entry/exit, reason (from signal note), and confidence score.

🧠 3. Simulation Logic
Step	Description
1	Load strategy signals for each symbol
2	If buy signal & no position → open simulated position
3	If sell signal & position exists → close simulated position
4	Update ledger + Transparency Panel
5	Send trade outcome to Learning Feedback queue
6	Continue loop every candle/interval

Timeframe: hourly (default) but configurable.

🧰 4. Configuration Parameters

Add to .env or config constants:

Variable	Default	Description
PAPER_TRADING_ENABLED	true	Enables simulation engine
PAPER_TRADING_INTERVAL_MIN	60	Candle interval
MAX_OPEN_POSITIONS	10	Portfolio guardrail
MAX_BATCH_TRADES_PER_HOUR	50	Safety throttle
TRADE_FEE_RATE	0.001	0.1 %
SLIPPAGE_BPS	10	0.1 % slippage
LEARNING_FEEDBACK_ENABLED	true	Sends outcomes to CLE/CWA
🔒 5. Safety Controls (Simulation-Only Enforcement)

Route separation:
All trading endpoints under /api/paper/ namespace.
No route ever calls external trade APIs.

Environment enforcement:
Paper trading starts only when NODE_ENV !== 'production' or ALLOW_LIVE_TRADING = false.

Verification middleware:
On startup, check:

if (process.env.PAPER_TRADING_ENABLED && !process.env.ALLOW_LIVE_TRADING)
    console.log("✅ Paper trading mode active, live trading disabled");


Fail-safe lock:
If any call attempts to reach an external broker API → system throws and logs a “Live Execution Blocked” event.
