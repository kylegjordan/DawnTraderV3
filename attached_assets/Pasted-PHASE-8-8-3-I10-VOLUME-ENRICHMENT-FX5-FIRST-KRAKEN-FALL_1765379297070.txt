PHASE 8.8.3-I10 — VOLUME ENRICHMENT (FX5- FIRST, KRAKEN FALLBACK)

Directive to Replit

Purpose

Fix the $0 volume problem and stabilize trade volume data by persisting FX5 volume at trade creation, providing UI buckets, and adding a caching fallback for Kraken volume without increasing REST load.

1. REQUIREMENTS SUMMARY (IMPLEMENT ALL OF THIS)
1.1 Use FX5 volume as the authoritative source at trade creation

When a trade is executed from Ready-to-Buy → createPaperSimOpenPosition:

Read the FX5 scan metadata attached to the signal

Extract:

volume_24h

liquidity (if available)

Persist these values into the new open-position record.

1.2 Persist in DB (no async fetching needed per UI refresh)

In the paper_sim_open_positions table, add:

volume_24h (numeric)

volume_bucket (string, one of: "High" | "Medium" | "Low" | "Very Low")

Use the same bucket system as Active Filter Insights.

1.3 Populate volume in backend API responses

Modify:

/api/paper-sim/active-trades

/api/paper-sim/trade-history

to include:

volume_24h
volume_bucket


in each returned position.

1.4 Add 5-min cached fallback when FX5 volume is missing

Implement a lightweight fallback in a new in-memory module:

krakenVolumeCache.ts


Functionality:

TTL: 5 minutes

Key: canonical symbol (BTC/USD)

Value: { volume_24h, timestamp }

If FX5 volume missing →

check cache

else fetch Kraken REST /0/public/Ticker once

store result

DO NOT fetch again until TTL expires

This avoids REST flooding and ensures all trades have volume.

1.5 UI Volume Column

The Active Trades tab must show:

VOLUME
$37K  (High)
$540  (Low)
$0    (Very Low)


Format:

$ prefix

Thousands separators

K/M abbreviations for large numbers

Bucket label under the value (same style as CONF column)

1.6 No Per-Tick Volume Fetching

Volume must NOT:

refresh per WebSocket tick

refresh per position evaluation cycle

cause new REST calls during live trading

Volume changes slowly; we only update:

when trade is created

or manually via cache fallback (5 min TTL)

1.7 No UI Blocking

Volume computation must never block the Active Trades render path.
