## 🔍 Context

Phase 8.8.4 strengthens Dawn Trader’s trading intelligence by transforming the system from a reactive, first-come-first-served trade executor into an informed, ranked opportunity manager.  
The problem this phase addresses is that high-quality trading signals are currently being lost or instantly executed without proper evaluation due to the absence of a unified signal-tracking and audit mechanism.  
Directive 8.8.4-A establishes that diagnostic foundation — creating complete visibility of the signal lifecycle so subsequent directives can build the Ready-to-Buy queue, ranking system, and re-evaluation logic.

## 🎯 Objective

Instrument every stage of the trading-signal lifecycle so that each decision taken by the engine is:
1. Recorded with full contextual data,  
2. Traceable from origin → decision → outcome, and  
3. Accessible for later analysis and queue-ranking logic.

This directive produces the canonical **Signal Lifecycle Audit Layer (SLAL).**

---

## 🧩 Scope of Instrumentation

| Stage | Module / Layer | Required Output |
|--------|----------------|-----------------|
| **1** | Strategy Engines | Raw Signal object emitted with: `pair`, `strategy`, `timestamp`, `confidence`, `entry`, `target`, `stop`, `risk`, `indicators`, `rawScore` |
| **2** | Guardrail Evaluation | For each guardrail applied, record: `name`, `type` (Quality or Capacity), `result` (pass/fail), `threshold`, `reasonCode` |
| **3** | Portfolio Assessment | Capture `availableExposure%`, `openSlots`, `usedCapital`, `maxTradeLimit` at the moment of decision |
| **4** | Decision Node | Record `decisionOutcome` (`OPENED`, `QUEUED`, `BLOCKED`, `EXPIRED`) + `sourceReason` |
| **5** | Execution Result | For OPENED trades, store link to trade ID and execution metrics (`qty`, `price`, `slippage`, `fee`) |
| **6** | Lifecycle Events | Record `refresh`, `re-evaluation`, and `expiry` events with timestamp and status. |

Each signal must carry a persistent UUID through all stages.

## 🧠 Implementation Instructions

### 1. Create Audit Data Structure

- **File:** `/core/audit/signal_lifecycle_audit.ts`  
- Define TypeScript interface `SignalAuditRecord` with all fields above.  
- Initialize `SignalAuditLog` as append-only in-memory array with periodic flush to JSON or SQLite (`signal_audit_log.db`).  
- Ensure non-blocking writes to avoid latency in trade execution.

### 2. Insert Instrumentation Hooks

Insert logging calls at the following points:

1. `/core/strategyEngine.ts` → after signal generation.  
2. `/core/guardrails/index.ts` → around each guardrail evaluation.  
3. `/core/portfolioManager.ts` → before capacity checks.  
4. `/core/tradeManager.ts` → at decision node (open / block / queue).  
5. `/core/lifecycleManager.ts` → during refresh and expiry events.

Use the shared utility:

logSignalEvent(eventType, signalUUID, payload);
