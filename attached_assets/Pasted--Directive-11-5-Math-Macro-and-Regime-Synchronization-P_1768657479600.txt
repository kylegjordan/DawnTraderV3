⚙️ Directive 11.5 — “Math, Macro, and Regime Synchronization”

Phase: 11.5
Objective:
Stabilize DawnTrader’s mathematical framework across passive and active trading by:

Normalizing regime calculations dynamically (Z-Scores).

Making secondary metric thresholds adaptive to macro market conditions.

Enforcing pre-trade profitability validation.

Ensuring consistent canonical use across VTS and DSS.

Respecting benchmark/stablecoin inclusion rules while avoiding false trades.

🧩 I. CORE GOALS

Dynamic Regime Normalization:
All regime classifications use rolling statistical normalization (Z-Scores), not fixed cutoffs.

Macro-Aware Secondary Metrics:
Secondary metric ranges (momentum, volatility, liquidity, friction) adjust based on global market condition indices (“Macro States”).

Profitability Validation (Net Expectancy Gate):
No simulated or live trade proceeds if projected profit ≤ trading cost.

Filter Integrity & Blue-Chip Respect:
Stablecoins and blue chips are always scanned but only tradable when passing filters.

Canonical Consistency:
The same normalized regime and secondary metric logic is used by both VTS (passive) and DSS (active) systems.

export function isMathematicallyProfitable(entry, target, spread, slippage, fee) {
  const grossProfit = Math.abs(target - entry);
  const totalCost = (fee * 2) + (spread * 1.1) + slippage;
  return grossProfit > totalCost;
}


In vts-runner.ts (before trade simulation):

   continue; // skip trade simulation
}

Task 2 — Rolling Z-Score Normalization for Regimes

Purpose:
Replace static regime thresholds with rolling, adaptive normalization.

Insert near top of file:

import { RollingStats } from '@/utils/rolling-stats';

// Rolling windows for last 300 periods
const rollingStats = {
  ADX: new RollingStats(300),
  VOL: new RollingStats(300),
  MOM: new RollingStats(300)
};

export function getNormalizedRegime(metrics) {
  const { adx, vol, momentum } = metrics;

  rollingStats.ADX.push(adx);
  rollingStats.VOL.push(vol);
  rollingStats.MOM.push(momentum);

  const adxZ = (adx - rollingStats.ADX.mean()) / (rollingStats.ADX.std() || 1);
  const volZ = (vol - rollingStats.VOL.mean()) / (rollingStats.VOL.std() || 1);
  const momZ = (momentum - rollingStats.MOM.mean()) / (rollingStats.MOM.std() || 1);

  if (volZ > 1 && adxZ > 0.5) return 'BULL_VOLATILE';
  if (volZ > 0.5 && adxZ > 0.2) return 'BULL_STABLE';
  if (volZ < -0.5 && adxZ > 0) return 'LOW_VOL_CHOP';
  if (adxZ < -0.5 && momZ < 0) return 'BEAR_STABLE';
  return 'BEAR_VOLATILE';
}


In vts-runner.ts and dss/strategy-selector.ts, replace:

const regime = calculateRegimeScore(metrics);


With:

import { getNormalizedRegime } from '@/core/metrics/market-regime';
const regime = getNormalizedRegime(metrics);


✅ Result: Regime labeling adapts automatically to current volatility/momentum levels across both passive and active systems.

export function getGlobalMacroCondition(globalStats) {
  const { avgVolatilityZ, liquidityZ, correlationZ } = globalStats;

  if (avgVolatilityZ > 2) return 'VOLATILITY_EXPANSION';
  if (liquidityZ < -1) return 'LIQUIDITY_CRUNCH';
  if (correlationZ > 1.5) return 'SPECULATIVE_SURGE';
  return 'NORMAL';
}


Modify secondary-metrics.ts:

export function adjustMetricRanges(baseRanges, globalStats) {
  const condition = getGlobalMacroCondition(globalStats);

  switch (condition) {
    case 'VOLATILITY_EXPANSION':
      baseRanges.VOL_HIGH *= 1.25;
      baseRanges.MOM_HIGH *= 1.1;
      break;
    case 'LIQUIDITY_CRUNCH':
      baseRanges.LQ_MIN += 10;
      break;
    case 'SPECULATIVE_SURGE':
      baseRanges.ADX_MIN += 10;
      baseRanges.VOL_HIGH *= 0.9;
      break;
  }

  return baseRanges;
}

✅ Result: Secondary metrics (momentum, volatility, liquidity) now auto-adjust to global market “moods” — calm, panic, or mania.

Task 6 — Range Trade Performance Audit

File: /server/core/strategy-analyzer.ts

Purpose:
Before disabling any strategy (like Range Trade), audit its performance in each regime to determine whether failure is due to mapping or math.

Add function:

export function auditStrategyPerformance(results) {
  const grouped = groupBy(results, 'strategy');
  for (const [strategy, trades] of Object.entries(grouped)) {
    const winRate = trades.filter(t => t.NetProfit > 0).length / trades.length;
    log(`[11.5][Audit] ${strategy} Win Rate: ${(winRate * 100).toFixed(2)}%`);
  }
}


Run post-simulation:

auditStrategyPerformance(VTS_RESULTS);


✅ Result: Range Trade stays enabled until data confirms underperformance across correctly classified regimes.
