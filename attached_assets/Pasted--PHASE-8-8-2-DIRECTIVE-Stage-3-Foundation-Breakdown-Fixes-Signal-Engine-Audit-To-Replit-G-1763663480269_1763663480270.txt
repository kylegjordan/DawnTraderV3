🔶 8.8.2A — Build Stage-3 Foundation Layer
🧩 1. Create server/services/stage3-state-cache.ts

This module will hold per-mode real-time state:

Required fields:
{
  cycleId: string,
  completedAt: string,      // ISO timestamp
  evaluatedCount: number,
  eligibleCount: number,
  ineligibleCount: number,

  activePoolCount: number,  // from DB or trading engine
  topNCount: number,        // how many came from top-end tiers
  tierBCount: number,       // how many came from tier-B tiers

  rotation: {
    topEndUniverseSize: number,
    tierBUniverseSize: number,
  },

  // Optional but recommended:
  latestEligibleSymbols?: string[],
}

Requirements:

Must be in-memory

Must be per-mode (paper, live)

Must only be updated once per scan cycle

Must be the source of data for WebSocket events

🧩 2. Create server/services/stage3-emitter.ts

This module is responsible for:

A) Emitting scan_tick (lightweight)

Event: scan_tick
Send via contextBridge.broadcast({...})

Payload must include:

{
  type: 'scan_tick',
  payload: {
    mode,
    cycleId,
    completedAt,
    evaluatedCount,
    eligibleCount,
    ineligibleCount,
    activePoolCount,
    topNCount,
    tierBCount,
    rotation: {
      topEndUniverseSize,
      tierBUniverseSize
    }
  },
  mode
}

❗Important:

DO NOT include:

breakdown

full eligibleSymbols[]

large arrays

diagnostic data

B) Emitting scanner:breakdown:<mode> (heavy diagnostic)

Event name must be:

scanner:breakdown:paper
scanner:breakdown:live


Payload must include:

all breakdown keys (corrected schema)

evaluatedCount

eligibleCount

ineligibleCount

truthConstraintOk

🧩 3. Wire Scanner → Stage-3 Cache → Events

At the end of each scanner cycle:

Build new state object

Update Stage-3 Cache

Emit scan_tick

Emit scanner:breakdown:<mode>

Make sure:

Only one update per cycle

No duplicate events

No race conditions
