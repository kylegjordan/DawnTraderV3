⚙️ Directive 11.4F.1A — Canonical Enforcement & Validation Audit

Phase: 11.4F.1A
Objective:
To verify, enforce, and propagate the canonical regime–strategy–signal–pattern mapping across all systems; to confirm correct inclusion of hybrid–pattern pairings; to deprecate all legacy mappings; and to validate total backend–frontend consistency with zero UI workarounds.

I. Diagnostic Summary

Following the implementation of Directive 11.4F.1, initial validation indicates:

The canonical file was created successfully and referenced across multiple subsystems.

Backward compatibility was maintained unintentionally via regime-strategy-map.ts, which should have been deprecated.

UI displays (Top Batch, Analytics) reveal missing or inconsistent patternType fields, particularly for Hybrid strategies.

These issues may stem from:

Missing hybrid-to-pattern mappings in the canonical file, or

Partial propagation (middleware timing issue or incomplete mapping ingestion).

II. Task 1 — Confirm Canonical Hybrid–Pattern Mappings

Before further propagation, confirm inclusion integrity within /server/config/canonical-regime-strategy-map.ts.

Action:
Run the following check within Replit or any TypeScript runtime:

import { CANONICAL_REGIME_STRATEGY_MAP } from "@/server/config/canonical-regime-strategy-map";

for (const [regime, entries] of Object.entries(CANONICAL_REGIME_STRATEGY_MAP)) {
  for (const e of entries) {
    if (e.signalType === "HYBRID" && !e.patternType) {
      console.warn(`⚠️ Missing patternType for hybrid strategy: ${e.strategy} in ${regime}`);
    }
  }
}


Expected Output (no warnings):

✅ All hybrid strategies include a patternType.


If any hybrid strategy produces a warning, update the canonical file immediately to include:
