Phase 8.5 Addendum K.4.1 — Live Balance & Strategy Visibility Correction
🧭 Purpose

Ensure Walter AI, the dashboard, and the backend truth system always display accurate live-mode balances and strategies, even when the trading engine is stopped.
This eliminates false zeros, missing strategy lists, and dependency on in-memory engine objects.

Problem Summary

When the live trading engine is stopped, the in-memory tradingEngines map and engine caches are empty.
Walter’s prompt and the /api/trading/status endpoint still read from those runtime objects, not from the persistent database snapshot (portfolio_state + strategy_settings).
As a result, Walter shows:

“Live Mode: $0 (The trading engine is currently stopped)”

“Live Mode: No strategies enabled”

while the actual database has valid balances and 8 enabled strategies.

Objectives

Make live-mode balance and strategy data always come from the database, never from runtime engine memory.

Maintain correct engine-status reporting (running vs stopped) without hiding live data.

Synchronize all layers — Backend / Cortex / Walter — to use the same global truth.

Confirm parity through the System Truth Sync diagnostics panel.

Tasks Overview
1️⃣ Unify Live & Paper Data Retrieval

Modify the Context Refresh Coordinator so fetchDualModeData() always retrieves both live and paper records directly from:

portfolio_state (for balances, exposure, limits)

strategy_settings (for enabled strategies and parameters)

No conditional engine check — the database is always queried for both modes.

2️⃣ Rebuild Walter’s Prompt Assembly

Update the LIVE SYSTEM STATE block in Walter’s prompt to use the freshData.live snapshot instead of engine memory.

Always display:

Portfolio Balance

Enabled Strategies

Engine Status

If the engine is stopped, prepend “(Trading paused)” but still show balance + strategies.

3️⃣ Correct /api/trading/status Response

Ensure this endpoint now returns a dual-mode object where:

Both modes’ balances and strategies come from the database.

Engine status fields (engineActive) are checked separately using TradingEngine.isEngineRunning().

Add an internal metadata flag such as "source": "database" for verification.

4️⃣ Update System Truth Sync

Extend the diagnostic schema to verify:

liveBalanceBackend = liveBalanceCortex = liveBalanceWalter

liveStrategiesBackend = liveStrategiesCortex = liveStrategiesWalter

Trigger a low-severity alert if any layer diverges for longer than 30 seconds.

5️⃣ Validate Behavior

Stop both engines → Ask Walter:

“What’s my current portfolio balance and enabled strategies for live and paper modes?”

Expect:

PAPER Mode: $800 (8 strategies)
LIVE Mode: $834 (8 strategies, Trading paused)


Restart Live engine → Re-ask → should update to “Trading engine running” automatically.

Confirm System Truth Sync panel shows “All Layers Aligned ✓”.
