🚀 DIRECTIVE FOR REPLIT IMPLEMENTATION
Phase 8.8.3 – WebSocket Symbol Normalization & Hard Stop Trade Closure
(V3 Architecture Only – No Legacy, No Heuristics, No Drift)
0. CONTEXT (READ FIRST)

The DawnTrader V3 engine is currently:

Opening trades correctly

Running FX5 and generating RTB signals correctly

Starting the Kraken WebSocket connection correctly

…but:

WebSocket is only subscribing to a subset of symbols

E.g. FARTCOIN/EUR and TRX/USD, but not ADAUSD/ADAEUR/ADAAUD/ADAGBP etc.

This is caused by symbol format mismatches (slash vs no-slash).

Open trades are preserved across STOP, and then later auto-closed with Unknown reason

There is no proper Hard Stop routine that force-closes all open trades when the sim is stopped.

This causes ghost trades, slot starvation, and confusing history entries.

We are NOT trying to support “continue previous simulation” right now.

For this phase, we want:

STOP = Hard stop → force-close all open trades, clear state

Start Simulation = always clean slate (no continuation model)

All changes must:

Stay 100% within the V3 architecture

Avoid any use of legacy files or logic

Be stable, sustainable, and scalable

Align with the future-state blueprint and Phase 8.8.3 direction

1. NON-GOALS / HARD CONSTRAINTS

❌ Do NOT modify FX5’s core filtering/scanning logic or its 30-second cycle.

❌ Do NOT pull back any legacy execution, pricing, or paper sim code (no server/legacy/*).

❌ Do NOT fetch Kraken AssetPairs on every FX5 run.

❌ Do NOT add heuristic “auto-insert slashes” logic that guesses symbols.

❌ Do NOT introduce any continuation mode semantics in this phase.

2. ADD KRAKEN PAIR METADATA & SYMBOL NORMALIZATION SERVICE
2.1. Create a new service

Create a new file:

server/services/kraken-pair-metadata-service.ts

Implement a singleton service with responsibilities:

Fetch Kraken AssetPairs metadata at startup.

Build deterministic symbol maps:

internalToExchange: Map<string, string>

exchangeToInternal: Map<string, string>

Provide fast lookup helpers:

getCanonicalKrakenSymbol(internalSymbol: string): string | null

getInternalSymbol(krakenSymbol: string): string | null

Provide diagnostics:

getDiagnostics() returning:

list of known internal symbols

list of known kraken symbols

timestamps of last load / last refresh

error counters, if any

Implementation details:

Use Kraken REST endpoint: /0/public/AssetPairs (public, unauthenticated).

Fetch once on server startup.

Parse all tradeable pairs, and build:

interface KrakenPairInfo {
  wsname?: string;   // Prefer wsname if present
  altname: string;
}


For each pair:

Choose canonical symbol for WS usage:

Prefer wsname if present (e.g. "ADA/USD")

Otherwise fallback to altname if WS doesn’t use wsname (still canonical enough)

Map:

internalToExchange.set(altname, wsNameOrAlt);

Also support a simple uppercase normalization: internalToExchange.set(altname.toUpperCase(), wsNameOrAlt);

Do NOT do any “guessing” beyond those mappings.

If a symbol isn’t present in the Kraken response, treat it as unrecognized.

2.2. Add periodic refresh

Inside the service:

After initial load, schedule refresh:

const TWELVE_HOURS_MS = 12 * 60 * 60 * 1000;

setInterval(() => {
  // safely re-fetch AssetPairs and rebuild maps
}, TWELVE_HOURS_MS);


Make sure refresh:

Rebuilds maps atomically (swap reference, don’t mutate partially).

Logs errors if refresh fails, but does not crash the server.

2.3. Wire the service into server startup

Where the app initializes core services (main server bootstrap), ensure:

krakenPairMetadataService.loadAssetPairs() is called once on startup.

Trading/sim start must not depend on successful refresh; if initial fetch fails:

Log [SYM][PAIR_METADATA_LOAD_FAILED] with error details.

The system can still run, but any symbol normalization will fall back to unrecognized handling (see below).

5. HARD STOP: FORCE-CLOSE ALL OPEN TRADES ON STOP

We are not implementing continuation now.
STOP must behave as Hard Stop:

All open trades closed

All positions removed from open positions tables

UI Open/Active Trades tab becomes empty

History shows these trades closed with a clear reason

5.1. Add a force-close routine in paper-portfolio-manager.ts

In server/trading/paper-portfolio-manager.ts:

Add a new method:

public async forceCloseAllOpenPositionsOnStop(): Promise<void> {
  console.log('[DEBUG-B9][MANAGER_FORCE_CLOSE_ON_STOP][START]');
  const openPositions = await this.storage.getPaperSimOpenPositions(this.mode);

  if (!openPositions || openPositions.length === 0) {
    console.log('[DEBUG-B9][MANAGER_FORCE_CLOSE_ON_STOP][NO_OPEN_POSITIONS]');
    return;
  }

  for (const position of openPositions) {
    try {
      console.log('[DEBUG-B9][MANAGER_FORCE_CLOSE_ON_STOP][CLOSE_POSITION]', {
        positionId: position.id,
        symbol: position.symbol,
      });

      await this.executionEngine.closePosition(position.id, {
        type: 'manual_stop',
        reason: 'Manual stop requested by user',
      });
    } catch (err) {
      console.error('[ERROR][MANAGER_FORCE_CLOSE_ON_STOP][FAILED_TO_CLOSE]', {
        positionId: position.id,
        symbol: position.symbol,
        error: err instanceof Error ? err.message : String(err),
      });
    }
  }

  console.log('[DEBUG-B9][MANAGER_FORCE_CLOSE_ON_STOP][END]');
}


Constraints:

Use the existing V3 executionEngine.closePosition() logic.

Do not bypass the engine or manually manipulate DB rows.

Do not introduce any legacy close logic.

5.2. Wire force-close into paper-sim-service.ts stop flow

In server/services/paper-sim-service.ts, in the stop handler (paper sim stop):

After verifying existingSession and existingManager but before calling manager.stop():

console.log('[DEBUG-B9][PAPER_SIM_STOP][FORCE_CLOSE_ON_STOP]', {

5.3. Ensure clean state after stop

After manager.stop() and DB session status update, add a DB consistency check:

if (remainingOpenPositions.length > 0) {

This allows us to detect any cases where force-close failed.
