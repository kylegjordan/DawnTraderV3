1. FIX: Use KrakenPairMetadataService for incoming ticker symbols

File: server/services/kraken-websocket-adapter.ts

Problem:
handleTickerUpdate() currently derives normalizedSymbol via krakenToNormalSymbol(pair), which does dumb string manipulation and ignores the metadata registry:

const ticker = tickerData as KrakenTickerPayload;
const normalizedSymbol = this.krakenToNormalSymbol(pair);


This breaks pairs like XXRPZUSD / XXRPZEUR, causing:

Ticks to be stored under "XXRPZ/USD" or "XRP/USD"

Engine + UI to look up "XXRPZUSD" / "XXRPZEUR"

=> No live price updates for those positions.

Required changes:

Add a helper method in the adapter:

private mapKrakenPairToInternalSymbol(krakenPair: string): string | null {
  // First, ask KrakenPairMetadataService
  const internalFromMetadata = krakenPairMetadataService.getInternalSymbol(krakenPair);
  if (internalFromMetadata) {
    return internalFromMetadata;
  }

  // Fallback: existing krakenToNormalSymbol for logging / legacy safety
  const legacy = this.krakenToNormalSymbol(krakenPair);
  return legacy || null;
}


Update handleTickerUpdate to use this mapping:

const ticker = tickerData as KrakenTickerPayload;
const internalSymbol = this.mapKrakenPairToInternalSymbol(pair);

if (!internalSymbol) {
  console.warn(`[${this.MODULE_NAME}][TICKER][UNMAPPED_PAIR]`, { pair });
  return;
}


Replace all uses of normalizedSymbol in that method with internalSymbol:

Symbol key in symbolStats

Calls to livePricingAdapter.updateFromWebSocket(...)

Any logs referring to the symbol

Keep krakenToNormalSymbol ONLY as a fallback, not as the primary mapping.

Result:

Incoming WS ticks will be keyed by the same internal symbol used in:

paper_sim_open_positions

paper_sim_trades

execution engine / strategy engine

Positions like XXRPZUSD, XXRPZEUR, ADAUSD, etc. will finally receive their live prices correctly.
