🎯 Objective

Enable microphone-based voice input for both:

Goals Engine chat (/goals)

GPT Chats panel (/ai-chat or equivalent route)

When a user presses a mic icon:

Recording begins (toggle on/off with a single click).

On stop, the recorded audio is sent to the backend.

Backend uses Google Cloud Speech-to-Text to transcribe.

Transcription appears in the chat input area automatically (ready to send).

This matches ChatGPT’s “hold mic → transcribe → send or edit” experience.

🏗️ Section 1 — Architecture Overview
Layer	Purpose	Notes
Frontend (React)	Capture audio + display transcription	Add mic button and local recorder
Backend (Node.js + Firebase Function)	Receive audio, send to Google Cloud STT, return text	Secure endpoint using JWT
Google Cloud Speech-to-Text	Convert speech → text	Uses existing credentials in Firebase Functions
Chat Component	Integrate transcription into message input	Same flow as manual typing
🧱 Section 2 — Deliverables & Actionable Steps
Deliverable A — Add Mic Button to Chat UI

Goal: Show a mic icon beside the text input in both panels.

Actions:

In the ChatInput.tsx (or similar) component:

Add a mic icon (lucide-react’s Mic or MicOff).

Use state: isRecording to toggle recording.

Style: small circular button aligned right in the input bar.

Check:
✅ Mic icon toggles on/off visually.
✅ No errors appear on toggle.

Deliverable B — Integrate Audio Recorder Hook

Goal: Record short audio clips locally in browser.

Actions:

Create useAudioRecorder.ts hook.

Use browser MediaRecorder API:

navigator.mediaDevices.getUserMedia({ audio: true })


On stop, the blob is passed to a function:

uploadAudioForTranscription(blob);


Check:
✅ Recording starts/stops with mic button.
✅ Console log shows “Audio blob ready (size: X bytes)”.

Deliverable C — Backend Route for Transcription

Goal: Send the audio blob → Firebase Function → Google Cloud STT.

Actions:

Create Firebase Function: /transcribeAudio.

Input: audio file (base64 or blob)

Use Google Cloud SDK:

const [response] = await client.recognize({
  audio: { content: audioBytes },
  config: {
    encoding: 'WEBM_OPUS',
    languageCode: 'en-US',
  },
});


Return transcription text to frontend.

Update server/routes.ts:

router.post('/api/transcribe', verifyJWT, handleTranscription);


Frontend call:

const res = await apiRequest('/api/transcribe', {
  method: 'POST',
  body: audioBlob,
});
setInputText(res.text);


Check:
✅ /api/transcribe responds within 2–3s for <30s clips.
✅ Returns { text: "recognized speech" }.

Deliverable D — Display Transcription in Chat Input

Goal: Inject transcription result into input box for review/edit before sending.

Actions:

Update chat input component to accept external updates:

setInputText(transcribedText);


Optionally auto-send on success:

Configurable: autoSendTranscription: boolean in user settings.

Check:
✅ After mic stops, transcription appears in text field.
✅ Editable before sending.
✅ Works identically in both /goals and /ai-chat.

Deliverable E — Security & Stability Validation

Goal: Ensure privacy and consistent function.

Actions:

Verify JWT middleware protects /api/transcribe.

Set upload limit (e.g., max 15 MB).

Catch edge cases:

No mic permission → show “Enable microphone access.”

Transcription fails → toast “Couldn’t transcribe audio.”

Check:
✅ Unauthorized users cannot call /api/transcribe.
✅ Friendly error for denied mic permissions.
✅ No console or network errors.
