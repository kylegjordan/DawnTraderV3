2. Numeric Formatting – Manual Mode (Commas After Save)
2.1 Current Behavior (What you should observe before changes)

From the current build:

When Managed by LATTi = checked (overrideDisabled):

Inputs are disabled (read-only).

Numbers are shown with comma separators (e.g. 5,000).

When Managed by LATTi = unchecked (manual override ON):

User can type into the input (this is already fixed).

Value is persisted via the PUT /api/filters-v2 call (toast confirms).

But after save/refresh, the manual value still shows without commas (e.g. 5000).

We want the manual override path to display formatted numbers after edit/save, just like the LATTi-managed path, without interfering with typing UX.

2.2 Target Behavior

For numeric filters (Min Volume, Max Liquidity, Min/Max Price, etc.):

While the user is actively typing, they should see a clean, raw numeric text field (no commas while typing).

On blur (and/or after successful mutation), the value should re-render with thousand separators, same as LATTi-managed values.

Internally, the stored value must remain a number everywhere (React state, React Query cache, API payload). Formatting is presentation only.

2.3 Implementation Requirements

In client/src/components/goals/filters-with-override.tsx:

Centralize formatting logic

If a helper already exists from previous work (e.g. formatThousands() or similar), reuse it.

If not, create a helper inside this file or a small local util:

const formatThousands = (value: number | null | undefined) => {
  if (value === null || value === undefined || Number.isNaN(value)) return '';
  return new Intl.NumberFormat('en-US', { maximumFractionDigits: 2 }).format(value);
};


Use this for both:

LATTi-managed display

Manual override display (after blur / after load)

Do NOT change the underlying state shape

Continue storing numeric values in state / React Query.

When parsing user input:

Strip commas and spaces, parse to number.

On invalid input, show validation error or revert to previous value (reuse existing logic).

Manual input behavior

When overrideEnabled = true (Managed by LATTi unchecked):

On onChange, treat input as “raw” text:

Strip commas only for parsing, but don’t re-insert commas while typing.

On onBlur:

If the current value is a valid number and mutation succeeded (you already have a mutation + onSuccess handler), render the formatted string using formatThousands(value).

You can implement this either via:

A per-field “isEditing” flag, or

Re-rendering from the numeric value on blur using formatThousands(value).

When overrideEnabled = false (LATTi-managed):

Continue to show disabled input with formatThousands(value) (current behavior).

Minimum History formatting

If minHistoryDays is numeric and already using a Select, it does not need comma formatting.

The formatting change only applies to numeric text inputs that represent amounts (volume, price, market cap, etc.).

Regression checks (local)

Confirm:

Toggle a filter to manual mode.

Type 5000 → blur → field shows 5,000.

Refresh page:

The value is still 5,000.

Backend still receives a bare numeric 5000 in the payload and in /api/filters-v2 response.
