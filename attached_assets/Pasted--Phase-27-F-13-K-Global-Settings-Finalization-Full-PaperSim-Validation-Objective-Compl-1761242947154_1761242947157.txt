## 🧩 Part 1 — Global Settings Finalization
### ✅ Goal
All configuration entities (`guardrails`, `screener_filters`, `strategy_settings`) must be **global per mode**, not user-specific.  
Values are shared between all users but isolated between `live` and `paper`.

### 1. Refactor Storage Layer
- Remove all `userId` and `globalContextId` parameters from these methods:
  - `getGuardrails`, `upsertGuardrails`
  - `getScreenerFilters`, `upsertScreenerFilters`
  - `getStrategySettings`, `upsertStrategySettings`
- New function signatures:
  ```ts
  getGuardrails(mode: 'live' | 'paper'): Promise<GuardrailConfig>;
  upsertGuardrails(mode: 'live' | 'paper', data: GuardrailConfig, lastUpdatedBy: string): Promise<void>;
  ```
- All lookups should use only:
  ```sql
  SELECT * FROM guardrails WHERE mode = $1 LIMIT 1;
  ```

### 2. Update API Routes & Services (82 Call Sites)
- Replace all calls passing `userId` or `globalContextId` with mode-based calls.
- Add `lastUpdatedBy` (from auth context) only for audit logging.
- Affected files include:
  - `/server/routes.ts`
  - `/server/storage.ts`
  - `/server/services/paper-sim-service.ts`
  - `/server/services/market-scanner.ts`
  - `/server/services/trading-engine.ts`
  - `/client/src/components/goals/*.tsx` (for fetch & save calls)
- Verify LSP (TypeScript) shows zero errors post-refactor.

### 3. Database Validation
Run SQL queries to confirm migration:
```sql
SELECT mode, COUNT(*) FROM guardrails GROUP BY mode;
SELECT mode, COUNT(*) FROM screener_filters GROUP BY mode;
SELECT mode, COUNT(*) FROM strategy_settings GROUP BY mode;
```
Expected:  
Each table → exactly 2 rows (one `live`, one `paper`).

### 4. Confirm Front-End Behavior
- Edit Paper values → save → navigate → return → values persist.
- Switch to Live → different values persist independently.
- Log out/in → same values remain (global).
- No `user_id` appears in network payloads or database logs.
