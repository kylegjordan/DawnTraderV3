B) Goals Engine – remove legacy card, keep performance tracking table

Remove the “Trading Goals Configuration” card (the 10 numeric inputs like Target Profit %, Max Drawdown %, etc.). That card should not render anywhere in Goals Engine.

Keep and surface the Performance-Tracking Goals table with columns Metric | Goals | Actuals | % Achieved for these rows:

Earnings per Trade

Average Return (%)

Grouped section (one input drives the set; others auto-calculate)

Earnings per Day

Earnings per Week

Earnings per Month

Earnings per Year

Editing behavior (group rule): When a user types into any one of Day/Week/Month/Year goals, auto-recompute the others using:

Week = Day × 5

Month = Week × 4

Year = Month × 12
(If Month is edited, recompute Week=Month/4, Day=Week/5, Year=Month×12; and similarly for Year edits.)

Actuals source (read-only values):

Earnings per Trade (Actuals): realized P/L ÷ count of closed trades over a recent rolling window (use the same period the app already uses for Goals/Briefs; if ambiguous, use last 30 days).

Average Return (Actuals): average % return per closed trade over the same window.

Earnings per Day/Week/Month/Year (Actuals): realized P/L aggregated over today / last 7 days / last 30 days / YTD respectively (or your existing periods if already standardized).

Respect mode isolation (Live vs Paper) in all fetches.

% Achieved = (Actuals ÷ Goals) × 100 (cap at 0–999% to avoid wild displays).

Keep the Save Goals and Reset to Defaults actions wired to the existing goals endpoints and persist per user + mode.
