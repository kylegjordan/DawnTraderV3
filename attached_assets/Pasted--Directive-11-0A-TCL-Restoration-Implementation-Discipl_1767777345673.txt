⚙️ Task 2 — Restore the Canonical TCL Behavior
The Trade Criteria Limiter (TCL) governs promotion of Ready-to-Buy (RTB) signals to open trades.
It is not a filter and not an evaluator.
It simply reacts to trade slot and queue events.
✅ TCL Should:
1.	Trigger conditions:
o	2-minute failsafe (onFailsafeTimer())
o	15-signal RTB accumulation (onReadyToBuyQueueFull())
2.	Monitor open trade slots:
o	If openSlots > 0, promote the highest-ranked RTB signals.
3.	Promotion logic:
4.	const openSlots = tradePool.maxOpen - tradePool.currentOpen;
5.	const eligibleSignals = rtbQueue.getTopRanked(openSlots);
6.	for (const signal of eligibleSignals) {
7.	    promoteToTrade(signal);
8.	}
9.	Post-promotion behavior:
o	Clear promoted signals from RTB.
o	Reset the failsafe timer.
o	Re-arm event listeners.
10.	Prohibited actions:
o	No exposure/correlation/cooldown checks.
o	No position sizing.
o	No prioritization beyond ranking.

🔧 Task 3 — Restrict TEC Responsibilities
The Trade Execution Controller (TEC) should:
✅ Handle only:
•	Trade entry execution.
•	Active trade monitoring.
•	Trendline exit-based adaptive trailing.
•	Stop-loss and take-profit closures.
🚫 Should NOT handle:
•	Initial position sizing (Phase 11.3 will implement predictive sizing).
•	Queue-based trade scheduling (FIFO logic).
•	Re-evaluation or re-ranking of signals.
TEC Example:
class TradeExecutionController {
  monitor(trade) {
    if (this.shouldExit(trade)) this.close(trade);
    else this.updateTrailingStop(trade);
  }

  shouldExit(trade) {
    return trade.price < trade.trailingStop || trade.price > trade.takeProfit;
  }
}
