Objective
Complete Phase 8.7.4 by wiring the frontend WebSocket clients to the Context Bridge so broadcasts reach both the Walter Panel and the Widget. Ensure scoped delivery (per-user), robust reconnection, and auditable delivery logs.

Tasks

Confirm WS Server Route & Auth

Verify the backend WS endpoint (e.g., ws://<host>/ws or wss://.../ws) is exposed.

Require JWT in the WS URL query or protocol header so the server can attach userId.
Example (client-side, conceptually): new WebSocket(${WS_BASE}/ws?token=${jwt})

On connection, the server should:

Validate token → resolve userId

Register client in Context Bridge registry: { userId, clientId, ts }

Log CONNECTED event to context_bridge_log

Frontend Client Hook (Panel + Widget)

Create/Update a shared hook/util (e.g., useContextBridgeWS) used by both chat UIs.

Behavior requirements:

Connect to /ws?token=<JWT> on mount

Send registration message on open (if your server expects one)

Listen for messages:

state_update → update state cache / UI

chat_update → append to chat or trigger local refresh

Implement client-side exponential backoff reconnect (1s, 2s, 4s, max 30s)

Heartbeat: ping every 25s, close on 3 missed pongs (server should respond to ping/pong)

Persist currentMode changes: ensure UI still calls PUT /api/settings so the server broadcasts.

Ensure User-Scoped Delivery

On server, deliveries must be filtered by userId:

contextBridge.broadcast({ userId, type, payload })

Success criteria for each broadcast:

totalTargets > 0

failureCount === 0

Only after all sends succeed → log DELIVERED with target count

Partial failures → log PARTIAL_FAILURE with per-target errors.

Add Server-Side Heartbeat & Cleanup

WS server should:

Reply to ping with pong

Mark client stale after ~60s no heartbeat

Hourly cleanup (already added) should remove stale clients and log CLEANUP_REMOVED

Broadcast Hooks Audit

Confirm broadcasts fire on:

PUT /api/settings (mode changes) ✅

config-change-handler (guardrails, goals, screeners) ✅

IntentExecutor after successful execution (start/stop engines, strategy update) ✅

StateAwarenessService.generateStateSnapshot() (optional: dedupe with a cooldown to avoid spam)

Security & Hardening

Reject WS connections without valid JWT; log AUTH_REJECT

Rate-limit reconnect attempts (cap at 30s backoff)

Prevent oversized messages (drop > 64KB payloads)

Sanitize outbound payloads (no secrets)

Tests

Open Panel + Widget in two browser tabs (same user).

Expect: context_bridge_log shows two CONNECTED entries with same userId and distinct clientIds.

B. Mode Switch Broadcast

Click PAPER ↔ LIVE.

Expect:

Server logs: SETTINGS_UPDATED, then BROADCAST SENT with totalTargets >= 2

Both UIs reflect mode in < 2s (no manual refresh)

context_bridge_log: DELIVERED, successCount >= 2

C. Intent Execution Broadcast

Start paper sim → stop paper sim.

Expect: status lights update on both UIs within < 2s; DELIVERED logs with successCount >= 2.

D. Config Change Broadcast

Update guardrail or goal.

Expect both UIs reflect counts/values live; DELIVERED log.

E. Disconnect & Reconnect

Close one tab; wait for cleanup (or shorten interval temporarily).

Expect: DISCONNECTED → later CLEANUP_REMOVED

Reopen tab: CONNECTED again; next broadcast shows totalTargets incremented.

F. Auth Failure

Attempt WS without token / with bad token.

Expect: server rejects; AUTH_REJECT log; client sees close event.
