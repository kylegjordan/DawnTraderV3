Paper Trading System — Implementation Plan (Non-Code)
1) Scope & Outcomes

Data isolation: Live and paper trading are fully separate (storage, APIs, UI).

Simulator fills: Orders filled using market data with configurable slippage/latency (no real exchange calls).

Daily Paper Briefing: Same format as live, clearly labeled “Paper”.

UI toggle: Seamless switch between Live and Paper views across dashboard, widgets, reports.

Identical analytics: Same metrics & visuals; distinct theme/labels prevent confusion.

2) Delivery Phases (safe sequence)
Phase A — Data & Services (isolated)

Storage

Add paper tables mirroring live (e.g., paper_trades, daily_briefs_paper, ai_reports_paper).

No reuse of live tables or ids; include is_paper=true only if Replit prefers a single table (otherwise keep separate tables).

Execution Simulator

New internal service that:

Consumes strategy signals.

Computes fills using current market price ± slippage (config) and optional latency (config).

Records fills to paper_trades.

Hard safety: zero calls to exchange order endpoints in paper mode.

Metrics Pipeline

Duplicate live aggregations for paper: P&L, win rate, ADE, drawdown, exposure, profit factor, equity curve.

Reuse existing calculation utilities; point them at paper data sources.

Daily Paper Brief Generator

Clone live briefing flow; source paper metrics and trades.

Same schema, labeled Daily Paper Trading Briefing.

Scheduled creation (00:01 UTC), updates (e.g., 30–60 min), finalize (23:59 UTC).

Phase B — APIs (clear separation)

Expose paper routes parallel to live:

Trading & positions

GET /api/paper/trades

GET /api/paper/positions

POST /api/paper/orders (simulation entry point)

Reports & briefs

GET /api/paper/briefs/today

GET /api/paper/briefs/:date

GET /api/paper/briefs?from=&to=

Metrics

GET /api/paper/metrics/summary (P&L, win rate, drawdown, ADE)

GET /api/paper/metrics/equity-curve

Admin/simulation controls (optional)

POST /api/paper/config (set slippage/latency)

POST /api/paper/reset (clear paper state for fresh tests)

Note: Keep request/response shapes identical to live equivalents where possible to minimize UI branching.

Phase C — UI Integration (safe & obvious)

Global toggle in dashboard header

Segmented control: Live | Paper.

Toggle controls a single app-level state (e.g., mode = 'live' | 'paper') that all widgets read.

Visual differentiation

Paper mode badge (e.g., “Simulated”).

Subtle blue accent color for paper sections.

Titles: “Current Paper Briefing”, “Paper Earnings”, etc.

Widgets & pages

Earnings Summary: pull paper endpoints when in paper mode (includes ADE + 7-day sparkline).

Daily Brief Card & Full Brief Page: show paper brief & historical navigation with labels.

Reports Panel: add a Paper tab mirroring live reports list & filters.

Phase D — Controls & Safety

Mode selection persistence: Remember last chosen mode per user (local storage or user profile).

Kill switch: App-level feature flag to disable paper execution if needed.

Audit note: Mark paper execution actions in logs as source=paper_sim.

3) Configuration (no new vendors needed)

ENV flags:

PAPER_MODE_ENABLED=true

PAPER_DEFAULT_SLIPPAGE_BPS=10 (0.10%)

PAPER_DEFAULT_LATENCY_MS=250

Scheduler: Reuse existing setInterval / UTC finalization pattern for briefs.
