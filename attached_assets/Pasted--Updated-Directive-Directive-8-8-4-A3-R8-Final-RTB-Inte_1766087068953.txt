2️⃣ RTB Status Lifecycle

Update schema and logic to support full four-state lifecycle:

Status	Trigger	Description
active	On insertion into RTBQ	Newly validated signal, pending first refresh
reconfirmed	On successful SQE revalidation	Signal remains valid, TTL reset
promoted	When promoted by TCL	Trade created; RTBQ cleanup required
expired	On SQE failure or TTL exceed	Signal invalidated, pending cleanup

Implementation details:

Modify shared/schema.ts ENUM.

In queueSQESignal() set status='active'.

In refreshAndRank(), if pass → status='reconfirmed'; if fail → status='expired'.

In TCL promotion handler → status='promoted' then remove from RTBQ after trade creation.

3️⃣ Immediate Expiry on SQE Failure

Remove the MISSED_REFRESH_THRESHOLD logic completely:

if (!sqePassed) {
  signal.status = 'expired';
  await storage.deleteRtbSignal(signal.id);
  continue;
}


✅ No “missed refresh” counter. Any failed reconfirmation → immediate expiry.
