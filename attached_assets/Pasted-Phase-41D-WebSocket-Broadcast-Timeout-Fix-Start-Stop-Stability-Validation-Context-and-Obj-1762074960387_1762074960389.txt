Phase 41D – WebSocket Broadcast Timeout Fix + Start/Stop Stability Validation


---

Context and Objective

RAPID,
during Phase 41C testing we identified that the /api/paper-sim/start endpoint successfully starts the trading engine but the HTTP request never returns because of a blocking call to:

await tradingStateSync.broadcastUserUpdate(userId);

This WebSocket broadcast attempts to notify connected clients that trading has started.
However, it awaits acknowledgments from all connected sockets, and if even one is slow or unresponsive, the entire HTTP transaction hangs.
That prevents the frontend from receiving confirmation, leaves the engine’s busy flag stuck, and causes subsequent “Engine is busy” errors.

The trading actually starts in the background, but the client times out — producing false negatives.

This phase’s goal is to:

1. Implement a non-blocking broadcast fix that decouples WebSocket updates from HTTP responses.


2. Guarantee proper cleanup (busyFlag, database session).


3. Validate stability through three full start/stop cycles of the paper-trading engine to confirm that the system behaves consistently.




---

🧩 Implementation Tasks


---

1️⃣ Modify the Broadcast Call

In server/routes.ts (within /api/paper-sim/start route handler):

Replace:

await tradingStateSync.broadcastUserUpdate(userId);

With the non-blocking version:

tradingStateSync.broadcastUserUpdate(userId)
  .then(() => console.log('[41D-FIX] Broadcast completed asynchronously'))
  .catch(err => console.warn('[41D-FIX] Broadcast error:', err.message));

👉 This ensures the HTTP response is sent immediately after engine initialization.
If the broadcast fails or stalls, it logs a warning but does not block the client.


---

2️⃣ Add Timeout Protection (Optional Enhancement)

If you wish to retain a bounded wait:

await Promise.race([
  tradingStateSync.broadcastUserUpdate(userId),
  new Promise((_, reject) =>
    setTimeout(() => reject(new Error('Broadcast timeout after 2 s')), 2000)
  )
]).catch(err => console.warn('[41D-FIX] Broadcast timeout or error:', err.message));


---

3️⃣ Ensure Busy-Flag and Session Cleanup

At the end of the same route, confirm there’s a final cleanup block:

finally {
  global.globalPaperSimBusyFlag = false;
  console.log('[41D-FIX] Busy flag cleared');
}

This guarantees proper reset even if the broadcast or database operation fails.


---

4️⃣ Add Diagnostic Logging

Insert explicit trace logs around the modified section:

console.log('[41D-FIX] Engine start completed, preparing HTTP response...');
console.log('[41D-FIX] Broadcast triggered asynchronously');
