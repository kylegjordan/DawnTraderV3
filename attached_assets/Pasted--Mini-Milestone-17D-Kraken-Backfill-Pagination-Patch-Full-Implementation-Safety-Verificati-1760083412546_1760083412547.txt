⚙️ Mini-Milestone 17D — Kraken Backfill Pagination Patch

(Full Implementation + Safety & Verification Checklist)

🎯 Objective

Upgrade the historic-signal generator to automatically fetch multi-month historical data from Kraken by paging through sequential OHLC requests.
This bypasses Kraken’s 720-candle limit and enables a single command to backfill up to 90 days of hourly data per symbol, seeding richer historical learning before paper trading begins.

🧩 Implementation Plan (Developer-Facing)
1️⃣ Modify getOHLCData() in server/services/kraken.ts

Add a pagination loop to request consecutive data batches:

Parse result.last from each Kraken response.

Continue requesting while:

candles.length >= 720 && last < end_timestamp


After each call, append new candles to the combined array.

Delay between calls: await delay(paginationDelayMs).

Example structure:

async getOHLCData(pair, interval, start, end) {
  let since = start;
  let allCandles = [];
  let batch = 1;

  while (since < end) {
    const res = await fetchKraken(pair, interval, since);
    const { candles, last } = parseKrakenResponse(res);
    if (!candles?.length) break;

    console.log(`[Backfill] Batch ${batch++}: ${candles.length} candles`);
    allCandles.push(...candles);

    if (candles.length < 720 || !last) break;
    since = last;
    await delay(500); // rate-limit protection
  }

  return allCandles;
}

5️⃣ Error Handling

Empty result → break loop, log warning.

HTTP 429 or 5xx → retry once after delay; if repeat failure, skip symbol gracefully.

Never throw uncaught exceptions during multi-batch runs.

6️⃣ Performance Safeguards

Use asynchronous delay() between requests (500–750 ms).

Auto-stop if:

Batch > 10, or

Total candles > 5000.

Cache complete data sets (24 h TTL) to avoid re-querying same date range.
