A) Database Layer → Performance Tracking

Create new table: goals_learning_metrics

CREATE TABLE goals_learning_metrics (
  id VARCHAR PRIMARY KEY DEFAULT gen_random_uuid(),
  mode trading_mode NOT NULL,
  date DATE NOT NULL DEFAULT CURRENT_DATE,
  avg_daily_return DECIMAL(6,3),
  avg_risk_per_trade DECIMAL(5,3),
  avg_drawdown DECIMAL(5,3),
  trades_count INT DEFAULT 0,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS goals_learning_mode_date_idx ON goals_learning_metrics(mode, date);


Purpose: record rolling 30-day averages per mode to assess performance vs preset ceilings.

Add SQL view: v_goals_learning_summary aggregating last 30 days per mode:

CREATE OR REPLACE VIEW v_goals_learning_summary AS
SELECT
  mode,
  ROUND(AVG(avg_daily_return),3) AS avg_daily_return_30d,
  ROUND(AVG(avg_risk_per_trade),3) AS avg_risk_per_trade_30d,
  ROUND(AVG(avg_drawdown),3) AS avg_drawdown_30d
FROM goals_learning_metrics
WHERE date >= CURRENT_DATE - INTERVAL '30 days'
GROUP BY mode;

B) Backend Service → GoalsLearningEngine

Create new file server/services/goals-learning-engine.ts that:

Reads v_goals_learning_summary + goals_presets.

For each preset, if avg_daily_return_30d ≥ 0.8 × preset target ceiling, expand preset range upward by 5 %.

Updates corresponding goals_presets values and emits telemetry event goals.learning.expanded.

Prevents expansion beyond a hardcoded global safety cap (e.g., risk ≤ 5 %, kill switch ≤ 20 %).

Runs once per day via cron or scheduled task.

Example pseudocode:

if (metrics.avg_daily_return_30d >= preset.target_daily_avg_earning_pct * 0.8)
  preset.portfolio_risk_per_trade_pct *= 1.05;
