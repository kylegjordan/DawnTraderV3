🧾 Directive 8.8.4-L4 — Adaptive Risk Advisor & SDPOE Integration

Directive ID: 8.8.4-L4
Title: Adaptive Risk Advisor (ARA) + SDPOE Reinforcement Integration
Phase: 8.8.4-L Series
Objective:
Introduce the Adaptive Risk Advisor UI and logic, integrate manual risk-optimization workflow, expose predictive metrics in RTB, and embed the SDPOE reward weighting into the ML microservice.

1️⃣ Implementation Scope
A. Adaptive Risk Advisor (ARA) UI – Goals Tab

Location: /ui/pages/goals/AdaptiveRiskAdvisor.vue (or equivalent React component)

Fields:

Field	Type	Behavior
Portfolio Value	Display (live from portfolio service)	Used in downstream calculations
Risk per Trade (%)	Input (editable, suggestable)	Used in calculations and recommendations
Max Exposure (%)	Input (editable, suggestable)	Used in calculations and recommendations
Number of Trades (derived)	Read-only	Calculated: floor((MaxExposure / RiskPerTrade))
Average Value per Trade	Read-only	Calculated: (PortfolioValue * RiskPerTrade) / 100
Estimated Gross Profit per Trade	Read-only	Derived from ML expected_profit prediction
Estimated Net Profit per Trade	Read-only	Gross minus projected fees/slippage

Buttons:

Apply Suggested Settings — Writes ARA’s suggested Risk % and Exposure % into the actual configuration fields.

Retrain Model — Initiates Python ML retraining (alerts if trading active, displays progress bar with real-time percentage).

B. Logic & Data Flow

Suggestions:

Generated from rolling average performance and ML model feedback.

Include recommended RiskPerTrade and MaxExposure.

Displayed but only applied on manual click.

Derived Calculations:

NumTrades = floor(MaxExposure / RiskPerTrade)

ValuePerTrade = (PortfolioValue * RiskPerTrade) / 100

Retraining Control:

Alert if trading is active (“Please stop trading before retraining.”).

On confirmation, sends POST /train to Python ML microservice.

UI progress bar updates from streaming JSON (phase, percent, eta).

On completion: “Retraining complete. Model vX.Y deployed.”

C. RTB Table Enhancement

Add two new columns:

Column	Source	Description
ML Confidence	From ML microservice	Probability that the signal is profitable
Final Rank	Calculated as (NGC × 0.4) + (CWQI × 0.3) + (MLConfidence × 0.3)	Used for trade ranking and TCL promotions

Behavior:

RTB cycles sort by FinalRank descending.

TCL only considers top-ranked signals for promotion.

D. SDPOE Reinforcement Integration (Python ML Microservice)

Add reward-weighted training logic:

reward = (profit_rate * 0.6) + (accuracy_delta * 0.3) + (stability_gain * 0.1)
weights = normalize(reward)
loss = np.sum(weights * (predictions - outcomes) ** 2)


Outcome:

Profitable / accurate samples influence future predictions more heavily.

Unprofitable conditions fade in weighting.

Model gradually self-optimizes toward stability and profitability.

2️⃣ Validation & Testing

Functional Tests:

✅ Manual “Apply Suggested Settings” updates live configuration safely.

✅ Derived trade counts and value calculations are accurate and real-time.

✅ Retraining button alerts if trading active and shows progress bar.

✅ RTB correctly sorts by FinalRank.

✅ ML microservice logs [SDPOE][REWARD_UPDATE] with weight adjustments.

Performance Targets:

Retraining runtime: < 10 min typical, < 60 min full dataset.

ARA UI update latency: < 100 ms on field input.

ML inference latency: < 15 ms per prediction.
