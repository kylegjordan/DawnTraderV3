H7.2 — Architectural Change: Make Guardrails v2 the Single Kill Switch Source

Goal: No service in the system should own its own kill-switch state apart from guardrails_v2. SafetyGuardrails can read/reflect that state, but not create a second truth.

Steps:

Update safety-guardrails.ts kill-switch logic

Locate all places it:

Reads kill_switch table

Writes to kill_switch table

Exposes getKillSwitchStatus, toggleKillSwitch, or similar.

Refactor:

Remove direct dependency on kill_switch table for runtime semantics.

Implement getKillSwitchStatus() as a thin view over guardrails_v2, e.g.:

// Pseudocode
const status = await guardrailPolicy.getKillSwitchStatus(modeOrGlobal);
return {
  isEnabled: status.killSwitchTripped,  // or false if you want SafetyGuardrails "soft only"
  reason: status.killSwitchReason,
  source: 'guardrails_v2',
};


Implement toggleKillSwitch(enabled, reason) to simply:

Call guardrailPolicy.setKillSwitch(mode, enabled, reason) or the appropriate method that writes to guardrails_v2.

Do not write to kill_switch table anymore.

Leave kill_switch table as legacy-only storage

After this phase, kill_switch should not be written to or read from in any runtime logic.

Update any /safety/kill-switch route to use GuardrailsPolicy instead of SafetyGuardrails global table

H7.3 — Decouple SafetyGuardrails from Blocking Behavior

Currently, H6 shows that AutonomyController calls SafetyGuardrails and gets “kill switch enabled,” which then blocks its self-check and produces noisy KILL_SWITCH events.

We want:

AutonomyController diagnostics to never block trading, and ideally:

Not be blocked themselves by legacy safety state

Not spam KILL_SWITCH events just because someone flipped a UI toggle months ago

Steps:

Inspect autonomy-controller.ts for SafetyGuardrails usage

Identify:

Calls like safetyGuardrails.evaluateAction(...)

Any conditional like “if policy hits include KILL_SWITCH ⇒ block”

Change semantics for phase 8.8.3:

For now, we want no hidden guardrail here:

If SafetyGuardrails returns killSwitch.isEnabled based on guardrails_v2.killSwitchTripped, it should be informational only for AutonomyController.

AutonomyController can log a warning or record a telemetry event, but must not block its self-checks purely due to kill-switch.

Concretely:

Replace any early-return like:

if (policyHits.includes('KILL_SWITCH')) {
  // block self-check
  return { blocked: true, reason: 'Kill switch enabled' };
}


with something like:

if (policyHits.includes('KILL_SWITCH')) {
  console.warn('[8.8.3-H7][AUTONOMY] Kill switch active; proceeding with self-check in read-only mode');
  // proceed, maybe with a flag in the result but do NOT block
}


The key is: no “hidden KILL_SWITCH” semantics left in the autonomy layer.

Safety events

Keep safety telemetry events (for future analysis) but downgrade the noise:

If kill switch is enabled, broadcast once per self-check, not as a continuous spam.

Tag them clearly as “diagnostic-only, no trading impact” in the payload.
