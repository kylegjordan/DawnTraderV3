📌 PART A — Fix Individual Trade Close Error Toast (A1)
Problem

UI always shows an error toast after clicking Close on a single trade, even though:

Trade closes successfully

DB updates correctly

Engine position is removed

UI refreshes correctly

Root Cause

Backend response shape does not match what the UI expects.

UI expects:

{ success: true }


Backend returns variations such as:

{ status: "ok" }
{ closed: 1 }
{ removed: true }

Required Fix

Update the backend endpoint called by Close Trade to always return:

{
  success: true,
  closedTradeId: "<uuid>",
  message: "Trade closed successfully"
}


Do not change existing functionality.
Only unify the success response shape.

Also update the UI handler to look for success === true and show a green confirmation toast instead of red error toast.

📌 PART B — Lightweight Reset Integrity Audit (A2, Option B)

We are NOT doing major changes to reset logic.
Instead, add a 1-step audit AFTER any reset operation to verify system state is clean.

Where

Inside paperSessionResetService.hardResetPaperSimulation() after all existing reset tasks complete.

Add audit method:
await engineIntegrityAudit.checkPostResetState();

Audit Rules (all must pass)

Paper engine must NOT be running

engine.isRunning === false

No open paper positions

DB query returns count = 0

No leftover ready-to-buy signals

orchestrator’s ready list empty

WebSocket adapter has zero active subscriptions

adapter.subscriptionMap empty

Price caches are empty

centralized price cache has zero entries

No dangling FX5 windows

hourly and 24h windows must reset to empty arrays

If audit passes → return:
{ success: true, message: "Reset complete" }

If audit fails → log diagnostic only

DO NOT throw errors, DO NOT block reset.
