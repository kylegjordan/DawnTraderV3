🧭 Directive 11.6C — “VTS Real-Price Persistence Integration (Legacy ML Pipeline Hook)”
Phase:

11.6C — Core Infrastructure Alignment

Objective:

Integrate the new real-price-based openVirtualTrades subsystem (Directive 11.6) directly into the existing VTS persistence and ML aggregation pipeline, ensuring all simulated trade outcomes persist automatically and flow into telemetry and machine learning systems as before.
No new persistence tables or systems are to be created.

I. Problem Summary

Following Directive 11.6:

Trade exits now use real Kraken price data via the priceCache (✅ correct).

Trades remain in-memory in the openVirtualTrades registry until closed.

Closed trades are only logged to console ([11.6][Exit]) and then lost.

No persistence or ML ingestion occurs, unlike in pre-11.6 random simulation mode.

As a result:

The ML Feature Store and TelemetryAggregator receive no new data.

All realistic trade outcomes vanish after server restart or log rotation.

II. Directive Objective

Restore the full data persistence and ML aggregation pipeline by reconnecting the new openVirtualTrades real-price exit logic to the existing VTS trade storage and telemetry ingestion pipeline that was used prior to Directive 11.6.

This ensures:

✅ Continuous ML data flow (no retraining gaps)

✅ Proper persistence of all closed trades

✅ Seamless continuity with historical schema and analytics tools

III. Implementation Tasks
Task 1 — Identify Existing Trade Persistence Function

File:

Persist simulated trades

Update telemetry history

Feed trade data into the ML pipeline

⚙️ Do not create new persistence logic.
We will reuse this function exactly as before.

IV. Architectural Constraints

No new DB tables.
Reuse existing schema and storage layers (vts-storage.ts, telemetry-aggregator.ts, and downstream ML).

No data duplication.
A trade must exist only once — in the same structure as historical VTS trades.

No schema drift.
Use the same keys and types:
symbol, entryTime, exitTime, entryPrice, exitPrice, pnl, regime, strategy, exitReason.

No extra Kraken API calls.
All price lookups remain from priceCache.

In-memory registry remains for open trades only.
Do not persist open trades yet — only closed ones.
