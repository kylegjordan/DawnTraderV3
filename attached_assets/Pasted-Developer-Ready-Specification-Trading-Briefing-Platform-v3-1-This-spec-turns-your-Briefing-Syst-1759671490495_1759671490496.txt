Developer-Ready Specification — Trading Briefing Platform (v3.1)

This spec turns your Briefing System Summary (v3) into implementable backend + frontend + scheduling instructions, with External Event Awareness that can also surface opportunities arising from those events, and Adaptive Intra-Day Coaching that includes Execute and Chat actions.

System timebase: All automation and email scheduling run on UTC.
UI time: Show timestamps in user’s local time as a secondary subtitle (primary remains UTC for logs).

2) Back-End Services
2.1 Services & Responsibilities

Report Orchestrator (svc-reports)

Builds/updates reports documents.

For daily: updates hourly or on market events; sets status=final at 23:59 UTC.

Triggers email dispatch when final.

Market Intelligence Harvester (svc-events)

Ingests central bank calendars, earnings calendars, economic releases, curated news feeds.

Normalizes into market_events.

Runs correlation step linking events to affected symbols and portfolio performance.

Opportunity Engine (svc-opportunities)

Scanners + LLM reasoning + rules.

Enforces ≥ 50% projected return gate.

Can generate event-derived opportunities (tie back via linked_event_ids).

System Health Monitor (svc-health)

Runs synthetic checks (API latency, ingestion gaps, execution errors, backups).

Writes system_health_logs, feeds summarized health into reports.system_health.

Email Dispatcher (svc-mail)

Formats subject + body preview.

Sends to kylegjordan@gmail.com.

Retries with exponential backoff; writes email_sent_at_utc.

Execution Gateway (svc-exec)

Validates payloads from UI “Execute”.

Submits to broker/exchange.

Records execution_orders with audit trail.

Chat Bridge (svc-chat)

Seeds a chat thread with context (report id, opportunity id, event id).

Returns a conversation link/token to open the Chat view.

3) Scheduling & Lifecycle

Daily

00:01 UTC: Initialize daily report (status=in_progress).

Every hour or on event/position changes: update sections.

23:59 UTC: finalize report → send email.

Weekly/Monthly/Quarterly/Half-Year/Yearly

End-of-period (UTC): generate → finalize → email.

Ad-Hoc

On-demand; single-shot generate and finalize (no intraday sections).

Scheduler: Use a single cron worker reading period boundaries from config, aligned to UTC.

5) External Event Awareness — Detection → Explanation → Opportunities
5.1 Event Ingestion

Sources: economic calendar, earnings calendar, central bank schedule, curated news API.

Normalize to market_events.

For each event:

Map to affected_symbols using:

sector/industry mapping

ETF constituents

FX sensitivity rules (e.g., Fed → USD pairs, gold, yields)

Estimate impact_direction by price/volatility response ± dispersion.

5.2 Explanation Layer

Template + LLM reasoner combines:

What happened (verified facts)

Why it matters (transmission channel: rates → multiples → sectors)

Portfolio effect (link to your positions & P&L anomalies)

Save into reports.external_events.

5.3 Event-Derived Opportunities

For each event, run event-specific scanners:

Earnings beats/misses → momentum/mean-reversion plays

Rate changes → duration/FX/gold rotations

Macro prints (CPI, NFP) → volatility regime shifts

Score and filter:

projected_return_pct >= 50

confidence >= 0.6 (tuneable)

Risk guardrails (exclude if stop > max allowed)

Persist to opportunities with linked_event_ids=[event.id].

Inject into:

reports.emerging_opportunities

reports.external_events[*].derived_opportunities

UI Actions: Each derived opportunity includes Execute and Chat buttons (payloads specified in §2.2).

6) Adaptive Intra-Day Coaching (Daily Only)

Trigger conditions (examples, tuneable):

win_rate_intraday < 0.5 OR

drawdown_from_open > X% OR

sequence_losses >= 3 OR

volatility_mismatch flag = true

Recommendations library (examples):

Reduce per-trade risk from r to r * 0.5

Tighten stop ATR multiple from k to k * 0.8

Pause new trades until volatility < threshold

Switch to only A-grade setups checklist

Action hooks in section:

Execute: applies a parameter patch (e.g., set max_position_risk_pct=0.35) or closes/reduces exposure per rules, routed via POST /api/actions/execute.

Chat: opens AI thread with pre-loaded context: report metrics, current pain points, rationale, and “what if” analysis.

9) Security, Permissions, Audit

RBAC:

viewer: read reports

trader: execute actions

admin: configure schedules, thresholds

CSRF & auth for all POSTs.

Audit trails: log user id, ip, payload hash, timestamp for Execute and Chat.

Dry-run mode in svc-exec for sandbox/testing.

10) Failure Handling

Partial data: mark sections with data_stale=true, show timestamp of last refresh.

Event source down: fallback to cached calendars; degrade gracefully with notice.

Email failure: queue retry (1m, 5m, 15m, 1h) then alert admin.

Execution error: surface error toast and write execution_orders.status="error" with broker message.

13) QA Checklist (Go-Live)

 Daily cron creates in_progress report @ 00:01 UTC.

 Hourly updates append to sections; dashboard preview refreshes.

 End-of-day finalization and email dispatch succeed.

 External events ingest & correlate; event-derived opportunities appear with actions.

 Opportunity filter strictly enforces ≥ 50%.

 Adaptive coaching triggers correctly; Execute/Chat actions work and are audited.

 Ad-hoc generator produces labeled reports over custom ranges.

 Health issues surface with correct severity; logs are linked.

 RBAC prevents unauthorized execution.
