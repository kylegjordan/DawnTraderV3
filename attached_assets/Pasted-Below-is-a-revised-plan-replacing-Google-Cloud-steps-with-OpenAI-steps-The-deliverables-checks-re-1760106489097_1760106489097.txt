Deliverable C — Backend Transcription Route (OpenAI instead of Google)

Goal: Call OpenAI’s transcription endpoint (Whisper or gpt-4o-transcribe) instead of Google.

Actions:

Add backend endpoint: e.g. POST /api/openai/transcribe.

In the handler:

Accept the audio blob (e.g. multipart/form-data or base64 JSON).

Convert to appropriate format (e.g. Uint8Array, base64) as required by OpenAI SDK.

Call OpenAI’s transcription API:

Using OpenAI’s Node.js SDK (pseudocode):

import { openai } from './openaiClient'; // configured with API key

const file = /* audio bytes or readable stream */;
const transcriptResponse = await openai.audio.transcriptions.create({
  model: "gpt-4o-transcribe",   // or “whisper-1” (or other model) depending on availability
  file: file,
  // optional: specify format, prompt, etc
});
const text = transcriptResponse.text;


Return { text } to the frontend.

Protect endpoint via JWT / auth checks (same as before).

Error handling: handle rate limits, unsupported format, invalid API key, etc.

Check:

Request to /api/openai/transcribe returns { text: "..." } within acceptable latency (e.g. < 2–4 s for small clips).

If wrong format, returns a clear error.

Auth-protected.

Deliverable D — Frontend: Display / Inject Transcription

After receiving { text }, set the chat input field’s value to that text.

Let user review, edit, and then send.

Optional: allow “auto-send” after transcription if user opts in.

Check: transcription appears correctly; works for both Goals Engine and GPT Chats.

Deliverable E — Edge Cases & Stability

If mic permissions denied → show “Enable mic access” prompt.

If transcription fails → error toast “Could not transcribe audio. Try again.”

Enforce maximum audio duration (e.g. limit to 30 s per recording).

Validate server-side that file size is within limit.

Log errors / fallback paths.

Check: No uncaught errors. Good UX on failure.
