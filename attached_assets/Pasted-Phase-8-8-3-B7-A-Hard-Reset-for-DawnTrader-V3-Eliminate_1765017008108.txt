Phase 8.8.3-B7.A — Hard Reset for DawnTrader V3 (Eliminate Ghost Paper Trades)
0. Context (for the dev)

We’re seeing:

Ghost open trades in the backend that the UI doesn’t show.

“Fresh” paper sessions that still hit MAX_TOTAL_EXPOSURE based on old positions.

Trades showing up almost immediately in the first few FX5 scan cycles.

This tells us the current paper reset only clears some DB rows but leaves in-memory engine state and diagnostics buffers intact.

We want a single, authoritative hard reset path inside DawnTrader V3 so that:

Clicking “Reset / New paper sim” in the UI gives a genuinely fresh session.

No one (human or script) needs to run ad-hoc SQL for clean starts.

2. Implement a dedicated PaperSessionResetService

Create a new service file:

server/services/paper-session-reset.ts

Add a class that coordinates a full paper-sim reset:

// server/services/paper-session-reset.ts
import { PaperExecutionEngine } from './paper-execution-engine';
import { PaperPositionSizing } from './paper-position-sizing';
import { SignalOrchestrator } from './signal-orchestrator';
import { TradingSignalsCleanupService } from './trading-signals-cleanup';
import { PaperSimRepository } from './schema'; // or the actual repo file
import { B4DiagnosticsService } from './b4-diagnostics'; // adapt to actual names
import { B5SizingAudit } from './b5-sizing-audit';
import { B6PipelineDiagnostics } from './b6-pipeline-diagnostics'; // if exists

export class PaperSessionResetService {
  constructor(
    private engine: PaperExecutionEngine,
    private sizing: PaperPositionSizing,
    private orchestrator: SignalOrchestrator,
    private signalsCleanup: TradingSignalsCleanupService,
    private paperRepo: PaperSimRepository,
    private b4: B4DiagnosticsService,
    private b5: B5SizingAudit,
    private b6?: B6PipelineDiagnostics
  ) {}

  /**
   * Hard reset for paper mode.
   * Clears ALL paper session state: engine, sizing, orchestrator,
   * filters/signals, diagnostics, and DB rows for open positions.
   */
  async hardResetPaperSimulation(): Promise<void> {
    // 1) Stop engine / loops safely
    await this.engine.stopPaperTrading?.(); // use the actual stop method

    // 2) Clear in-memory engine state
    this.engine.resetSessionState();

    // 3) Clear sizing and exposure tracking
    this.sizing.resetSession();

    // 4) Clear orchestrator and signal-related session state
    this.orchestrator.resetSession();
    await this.signalsCleanup.resetSession();

    // 5) Clear diagnostics buffers (B4/B5/B6)
    this.b4.reset();
    this.b5.reset();
    this.b6?.reset?.();

    // 6) Clear DB state for open paper positions and trades
    await this.paperRepo.hardResetPaperSim();
  }
}


Important: If class names or constructor signatures differ, adapt them, but keep the same intent: a single service coordinating a full reset.

Wire this into your service container / DI (where other services are instantiated) so it can be injected into the controller later.

3.6 DB layer (schema.ts or the paper sim repo)

In the file where paper_sim_trades and paper_sim_open_positions are handled (you mentioned schema.ts and we’ve seen Replit doing raw SQL), add a repository method:

export class PaperSimRepository {
  // existing db client...

  async hardResetPaperSim(): Promise<void> {
    // Close any open paper trades
    await this.db.query(`
      UPDATE paper_sim_trades
      SET closed_at = NOW(), close_reason = 'hard_reset'
      WHERE closed_at IS NULL AND mode = 'paper';
    `);

    // Remove current open positions snapshot
    await this.db.query(`
      DELETE FROM paper_sim_open_positions
      WHERE mode = 'paper';
    `);
  }
}

4. Wire the hard reset into the API

We want the existing reset flow you use in the UI to call this new orchestrator.

In server/routes.ts (or wherever the paper-sim routes are defined):

Locate the POST /api/paper-sim/reset handler.

Change its implementation to call PaperSessionResetService.hardResetPaperSimulation() instead of only resetting balance or DB partially.

Example:

// routes.ts (or paper-sim-controller.ts)
import { PaperSessionResetService } from './services/paper-session-reset';

// assume resetService is constructed with dependencies
router.post('/api/paper-sim/reset', requireAuth, async (req, res) => {
  try {
    await paperSessionResetService.hardResetPaperSimulation();

    // You can optionally accept a new balance here or leave that to /start
    const { newBalance } = req.body || {};
    if (newBalance != null) {
      await paperSimRepository.setBalance(newBalance);
    }

    res.json({ ok: true });
  } catch (err) {
    // log error details
    res.status(500).json({ ok: false, error: 'HARD_RESET_FAILED' });
  }
});


Key point:

After this change, when you click Reset from the UI, everything is cleared:

engine memory,

sizing memory,

orchestrator memory,

signals/RTB,

diagnostics,

DB open trades and positions.

No one needs to log into Replit and run SQL anymore.
