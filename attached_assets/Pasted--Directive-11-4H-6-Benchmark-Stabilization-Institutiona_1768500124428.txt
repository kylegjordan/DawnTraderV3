🧭 I. Architectural Context and Definitions
Term	Definition
Mode	The system’s operating environment: Live or Paper.
TradingActive	Boolean flag determining whether real or paper trades are executing.
true = Active Trading mode; false = Passive Learning (VTS).
VTS (Virtual Trade Simulator)	Engine that runs during Passive Learning to simulate signals, filter pairs, and update telemetry.
Institutional Math Filters (IMF)	Advanced filters for liquidity quality (LQ), volatility noise, correlation guards, and statistical market structure metrics. They must always calculate for every scanned pair — even in Passive Learning.
Ideal Pool	The set of pairs that are continuously scanned and updated by the VTS or Trading Engine. Benchmark pairs are forced members of this pool.
Benchmark Pairs	Blue-chip coins (BTC, ETH, SOL) and major stablecoins (USDT, USDC, DAI, BUSD, TUSD). They must always appear in the Ideal Pool and Benchmark List tabs.
Telemetry	Aggregated data from scans and VTS runs that feeds friction and regime metrics to the UI.

Prevent non-blue-chip coins (e.g., FARTCOIN/USDT) from being misclassified as benchmarks.

// server/config/benchmark-regex.ts
export const BENCHMARK_REGEX = /^(?:BTC|XBT|ETH|SOL|USDT|USDC|DAI|BUSD|TUSD)(?:[-_/]?(?:USD|USDT|USDC|DAI|BUSD|EUR))?$/i;

// server/services/adaptive-scan-manager.ts
import { BENCHMARK_REGEX } from "../config/benchmark-regex";

const isBenchmarkSymbol = (symbol: string): boolean => BENCHMARK_REGEX.test(symbol);

// Filter only valid benchmark symbols
const BENCHMARK_SYMBOLS = allPairs
  .map(p => p.symbol)
  .filter(sym => isBenchmarkSymbol(sym));

for (const symbol of BENCHMARK_SYMBOLS) {
  idealPool.add(symbol, { forceInclude: true, source: "benchmark" });
}


✅ Expected Result:
Only true benchmarks (BTC, ETH, SOL, stablecoins) are classified as benchmarks.
No memecoins or low-liquidity tokens can enter the Benchmark List or Ideal Pool.

Task 3 — Institutional Math Filters (IMF) Telemetry Persistence During Passive Learning

Objective:
Ensure IMF metrics are calculated and persisted in telemetry even when tradingActive = false.
Do not activate the Active Filter Pool when trading is inactive.

Files:

/server/services/fx5-scanner.ts

/server/services/vts-runner.ts

Implementation:

// Example snippet from fx5-scanner.ts
const imfMetrics = computeInstitutionalMath(pair.marketData);
pair.imfMetrics = imfMetrics;

// Persist IMF metrics to telemetry always
telemetry.persistIMF(pair.symbol, imfMetrics);

// Apply IMF filters conditionally
if (tradingActive) {
  // Active trading → use survivors in Active Filter Pool
  activeFilterPool.addSurvivors(mode, metricFilteredSurvivors);
} else {
  // Passive Learning → skip pool but store metrics
  logger.info(`[IMF] Stored metrics for ${pair.symbol} during passive learning.`);
}


✅ Expected Result:
IMF metrics are calculated for every scan and persisted to telemetry.
The Active Filter Pool remains inactive in Passive Learning.

Task 7 — Overview Tab Dynamic Binding for Favored Strategies and Signals

const [favoredStrategies, setFavoredStrategies] = useState([]);
const [favoredSignals, setFavoredSignals] = useState([]);

useEffect(() => {
  const fetchIndicators = async () => {
    const res = await fetch('/api/market-indicators');
    const data = await res.json();
    setFavoredStrategies(data.favoredStrategies);
    setFavoredSignals(data.favoredSignalTypes);
  };
  fetchIndicators();

  // Refresh every 60 seconds
  const interval = setInterval(fetchIndicators, 60000);
  return () => clearInterval(interval);
}, []);


✅ Expected Result:
Overview tab automatically refreshes favored strategies and signals each minute without overloading CPU.
