VTS Strategy & Scoring Audit

Objective: Determine whether the VTS is (a) using real strategy logic, (b) calculating and recording the same scores as the trading engine, and (c) what must be built to make the VTS a true learning-grade shadow engine without duplicating existing systems.

This audit is based on direct inspection of the repository structure and key files defined in the authoritative repo map you provided.

1. Strategy Files Inventory

Question: Can individual strategy files be reused by the VTS for TP/SL and signal math?

Where strategy logic lives

Primary file:
server/services/strategy-engine.ts

Supporting pattern logic:

server/core/regime/canonical-regime-strategy-map.ts

server/services/dynamic-strategy-selector.ts

Key finding

❌ Strategy logic is NOT encapsulated in standalone, reusable strategy modules.

Each strategy’s logic (entry conditions, TP/SL construction, structural references like VWAP, SMA, swing lows, range highs) is implemented inside the trading engine execution flow, not as isolated “pure” functions.

That means:

There is no reusable per-strategy function you can safely call from the VTS today.

Strategy calculations assume:

execution context

order direction

live/paper trade lifecycle

position sizing already resolved

➡️ Conclusion:
You cannot simply “call the strategy files” from the VTS. A VTS-specific shadow strategy engine is required, even if it borrows logic.

This validates your instinct completely.
