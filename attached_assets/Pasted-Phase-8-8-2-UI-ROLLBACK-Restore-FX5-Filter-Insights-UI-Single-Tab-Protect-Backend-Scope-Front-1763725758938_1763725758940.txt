Phase 8.8.2-UI-ROLLBACK

Restore FX5 Filter Insights UI (Single Tab) & Protect Backend

Scope: Front-end + wiring verification only.
Non-Goals: No changes to Stage-3 cache/emitter, scanner logic, or breakdown schema / truth-constraint.

1. Context – What Went Wrong

During Phase 8.8.2 / 8.8.2-D we correctly:

Implemented Stage-3 cache + emitter

Wired FX5 scanner to Stage-3

Fixed the FilterBreakdown schema and truth constraint

Verified singletons & runtime behavior

However, somewhere in that process the Trading → Filter Insights UI regressed:

A separate “Filter Pairs” tab was re-introduced.

The merged “Filter Insights” tab (from Phase 8.7 final) was broken apart.

Extra breakdown categories (History, Market Cap, Guardrail Risk, Universe Size) reappeared in the 24h Filter Breakdown section.

The per-filter descriptions under each breakdown row disappeared.

None of this was requested. Phase 8.7 had already delivered a single, consolidated Filter Insights tab, ready for production. This directive restores that UI and locks it to the current backend.

These keys may still exist in Stage-3 / diagnostics for internal accounting, but they are not part of the user-facing breakdown in Filter Insights. The 24h breakdown list is intentionally simplified for user clarity.

3. Constraints & Non-Goals (Must NOT Break 8.8.2 / 8.8.2D)

This sub-phase is UI rollback + mapping check only.

You must not:
