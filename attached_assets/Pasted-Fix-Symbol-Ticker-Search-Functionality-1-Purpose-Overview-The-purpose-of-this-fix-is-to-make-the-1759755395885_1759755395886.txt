Fix Symbol/Ticker Search Functionality
1) Purpose & Overview

The purpose of this fix is to make the Symbol/Ticker Search system correctly handle both stocks and crypto assets by improving how user selections are parsed and routed to the proper data source (Finnhub or CoinGecko/Kraken).

Currently, when a user searches for stock tickers like “PG” (Procter & Gamble) or “TSLA” (Tesla), the dropdown shows results — but when selected, the app incorrectly tries to fetch data from the crypto API instead of Finnhub, resulting in “No results found” messages.

This fix ensures that:

Only the actual ticker symbol (e.g., PG, TSLA) is passed to the backend.

The backend automatically detects and routes to the correct data source.

Stocks and cryptos are handled separately but through a unified interface.

The UI reliably displays live market data, with the “Analyze” button active for all valid symbols.

2) Implementation Tasks
2.1 Input Parsing (Frontend Fix)

Intent: Ensure that only the ticker symbol (not the company name) is passed to the API.

Replit: Update the Symbol Search input component.

2.2 Backend Service Fix (StockService and Routing Logic)

Intent: Ensure backend correctly determines whether a symbol is stock or crypto, and properly falls back between data providers.

Replit: Edit
server/services/stocks.ts

Add/Modify the following logic:

Parse incoming symbol

const cleanSymbol = symbol.match(/^([A-Z0-9\-_]+)/)?.[1] || symbol;


Determine lookup type

First check if cleanSymbol exists in cached crypto symbol list.

If yes → fetch via CoinGecko/Kraken.

If not → fetch via Finnhub.

If crypto lookup fails, auto-retry as stock.

let data = await getCryptoQuote(cleanSymbol);
if (!data) {
  data = await getStockQuote(cleanSymbol);
}


Standardize unified response:

return {
  type: data?.type || (isCrypto ? 'crypto' : 'stock'),
  symbol: cleanSymbol,
  name: data?.name || '',
  currentPrice: data?.price || null,
  lastUpdated: new Date().toISOString(),
  source: data?.source || (isCrypto ? 'CoinGecko' : 'Finnhub')
};


Enhance logging

console.log(`[SymbolLookup] ${cleanSymbol} resolved via ${data?.source}`);


Cache successful lookups for 12 hours to minimize API cost.

2.3 API Endpoint Update

Intent: Ensure /api/symbol/data uses the improved logic.

Replit: Edit server/routes.ts

Add or modify:

app.get("/api/symbol/data", async (req, res) => {
  const symbol = (req.query.symbol as string)?.toUpperCase();
  if (!symbol) return res.status(400).json({ error: "Missing symbol" });

  try {
    const data = await StockService.getSymbolData(symbol);
    if (!data) return res.status(404).json({ error: `No data found for ${symbol}` });
    res.json(data);
  } catch (err: any) {
    console.error("Symbol data fetch error:", err);
    res.status(500).json({ error: "Internal error fetching symbol data" });
  }
});

2.4 Error Handling and Retry Logic

When a symbol returns no data, return:

{ "error": "Data not found", "retryable": true }


Frontend should show:

“Retry with stock data” if crypto lookup failed.

“Retry with crypto data” if Finnhub lookup failed.

“No results found” only if both fail.
