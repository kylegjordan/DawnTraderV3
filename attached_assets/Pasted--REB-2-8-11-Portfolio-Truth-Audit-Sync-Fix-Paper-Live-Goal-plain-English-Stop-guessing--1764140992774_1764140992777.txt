⚙️ REB 2.8.11 – Portfolio Truth Audit & Sync Fix (Paper + Live)

Goal (plain English)
Stop guessing. Map exactly how portfolio value flows for both paper and live modes, from backend to every UI widget, then fix the places where:

Paper starting balance + simulated P&L are not propagating to all portfolio surfaces, and

LATTi Goals & Guardrails / Goals Engine either lag, desync, or error out after balance changes.

We must preserve the REB 2.8.10B architecture (global portfolio_balance_updated WebSocket + REST) and only fix broken pieces, not redesign the system.

A. Guardrails & Truth Constraints

Truth = Pre-corruption behavior

Paper mode:

User inputs a paper starting portfolio value when a new simulation starts.

That value + simulated P&L must drive all portfolio surfaces (Dashboard, LATTi, Goals Engine) for paper mode.

Live mode:

Portfolio value is taken from Kraken balances.

No manual override; all UI surfaces show the Kraken-derived value.

Architectural constraints

Keep REB 2.8.10B global refresh architecture (WebSocket + REST polling).

Do not remove PortfolioRefreshListener, query-keys.ts, or the portfolio_balance_updated mechanism.

Do not change trading engine metrics (scans, filters, FX5) – they remain REST-only. The portfolio is an exception allowed to use WebSocket for sub-second updates.

Scope of this REB

✅ Paper portfolio value truth (startBalance + simulated P&L).

✅ Live portfolio value truth (Kraken).

✅ Sync across:

Dashboard “Portfolio Value” widget

Dashboard “LATTI Goals & Guardrails” widget

Goals Engine → Goals tab → “Current Portfolio Value / Projected Portfolio Growth”

❌ Do not adjust anything in Filter Insights / trading metrics.

Confirm that:

LATTi Goals & Guardrails widget, and

Goals Engine → Goals tab / Projected Portfolio Growth
both read from endpoints wired to that canonical paper portfolio value.

Fix any code that:
