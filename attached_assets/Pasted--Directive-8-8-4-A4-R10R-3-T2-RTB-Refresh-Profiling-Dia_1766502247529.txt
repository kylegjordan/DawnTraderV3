🧩 Objective

Profile the internal stages of the readyToBuyService.refreshAndRank() function to identify which operations cause refresh cycles to exceed the 15-second micro-cycle window.

This diagnostic will gather high-precision timing data for:

Database fetch (getActiveSignals)

Metric recalculation (NGC, CWQI, etc.)

Sorting/ranking phase

Persistence/writeback

Total per-bucket duration

⚙️ Implementation Tasks
1️⃣ Instrument readyToBuyService.refreshAndRank()

Add timing points within server/core/rtb/ready_to_buy_service.ts (or equivalent file).

Example instrumentation:

async refreshAndRank(mode: string) {
  const tStart = Date.now();
  this.log(`[8.8.4-A4.R10R-3.T2][START] mode=${mode}`);

  const tFetchStart = Date.now();
  const activeSignals = await this.storage.getActiveSignals(mode);
  const tFetch = Date.now() - tFetchStart;

  const tRecalcStart = Date.now();
  for (const s of activeSignals) {
    await this.recalculateMetrics(s); // includes NGC, CWQI, etc.
  }
  const tRecalc = Date.now() - tRecalcStart;

  const tSortStart = Date.now();
  const sorted = this.rankSignals(activeSignals);
  const tSort = Date.now() - tSortStart;

  const tWriteStart = Date.now();
  await this.storage.updateReadyToBuy(sorted);
  const tWrite = Date.now() - tWriteStart;

  const total = Date.now() - tStart;
  this.log(`[8.8.4-A4.R10R-3.T2][TIMING] fetch=${tFetch}ms recalc=${tRecalc}ms sort=${tSort}ms write=${tWrite}ms total=${total}ms count=${activeSignals.length}`);

  return sorted;
}


Note: Guard this instrumentation under if (mode === 'paper') to avoid clutter in production.
