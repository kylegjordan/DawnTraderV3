🧩 B. TuningTab Component — Specifications

File: client/src/components/trading/tuning-tab.tsx

Layout Overview:

2-column responsive layout.

Left: Active summary (current policy + today’s KPIs).

Right: Table of tuning events (past 24 h, scrollable, sortable).

Sections
1️⃣ Header Summary

Displays current tuning state:

Auto-Tuning:  ✅ Enabled | ⛔ Disabled
Aggressiveness: Balanced
Policy Version: #3 (updated 2 hrs ago)
Session Mode: Paper / Live


Buttons:

“Enable / Disable Auto-Tuning”

“Show Policy”

“Rollback Last Tuning”

→ Each triggers NLAI intents through API:

POST /api/tuning/enable|disable
GET  /api/tuning/policy
POST /api/tuning/rollback

2️⃣ Tuning Activity Table

Pull data from:

GET /api/tuning/events?mode={currentMode}&limit=100


Columns:

Time (UTC)	Field	Old → New	Confidence	Reason	Approval	Status	
2025-10-19 17:14	riskPerTrade	1.5 → 1.9 %	0.82	P&L pace low	Auto	✅ Success	🔄 Reverted?

Features:

Sort by time desc (default)

Filter by approval type (auto/manual/reverted)

Export → CSV (Export History)

Auto-refresh every 30 s when session active

Empty-state card: “No tuning events yet for this session”

3️⃣ Policy Overview Card

Displays tuning_policy fields:

Per-field bounds & max step pct

Cooldowns & daily limits

Current counters (adjustments today, reverts)

⚙️ C. Backend Endpoints to Use / Add (if not already present)
1. Fetch Events

GET /api/tuning/events?mode={paper|live}&limit={n}
Returns last n rows from tuning_event, joined with walter_execution_log.

2. Toggle Auto-Tuning

POST /api/tuning/enable / disable
Body: { mode } → updates tuning_policy.enabled.

3. Rollback Last Tuning

POST /api/tuning/rollback
Reverts to most recent parameter_baseline snapshot.

4. Get Current Policy

GET /api/tuning/policy?mode={paper|live}

(Phase 26 already defined these; confirm they’re live.)

🧮 D. Data Display Logic

Data sources:

/api/tuning/events → react-query hook (useQuery(['tuningEvents', mode]))

/api/tuning/policy → policy summary

/api/state/summary → to show current session mode/status

Refresh rate: 30 s when simulation or live trading active; 120 s idle.

Error handling: If fetch fails, show toast “Unable to load tuning events – retrying.”
