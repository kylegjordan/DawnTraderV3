📋 Implementation Instructions — “AI Opportunities” (Full Stack)

0) Goal & Scope

Add an AI Opportunities tab inside the AI Analysis panel that:

Ingests all Kraken spot pairs (≈220+) every hour (not just the 20 screened coins).

Has the AI generate structured opportunity candidates across categories:
Long-term Hold, Moonshot, Momentum, Breakout, Mean Reversion.

Shows each opportunity with: coin, type, entry, floor (stop), ceiling (target), probability/risk-reward rating, rationale, plus Execute and Chat buttons.

Enforces portfolio guardrails and explicit confirmation before executing orders.

Stores everything in Postgres with a full audit trail, and exposes a Validation Report so the owner can verify correctness.



---

1) Data & Scheduler

1.1 Kraken Universe

Source: All spot tradable pairs (same set you already consume).

Frequency: Hourly (configurable).

Respect Kraken rate limits. Use batch endpoints where possible.


1.2 Data Collected per Pair (hourly snapshot)

At minimum (computed/derived if needed):

symbol, base_currency, quote_currency

last_price, 24h_volume, daily_range_pct

VWAP(1h or intraday), SMA(20), SMA(50), SMA(200)

ATR or simple volatility proxy (optional)

trend markers (above/below SMA 50/200), distance from VWAP/SMA

any existing flags from your screener


Persist to price_data / existing storage with timestamp.

1.3 Cost Control Pre-Processing

Before calling GPT:

Rank & trim: select top N by liquidity/volatility (configurable; start with N=150) to keep prompts small.

Delta filter: skip pairs whose features haven’t materially changed since last run (thresholds on price %, volume %, trend flips).

Summarize numerics (rounded) and strip noisy fields.



---

2) GPT Opportunity Generation

2.1 Model & Cadence

Default model for hourly analysis: GPT-4o mini (or equivalent low-cost).

Escalate to a stronger model only on demand (user requests deeper analysis).


2.2 Structured Output (must be JSON-serializable)

For each selected pair, AI may return zero or more opportunities. Each item should include:

opportunity_id (UUID generated by backend)

symbol

type ∈ {long_term_hold, moonshot, momentum, breakout, mean_reversion}

Plan:

entry_zone (price or range)

stop_floor (hard stop)

target_ceiling (TP/targets; allow array for scaling)

time_horizon (e.g., hours/days/weeks)

risk_amount_rule (in $ or as %; AI proposes, backend enforces cap)

notes (concise rationale)


Scores:

probability_score (0–100)

risk_reward_rating (1–5 or R multiple estimate)


Eligibility flags AI sees as risks (thin books, high spread, unusual volatility)


2.3 Guardrails in Prompting

Instruct AI not to place orders; it only proposes structured opportunities. Execution is a separate user action that must pass backend guardrails.

---

4) Backend Services

4.1 Hourly AI Pipeline

1. Collect Universe Data → all pairs with features.


2. Trim/Dedupe → rank by liquidity/vol; apply delta filter.


3. Call GPT → with compact batch payload; request structured JSON.


4. Validate → schema validation; discard malformed items; annotate reasons.


5. Upsert ai_opportunities with status='new', link to ai_opportunity_runs.


6. Log to ai_audit_log action=create_opportunity for each item.



4.2 Guardrails (reuse your engine + enforce before any execution)

Spot only, no margin/derivatives.

Risk sizing: R in $, stop distance, position size = R ÷ stop_distance.

Exposure caps: max exposure %, max open trades.

Slippage protection: simulate fill at stop vs. order book depth; compare to tolerance.

Available balance check.

Symbol locks: avoid duplicate active trades in same symbol if policy requires.


4.3 Opportunity Actions (API)

POST /api/opportunities/execute → runs guardrails, OCO orders, logs in trades, updates opportunity status='executed', writes to ai_audit_log.

POST /api/opportunities/watchlist → sets status='watchlist', logs.

POST /api/opportunities/dismiss → sets status='dismissed', logs.


4.4 Chat-per-Opportunity

POST /api/ai/conversations/opportunity → creates conversation titled "Opportunity: {SYMBOL} – {TYPE} – {DATE}", seeds first system/context message with the exact structured JSON of that opportunity; logs action=chat_created.


4.5 Validation Report (Owner Review Package)

Create an endpoint and in-app view:

GET /api/opportunities/validation/latest → returns latest run summary:

run_id, timestamp, model, input/output token est., cost_est.

pairs_considered, pairs_sent_to_ai, opportunities_created (by type)

sample payload sent to AI (redacted) and first 5 parsed opportunities (as JSON)

guardrail test summary (how many would pass/ fail if executed now, and why)

any parsing/validation errors Surface this in AI Analysis → Reports → “AI Opportunities Validation” with a “Copy JSON” button so it can be pasted here for review.
