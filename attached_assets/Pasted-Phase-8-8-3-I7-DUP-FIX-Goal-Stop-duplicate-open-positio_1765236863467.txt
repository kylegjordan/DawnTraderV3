Phase 8.8.3 – I7-DUP-FIX

Goal:

Stop duplicate open positions per symbol (root cause: race in open guardrail).

Stop duplicate Ready-To-Buy signals per symbol per scan.

Make the Active Trades UI show only one row per symbol and keep prices updating normally.

Do not auto-close existing duplicates yet – only prevent new ones and hide duplicates in the UI.

0. Scope / Safety

Backend only: server/ (trade engines, DB layer, WebSocket infra), plus client/src/components/trading/active-trades-v2.tsx and the Ready-To-Buy UI/component if needed.

Trading behavior change is guardrail only: when a duplicate-open is attempted, it must be cleanly rejected and logged, not crash the app.

Do not delete or mutate existing DB rows in this phase.

Keep all new logs clearly tagged with "[8.8.3-I7-DUP]".

1. Prevent Duplicate Open Positions (DB Unique Constraint)
1.1 Inspect DB schema

Find the schema / migrations for the paper trades table (e.g. paper_trades) and the live trades table (e.g. live_trades or trades).

Confirm there is a symbol column and a status column with values like 'open', 'closed', etc.

1.2 Add partial unique index per table

Add a migration (or direct SQL, consistent with existing style) that creates partial unique indexes so there can be at most one open position per symbol per table:

For paper trades table (exact table name may differ, adjust accordingly):

-- 8.8.3-I7-DUP-FIX: prevent duplicate open paper trades per symbol
CREATE UNIQUE INDEX IF NOT EXISTS idx_paper_trades_symbol_open_unique
ON paper_trades(symbol)
WHERE status = 'open';


For live trades table (adjust table name):

-- 8.8.3-I7-DUP-FIX: prevent duplicate open live trades per symbol
CREATE UNIQUE INDEX IF NOT EXISTS idx_live_trades_symbol_open_unique
ON live_trades(symbol)
WHERE status = 'open';


Notes:

If there is already some other uniqueness on (account_id, symbol, status) or similar, extend that instead of creating a conflicting index.

Do not modify existing constraints; add a new partial index unless one already exists with the same semantics.

1.3 Harden open-trade path to handle unique violation cleanly

Locate the trade open logic for paper and live trading.

For paper, this is likely in server/services/paper-execution-engine.ts or a closely related service.

For live, a similar engine or service file.

Wherever a new trade is inserted into the DB, wrap the DB insert call in a try/catch (or promise .catch) that specifically looks for a unique-constraint violation from the index above.

Pseudocode pattern (TypeScript-ish):

try {
  const trade = await storage.createPaperTrade(newTradeData);
  // continue as normal
} catch (err: any) {
  if (isUniqueOpenSymbolViolation(err)) {
    console.warn('[8.8.3-I7-DUP][OPEN_GUARD] Duplicate open position prevented', {
      symbol: newTradeData.symbol,
      mode: 'paper',
      reason: 'db_unique_constraint',
    });
    // Do NOT crash. Treat as guardrail:
    // - Option A: Return gracefully, indicating "no new position opened".
    // - Option B: Bubble a typed error that the caller understands as "open skipped".
    return null; // or a special result object
  }
  throw err;
}


Implement isUniqueOpenSymbolViolation(err) to detect the DB error code:

For Postgres, look for err.code === '23505' and message/constraint name containing idx_paper_trades_symbol_open_unique or idx_live_trades_symbol_open_unique.

For SQLite, check err.code and/or err.message for a similar unique-constraint indicator.

Add a log when a duplicate is attempted and blocked:

console.warn('[8.8.3-I7-DUP][OPEN_GUARD]', {
  symbol,
  table: 'paper_trades',
  reason: 'unique_constraint_open_symbol',
});


Ensure callers (e.g. the strategy engine / RTB execution) handle the “no trade opened” result silently, not as a fatal error.

1.4 Keep existing soft guardrail, but treat DB as source of truth

If there is an existing pre-check like:

const openCount = await storage.countOpenTradesForSymbol(symbol);
if (openCount >= maxPositionsPerAsset) { /* reject */ }


keep it for early rejection, but treat the DB unique index as the final authority.

Add a comment pointing to this directive so future devs know the DB constraint is intentional.

2. Prevent Duplicate Ready-To-Buy Signals

Goal: During a single scan cycle, only one RTB signal per (symbol, strategy, direction) should be emitted to the API/UI.

2.1 Locate RTB signal engine

Find the service that generates Ready-To-Buy signals, e.g. a file like:

server/services/ready-to-buy-engine.ts

or similar (look for "Ready-to-Buy" text, RTB endpoints, or the RTB API handler).

Confirm where the signal list is built and returned to the client (probably an array of objects with symbol, price, strategy, etc.).

2.2 Deduplicate signals per scan

In the code that assembles the signals array for a single scan:

Before returning, dedupe by a composite key. For example:

const seen = new Set<string>();
const dedupedSignals: ReadyToBuySignal[] = [];

for (const sig of rawSignals) {
  const key = `${sig.symbol}__${sig.strategy}__${sig.direction ?? 'long'}`;
  if (seen.has(key)) {
    console.warn('[8.8.3-I7-DUP][RTB_DEDUP]', {
      symbol: sig.symbol,
      strategy: sig.strategy,
      direction: sig.direction ?? 'long',
      reason: 'duplicate_in_same_scan',
    });
    continue;
  }
  seen.add(key);
  dedupedSignals.push(sig);
}

return dedupedSignals;


Make sure this deduping happens once per scan just before the signals are:

returned from the service, and/or

sent to the client in the RTB API.

If there is any client-side RTB polling that merges old and new signals, ensure it also de-dups on the same key to avoid front-end duplicates across multiple polls.

2.3 Optional: avoid signals where a position is already open

If not already done:

When building RTB signals, filter out any symbol that currently has an open position (as seen by the engine or DB).

This further reduces duplicates like: signal + open position for same symbol.

Add a log when a signal is suppressed:

console.info('[8.8.3-I7-DUP][RTB_SUPPRESS_OPEN_POSITION]', { symbol, strategy });

File:
client/src/components/trading/active-trades-v2.tsx

const dedupedPositions = useMemo(() => {

    seen.add(p.symbol);
    result.push(p);

}, [positions]);
