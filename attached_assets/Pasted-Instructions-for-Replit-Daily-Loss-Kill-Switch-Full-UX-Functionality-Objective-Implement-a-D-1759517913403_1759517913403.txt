Instructions for Replit – Daily Loss Kill Switch (Full UX + Functionality)

Objective:
Implement a Daily Loss Kill Switch as part of Portfolio Guardrails. It should:

Monitor rolling 24h losses,

Trigger a warning at a user-defined threshold,

Trigger a full kill switch at a user-defined threshold,

Halt trading until user reset,

Provide a dedicated Kill Switch screen in the app,

Allow user to enter a ChatGPT chat for automated analysis and recommendations.

1. Settings (UI + Database)

In Settings → Portfolio Guardrails, create a new section called Kill Switch.

Variables:

Daily Loss Kill Switch (%):

Default: 7.00%.

User-defined % of portfolio equity (rolling 24 hours).

Daily Loss Warning Trigger (% of Kill Switch):

Default: 75%.

User-defined (e.g., 50%, 75%).

Sends notification but does not suspend trading.

Trading Suspension Flag (system-controlled):

Boolean (true/false).

Set to true when kill switch triggered.

Must be reset manually by user via UI or ChatGPT.

2. Functional Logic

Rolling 24h PnL Tracking:

Track realized + unrealized PnL over the last 24h window.

Warning Trigger:

If loss >= WarningTrigger% of KillSwitchLimit:

Send notification:
“⚠️ Portfolio down X% in last 24h. Approaching Kill Switch limit of Y%.”

Kill Switch Trigger:

If loss >= DailyLossKillSwitch%:

Close all open trades immediately.

Set tradingSuspended = true.

Block new trades until reset.

Send push notification:
“🚨 Kill Switch Triggered: Portfolio down X% in last 24h. All trades closed. Trading suspended.”

User Reset:

In Settings: Toggle “Resume Trading.”

Or via ChatGPT: “Resume trading” command.

3. Notifications & Logging

All triggers logged clearly with timestamp + PnL values.

Notifications sent via email, push, Telegram per user preferences.

Kill Switch event logs must include:

Portfolio before/after equity

Total % loss vs threshold

Trade breakdown (symbols, strategy, entry/exit, PnL)

4. User Experience (UX Flow)

When Kill Switch is triggered:

Push Notification:
“🚨 Kill Switch Triggered: Portfolio down 7% in last 24h. All trades closed. Trading suspended.”

App Behavior:

On open, user is taken directly to a Kill Switch Screen (not the dashboard).

Header banner: “Kill Switch Activated – Trading Suspended.”

Summary displayed:

Current equity vs prior equity

Daily % loss vs Kill Switch limit

Time triggered

Collapsible trade breakdown (symbols, strategies, entry/exit, PnL).

Below Summary:

A button: “View Analysis in ChatGPT”.

Tapping this opens a new ChatGPT panel/chat dedicated to this incident.

5. ChatGPT Analysis Integration

When user taps “View Analysis in ChatGPT”:

Start a new chat session automatically.

Pre-populate first message with full context:

“Your Kill Switch was triggered after a X% loss (limit Y%). Here are the trades involved:”

Include trade list + portfolio metrics.

ChatGPT responds with:

Analysis (why losses happened).

Recommendations (adjust screener, strategy settings, guardrails, etc.).

User Options:

Accept Recommendations (apply suggested changes automatically).

Ask More Questions (continue ChatGPT conversation).

Reject Recommendations & Edit Settings Manually (link back to Portfolio Settings).

6. Deliverables

Updated Settings UI with Kill Switch section.

Updated Risk Manager / Guardrails logic with kill switch + warning trigger.

Kill Switch Screen design:

Banner, summary, trade breakdown, “View Analysis in ChatGPT” button.

ChatGPT integration flow: New chat auto-started with full loss context.

Test Scenario demonstrating:

Warning issued at 75% of threshold.

Kill switch activated at 100%.

Trades closed.

Kill Switch Screen shown on app open.

ChatGPT session created with analysis.
