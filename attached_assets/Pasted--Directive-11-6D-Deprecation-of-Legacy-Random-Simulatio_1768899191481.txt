🧭 Directive 11.6D — “Deprecation of Legacy Random Simulation Subsystem”
Phase

11.6D — System Sanitation and Architecture Unification

Objective

To completely remove the legacy Phase-10 random trade simulation logic (including any stochastic outcome generators, fake price exits, and Phase-10 persistence hooks) from the Virtual Trade Simulator (VTS) and related modules.
All VTS activity shall henceforth exclusively use the real-price-based openVirtualTrades subsystem introduced in Directive 11.6C.

This ensures all simulated trades represent genuine market movement, producing consistent data for learning, validation, and analytics.

I. Problem Summary
Current State

Two parallel simulation systems exist:

Legacy Random Simulation Path

Uses random volatility-based price deltas to generate artificial exits.

Writes directly to JSON logs and ML pipeline (vt_* records).

Located in legacy functions such as simulateTradeOutcome() and generatePhase10Signal().

Real-Price Simulation Path (Directive 11.6C)

Uses live Kraken price data from priceCache.

Trades persist when real prices hit stop-loss or take-profit.

Logged as vt_realp_* records and correctly feed ML.

Problem

Both systems run concurrently.

ML and analytics are receiving mixed data (real + random).

The random simulation produces meaningless P&L results, corrupting feature learning.

CPU and memory are wasted maintaining two pipelines.

The presence of both systems creates schema confusion and data inconsistency.

II. Directive Objectives

Fully deprecate and remove all references to the legacy random trade simulation path.

Ensure the VTS uses only the real-price monitoring and resolution loop for trade closure.

Preserve full ML continuity through the persistence integration completed under Directive 11.6C.

Confirm that no random or probability-based trade exits remain in the system.
