Calls /api/goals/update with { metricKey, goalValue }.

After success, refetches /api/goals and replaces the local state with the returned payload.

B. Trading Toggle Fix (Paper / Live Engine Start-Stop)

1️⃣ Backend:

Make /api/trading/status the only data source (reads from system_context).

Ensure /api/trading/set-mode commits changes atomically (is_engine_active, trading_mode, session_id).

Emit a trading_state_changed WebSocket event after commit.

2️⃣ Frontend:

Add/verify a central useTradingStore or equivalent state hook.

On click of the trading toggle:

Disable the button (isPending = true).

Call /api/trading/set-mode.

On success, update store and wait for WS event.

On WS event, set isPending=false and update display.

Add a fallback poll every 5 seconds to call /api/trading/status in case WS fails.

3️⃣ Expected result:

Click toggle → toast “Trading started” and header changes to ACTIVE.

Click again → toast “Trading stopped” and header changes to STOPPED.

State restored correctly after page reload.
