1. Re-establish the intended API contract for /api/filters-v2
1.1. Current problem

Right now, clicking a checkbox fires a PUT and returns:

Error: value is required when filterName is provided

That’s wrong for toggle-only actions (when we’re just changing “Managed by LATTI” on/off).

1.2. Required API contract

PUT /api/filters-v2?mode=paper|live must support two kinds of updates:

Toggle-only (no value change):

{
  "filterName": "minVolumeUsd",
  "manualOverrideEnabled": false   // or true
}


This must NOT require value.

Backend should only update the override flag for that filter and leave the numeric value unchanged.

Value update (with optional override toggle):

{
  "filterName": "minVolumeUsd",
  "value": 7500,
  "manualOverrideEnabled": true
}


This updates both the stored value and the override flag.

✅ Fix:
In server/routes.ts, find the PUT /api/filters-v2 handler and:

Remove / relax any validation that throws when filterName is present but value is missing.

Only require value when the request is actually a value update (you can infer from presence of value field).

Allow requests that contain just { filterName, manualOverrideEnabled } and update only the flags.

Important:
Do not change the overall filters data model, table shape, or add columns. Only update the logic that processes the inbound JSON for this endpoint.

2. Fix checkbox behavior in FiltersWithOverride

File: client/src/components/goals/filters-with-override.tsx

2.1. Each checkbox must toggle only its own filter

Locate where the filters from /api/filters-v2 are mapped to rows/cards (e.g. Volume & Liquidity, Price Range, Market Filters, Technical Indicators, Universe & Signal Controls, Data Quality).

For each filter row, ensure:

It has a unique filterName (e.g. "minVolumeUsd", "maxMarketCapUsd", "minHistoryDays", etc.).

The “Managed by LATTI” checkbox is bound to that filter’s own manualOverrideEnabled or equivalent flag (whatever field you are using to represent “Managed by LATTI” vs Manual).

Implement a dedicated toggle handler:

const toggleManagedByLatti = (filterName: string, isManaged: boolean) => {
  updateFilterMutation.mutate({
    filterName,
    manualOverrideEnabled: !isManaged   // or managedByLatti: isManaged, depending on convention
  });
};


Wire each checkbox click to this handler with its own filterName, e.g.:

<Checkbox
  checked={filter.isManagedByLatti}  // or the appropriate field
  onCheckedChange={(checked) =>
    toggleManagedByLatti(filter.name, !!checked)
  }
/>


Key requirement: Toggling one checkbox must never affect another filter’s managed state.

3. Fix field editability when override is off

Still in FiltersWithOverride.tsx:

3.1. Bind disabled correctly

For each input/select field:

Disabled when Managed by LATTI is ON

Enabled when Managed by LATTI is OFF

So, for each field:

const isManaged = filter.isManagedByLatti; // or inverse of manualOverrideEnabled

<Input

/>


Check:

There is no other prop that re-disables the input (e.g. readOnly, pointer-events: none, or wrapper disabling).

CSS classes are not interfering with pointer events (pointer-events-none etc).

3.2. Ensure onChange is wired

For each numeric or textbox style input:

It must have an onChange or onBlur that:

Reads the new value

Normalizes/validates it

Calls the mutation for value update:

const updateFilterValue = (filterName: string, value: number | string) => {
  updateFilterMutation.mutate({
    filterName,
    value,
    manualOverrideEnabled: true,   // if user is directly typing, we treat as manual
  });
};


Then:

<Input
  value={renderedValue}
  disabled={isManaged}
  onChange={(e) => {
    const raw = e.target.value;
    // Minimal parsing for now; Stage 2 will add nice formatting
    const numeric = parseFloat(raw.replace(/,/g, ''));
    if (!Number.isNaN(numeric)) {
      updateFilterValue(filter.name, numeric);
    }
  }}
/>


Goal: Once Managed by LATTI is unchecked, user can place a cursor, type a new number, and see it persisted on reload.
