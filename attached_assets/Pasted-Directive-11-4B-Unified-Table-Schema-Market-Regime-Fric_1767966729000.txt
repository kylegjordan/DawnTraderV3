I. Objective

To standardize the structure, content, and order of all trading-related tables — making every column meaningful, educational, and operationally consistent — while integrating Market Regime and Market Friction as visual metrics directly tied to the Analytics & Diagnostics architecture.

The new schema ensures that every signal, open trade, and closed trade presents a complete “story” of its lifecycle — from environment to outcome — with clear cost and risk context.

Task 2 — Update Cost-Metrics Utility for Visual Mapping

File: /server/core/metrics/cost-metrics.ts

Add a helper to generate color + label values for friction columns:

export function mapFrictionVisual(score: number): {
  label: string;
  color: string;
} {
  if (score <= 20) return { label: `${score}: High Liquidity`, color: "green" };
  if (score <= 50) return { label: `${score}: Normal Liquidity`, color: "yellow" };
  if (score <= 80) return { label: `${score}: Stressed Liquidity`, color: "orange" };
  return { label: `${score}: Frozen / Illiquid`, color: "red" };
}


This is called at serialization time for signals and trades before returning them to the client.

Task 4 — UI Rendering Logic for Color Coding

Example Utility (shared across all tables):

File: /client/src/utils/frictionColor.ts

export function getFrictionColor(score: number): string {
  if (score <= 20) return "text-green-600 bg-green-50";
  if (score <= 50) return "text-yellow-700 bg-yellow-50";
  if (score <= 80) return "text-orange-700 bg-orange-50";
  return "text-red-700 bg-red-50";
}


Example Cell Renderer:

<td className={`px-3 py-1 rounded ${getFrictionColor(row.marketFrictionScore)}`}>
  {row.marketFrictionLabel}
</td>
