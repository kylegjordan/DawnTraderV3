🎯 Objective

Add automated anomaly detection, color-coded alerting, and self-recovery capabilities to the existing Unified Engine Health Monitor and Engine Telemetry Dashboard.
This will allow the system to automatically detect and respond to operational faults (e.g., stalled queues, long heartbeats, blocked WebSocket, etc.) in both Paper and Live modes.

🧩 Implementation Tasks
Task 1 – Define Alert Thresholds

Add thresholds in server/services/health-monitor.ts:

Metric	Warning (YELLOW)	Critical (RED)	Action
Heartbeat latency	> 200 ms	> 400 ms	Flag & recover
Broadcast latency	> 100 ms	> 250 ms	Reinit contextBridge
Queue depth	> 5	> 10	Purge old jobs
Job age	> 15 s	> 30 s	Restart engine
WebSocket silence	> 2 cycles	> 4 cycles	Force reconnect

Use a configuration block:

const ALERT_THRESHOLDS = {
  heartbeat: { warn: 200, crit: 400 },
  broadcast: { warn: 100, crit: 250 },
  queueDepth: { warn: 5, crit: 10 },
  jobAge: { warn: 15000, crit: 30000 },
  wsSilence: { warn: 2, crit: 4 },
};

Task 2 – Extend HealthMonitor

Add:

evaluateAnomalies() method comparing metrics to thresholds.

triggerAutoRecovery(reason) method that:

Logs [41F-F][RECOVERY][AUTO] entries.

Broadcasts health_recovery over WebSocket.

Executes recovery routines (queue clear, reconnect, etc.).

Append anomalies to a rolling anomalyBuffer (100 entries).

Task 3 – Update EngineTelemetry UI

Enhance the Engine Telemetry tab:

Display metric tiles with color state (green = OK / yellow = Warning / red = Critical).

Add a collapsible “Recent Anomalies & Recoveries” panel below the metrics.

Show guidance: normal ranges + what to check if out of range.

Task 4 – Implement Recovery Log API

Add to server/routes-health.ts:

GET  /api/health/recovery/log     // return recent recovery events
POST /api/health/recovery/trigger // manual recovery test

Task 5 – Fault-Injection Testing

Create /test-scripts/phase-41F-F-fault-injection.sh to simulate:

Stuck job: enqueue a dummy job that never resolves.

Busy flag drift: set globalPaperSimBusyFlag = true and start engine.

WebSocket silence: disable WS temporarily to trigger reconnect.

Cache burst: push 1000 dummy entries to test latency alerts.

Heartbeat lag: pause HealthMonitor thread for > 500 ms.

Observe that:

Alerts are generated.

Auto-recovery occurs.

Engine resumes normal heartbeat within 10 seconds.
