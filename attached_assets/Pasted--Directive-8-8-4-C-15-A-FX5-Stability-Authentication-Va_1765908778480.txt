⚙️ Directive 8.8.4-C.15.A — FX5 Stability & Authentication Validation Run

Date: 2025-12-16
Supersedes: 8.8.4-C.14.D
Objective: Conduct a fully monitored, one-hour trading session to validate system stability, authentication integrity, and FX5 scanner persistence following recent RTB and orchestrator updates.

1. Background

During an unmonitored paper-trading session (~2 hrs runtime), the system exhibited partial functionality:

Component	Observed State	Effect
Trading Engine (isEngineActive)	Active	System showed “Active” in UI
FX5 Scanner	Stopped after restart	Scan cycles frozen at 19
Authentication Layer	401 Errors	API endpoints for /api/trading-signals and /api/portfolio-summary failed
WebSocket Streams	Running	Live prices continued updating
RTB Table	Failing	“Failed to load trading signals” due to auth failure
Trade History	Empty	UI blocked by 401s (data exists in DB)
Starting/Current Balance	$0 displayed	API fetch blocked, but live portfolio value persisted

These indicate auth context loss and scanner timer termination, leaving the system in a half-active state.
Directive 8.8.4-C.15.A initiates a structured validation run to reproduce, observe, and document behavior under full supervision.

2. Scope of Work

Replit shall:

Reset all system components and clear transient state

Reinitialize trading and FX5 scanner modules

Run a supervised one-hour trading session

Collect structured logs and health metrics

3. Pre-Validation Environment Reset
3.1 Stop All Active Processes

Execute:

npm run stop-all


Verify that:

isEngineActive=false

FX5Scanner logs show [STOPPED]

No open WebSocket sessions persist

3.2 Clear Volatile Data

Truncate or reset:

system_context

fx5_scan_cycles

ready_to_buy_signals

paper_sim_sessions (mark all “running” sessions as closed)

auth_sessions or token cache store

3.3 Restart Backend
npm run start:prod


Confirm in logs:

[FX5Scanner][BOOTSTRAP] FX5 scan timers initialized
[SystemContext] Trading engine inactive (idle state)

GET /api/paper-sim/portfolio-summary → 200 OK

Signal Promotion	Promoted RTB signals removed immediately	0 duplicate signal IDs post-promotion
Auth Layer	No 401s during runtime	100 % successful API calls
Trading Engine	Remains stable, no crash logs	engineActive persists true
Trade History	Closed trades logged	≥ 1 close event recorded
Balances	API and WS values match (± $0.01)	Consistency check
Latency	RTB UI refresh ≤ 200 ms after broadcast	Pass
