Phase 8.8.3-J7.1 — Guardrails Persistence & Sizing Consistency (Paper Mode)

Goal

Fix guardrails editing so that:

Values set on the Goals Engine → Guardrails page (manual mode) persist correctly and become the single source of truth for paper mode.

The J7 sizing helper (paper-position-sizing.ts) always uses those persisted values.

No behavior that is currently working (J5 metrics, J7 sizing, RTB tables, FX5 scanner, kill-switches, etc.) is broken.

This is a narrow, corrective phase, not a redesign.

1. Guardrails Editing Bug – Fix & Audit

Symptoms (current behavior)

On the Guardrails page:

Changing “Portfolio Risk per Trade %” from 3 to some other value, clicking Save → field visually reverts to 3.

Changing “Max Position Percent %” from 30 to another value, clicking Save → field reverts to 30.

Changing Low Price Coin Protection threshold from 0.50 (50¢) to 0.075 (7.5¢) → UI accepts input, but after save it snaps back to 0.50.

Toggle is on Manual in all of these cases, so LATTi should not be overwriting them.

2. Persistence Fix (Manual Mode Wins for Paper)

After the mapping is done, implement the minimal fix so that for paper mode:

When the user:

Chooses Manual for a guardrail (risk per trade, max position %, LPCP threshold)

Enters a value

Clicks Save and the save succeeds

→ That value must be reliably persisted and read back unchanged on page reload.

LATTi / auto values must not overwrite manual values in paper mode while the control is set to Manual.

If there is any server-side validation error (e.g., out-of-range value), the user must see a clear validation message and the field should not silently revert; instead:

Do not update the stored value

Show an inline error saying what range is allowed

Keep the user’s typed value in the input until they change it or cancel

Handle decimal values for LPCP correctly:

Values like 0.075 (7.5¢) are valid and must round-trip correctly:

User enters 0.075

Save

Reload page → field still shows 0.075 (or 0.08 if we enforce a rounding rule — but if so, document and show that rule).

Important constraints

Do not reintroduce or depend on any legacy risk manager or getSettings() / pre-guardrails modules.

All work must stay on the guardrailsV2 / current architecture path.

Do not change any kill-switch, daily loss, or LTC/LATTi algorithms beyond what’s necessary to fix persistence.
