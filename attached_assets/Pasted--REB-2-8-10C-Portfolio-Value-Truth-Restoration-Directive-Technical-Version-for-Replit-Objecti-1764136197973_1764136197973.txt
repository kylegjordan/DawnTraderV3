🧩 REB 2.8.10C — Portfolio Value Truth Restoration Directive (Technical Version for Replit)

Objective:
Restore correct, instant-refresh, REST-only portfolio value behavior across the Dashboard, LATTi Goals & Guardrails, and Goals Engine for both paper and live mode, ensuring correct mode isolation, correct P&L integration, and removal of all WebSocket dependency from the UI.

✅ SECTION A — BACKEND: SINGLE SOURCE OF TRUTH PER MODE
A.1 — PAPER MODE PORTFOLIO (SSOT)

Canonical REST endpoint (must be the only data source for UI):

GET /api/paper/portfolio/state

Requirements

This endpoint must return the live in-memory simulation state, including:

{
  totalValue: number,            // startingPortfolio + realizedPnL + unrealizedPnL – fees
  startingPortfolio: number,
  realizedPnL: number,
  unrealizedPnL: number,
  lastUpdated: number
}


All modules that affect simulated P&L must write to the same source:

Paths to modify/confirm:

server/services/paper-sim-trade-execution.ts
server/services/paper-sim-engine.ts
server/services/paper-sim-service.ts
server/storage/paper-sim-state.ts


Update logic must be synchronous and must always update the in-memory paper simulation state used by /api/paper/portfolio/state.

When a simulated trade executes:

Update realizedPnL or unrealizedPnL immediately.

Recompute totalValue.

Persist to the same state object that /api/paper/portfolio/state reads from.

A.2 — LIVE MODE PORTFOLIO (SSOT)

Canonical REST endpoint:

GET /api/portfolio/overview?mode=live

Requirements

Value must come exclusively from Kraken/live account logic.

Must never use the paper simulation state.

No UI component may override or modify live mode values.

If additional live endpoints exist (e.g. /api/portfolio/state), they must internally delegate to the canonical endpoint or be deprecated.

Paths to audit:

server/services/live-trading-service.ts
server/services/kraken-portfolio-service.ts
server/routes.ts

✅ SECTION B — FRONTEND: UNIFIED PORTFOLIO HOOK

Create/update:

client/src/hooks/use-portfolio-balance.ts

Required API:
export function usePortfolioBalance(mode: 'paper' | 'live')

Internals:
queryKey: ['portfolioBalance', mode]

queryFn:
  if (mode==='paper')  GET /api/paper/portfolio/state
  if (mode==='live')   GET /api/portfolio/overview?mode=live

React Query Config:
{
  refetchInterval: 5000,     // Hard requirement
  staleTime: 0,
  refetchOnWindowFocus: true,
  refetchOnReconnect: true,
  retry: false
}


This must be the only portfolio-fetching hook used across the app.

Every component that displays a portfolio value must be refactored to use usePortfolioBalance(mode).

Remove any direct use of:

inconsistent queryKey variations

✅ SECTION E — INVALIDATE PORTFOLIO QUERIES AFTER MODE CHANGES

In:

client/src/components/layout/top-bar.tsx


After these operations:

handleStartNewSimulation

handleContinueSimulation

handleStopPaperSimulation

handleConfirmLiveTrading

handleConfirmStopLiveTrading

Add:

queryClient.invalidateQueries(['portfolioBalance', 'paper']);
queryClient.invalidateQueries(['portfolioBalance', 'live']);
queryClient.invalidateQueries({ queryKey: ['goalsSummary', mode] });
queryClient.invalidateQueries({ queryKey: ['lattiTargets', mode] });


This ensures:

Paper → Live switches refresh instantly

Live → Paper switches refresh instantly

Goals engine recomputes based on new balance

LATTi recomputes based on new balance
