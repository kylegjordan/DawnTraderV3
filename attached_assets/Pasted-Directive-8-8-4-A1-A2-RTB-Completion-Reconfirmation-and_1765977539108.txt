A1. RTB Promotion Cleanup

Purpose:
Ensure that signals promoted to active trades are immediately and cleanly removed from the RTB queue and broadcast to all clients, keeping the queue synchronized.

Tasks

Promotion Event Hook

Add in paper_trading_engine.ts:

Cleanup Handler

In ready_to_buy_service.ts:

  await readyToBuyService.removeSignal(symbol, mode);

});


Verification

Promoted symbols disappear from RTB ≤ 30 s after promotion.

UI updates immediately via rtb:cleared.

A1-Extended — RTB Refresh, Reconfirmation, and Dynamic Re-Ranking

Purpose:
The RTB queue should act as a live, adaptive ranking system, revalidating and reordering all entries every 30 seconds based on the latest signal data and recalculated CWQI.

1. Signal Reconfirmation

Each RTB signal must be refreshed with updated price and indicator data every FX5 scan cycle.

In fx5_scanner.ts:

const signals = await readyToBuyService.getAll(mode);
for (const signal of signals) {
  const updatedData = await fx5Service.fetchSignalData(signal.symbol);
  await readyToBuyService.refreshSignal(signal.symbol, updatedData);
}


This ensures:

price, indicators, and CWQI are up-to-date every 30 seconds.

Signals remain accurate reflections of current market conditions.

2. Continuous CWQI Re-Ranking

After refreshing signals, the RTB queue must re-sort dynamically based on CWQI, not insertion order.

In ready_to_buy_service.ts:

async refreshAndRank(mode) {
  const signals = await this.getAll(mode);

  // Recalculate CWQI for each signal
  const rescored = signals.map(sig => ({
    ...sig,
    CWQI: calculateCWQI(sig),  // use latest indicators
  }));

  // Sort by CWQI descending (highest first)
  rescored.sort((a, b) => b.CWQI - a.CWQI);

  // Save back to DB or cache
  await this.saveRankedSignals(mode, rescored);

  // Broadcast the update to clients
  await websocket.broadcast('rtb:updated', { mode });
}


Then, call readyToBuyService.refreshAndRank(mode) at the end of each FX5 cycle.

3. Behavior and Verification

Expected Behavior

Every 30 seconds:

All signals in RTB are reconfirmed with new price/indicator data.

CWQI is recalculated.

The queue is re-ranked based on current strength.

Top-ranked signals rise to the top in the UI automatically.

Validation Criteria

Queue order changes over time as conditions shift.

New strong signals can overtake older weaker ones.

CWQI values visibly fluctuate each refresh.

lastReconfirmedAt timestamps remain ≤ 30 s old for every entry.
