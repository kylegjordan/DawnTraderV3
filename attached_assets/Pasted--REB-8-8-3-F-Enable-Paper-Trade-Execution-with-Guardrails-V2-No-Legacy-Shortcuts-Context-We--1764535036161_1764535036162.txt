⚙️ Part 2 — Restore Signal → Execution Path (Paper Mode, Guardrails V2 Only)

Objective: For each valid strategy signal in paper mode, use guardrails_v2 + risk-manager to decide whether to open a trade and, if so, call the correct executor.

2.1 Re-enable processing of strategy signals

In the place where the pipeline is currently blocked (likely in paper-execution-engine.ts):

Remove / replace the early-return that logs "Signal processing disabled (pending guardrails_v2 migration)".

Instead, call a real execution path, roughly in this shape (pseudo-logic):

// inside signal processing loop for paper mode
const settings = await riskManager.buildSettingsFromGuardrailsV2({
  mode: 'paper',
  userId,
});

const riskCheck = await riskManager.validateSignal({
  mode: 'paper',
  settings,
  signal,          // StrategySignal from strategy-engine
  portfolioState,  // current positions + balance
});

if (!riskCheck.allowed) {
  // log rejection with [8.8.3-F][RISK_REJECT]
  continue;
}

// construct trade request from signal + riskCheck.positionSize
const tradeRequest: PaperTradeRequest = {
  mode: 'paper',
  symbol: signal.symbol,
  direction: signal.direction,   // long/short
  entryPrice: signal.entryPrice, // or currentPrice
  stopLoss: signal.stopPrice,
  takeProfit: signal.targetPrice,
  size: riskCheck.size,
  strategy: signal.strategyName,
  metadata: { ... },
};

// call the paper trade executor / trading engine
const tradeResult = await paperPortfolioManager.openTrade(tradeRequest);
// or whatever the current executor is


Important constraints:

Use existing risk-manager functions where possible; don’t invent new guardrail logic.

Respect all guardrails_v2 in paper mode:

portfolio risk per trade

total exposure

max open positions

symbol cooldown

daily loss kill switch (reactive, via existing risk logic)

Do not reintroduce tradingSuspended or any “secondary kill switch”.

2.2 Use correct trading state & kill switch logic

Only process signals / open trades when:

isEngineActive.paper === true

killSwitchTripped === false at engine start (as already implemented)

Do not stop scanning or signal generation when kill switch trips.

Kill switch should stop trading (no new trades) by stopping the engine, not silently ignore signals with engine still marked active.
