🧱 Task 1 — Canonical Symbol Normalization Integration
Purpose

Eliminate all symbol mismatches (e.g., XBT, XXBTZUSD, AVAXUSDT) by leveraging the live Symbol Mapping System already implemented in /server/markets/.

Actions

Apply canonicalization at data ingress for all critical services.
Replace any ad-hoc normalization or legacy regex mapping with:

import { normalizeToInternalSymbol } from "@/server/services/utils/symbol-canonicalizer";
const canonicalSymbol = normalizeToInternalSymbol(rawSymbol);


Integrate this call in:

/server/services/vts-runner.ts → before signal generation and trade routing

/server/services/fx5-scanner.ts → before pair ranking and pool updates

/server/services/signal-orchestrator.ts → at event ingestion

/server/services/routes.ts and /server/models/trade-model.ts → during payload validation

Audit canonicalization integrity

Create script /scripts/audit_symbol_normalization.js:

// iterate all active pairs → output tier, canonical, and mapping source


Output results to /audit/reports/symbol_normalization_audit.json.

Verification Criteria

All BTC/XBT and DOGE/XDG mappings resolve correctly.

No “NO_DATA” exclusions for Bitcoin pairs.

⚙️ Task 2 — Friction Rebalancing (Adaptive Percentile Scaling)
Purpose

Remove static spread thresholds that caused >50 % of pairs to fall into “Red” friction tier.

Implementation

File: /server/core/metrics/cost-metrics.ts

Replace fixed thresholds with adaptive percentile scaling:

const spreads = pairs.map(p => p.spread);
const low = percentile(spreads, 30);
const high = percentile(spreads, 70);

if (spread <= low) friction = "GREEN";
else if (spread <= high) friction = "ORANGE";
else friction = "RED";


Log friction tier counts and percentiles to:
/audit/reports/friction_balance_validation.json.

Target distribution:

GREEN ≈ 30 %

ORANGE ≈ 40 %

RED ≈ 30 %.

🧮 Task 5 — Goals Engine Adaptive Weighting
Purpose

Balance AI confidence dominance with adaptive control based on volatility.

Implementation

File: /server/core/metrics/goals-engine.ts

Maintain double weighting but cap total ML contribution:

const aiWeightCap = 0.40;
const baseWeight = config.weights.mlConfidence;
const volatilityFactor = clamp(volatility, 0, 1);
const aiWeight = Math.min(baseWeight * (1 - volatilityFactor), aiWeightCap);


Add checksum test in /tests/goals_engine_integrity.test.ts:

expect(totalWeight).toBeCloseTo(1.0, 2);


Output report /audit/reports/goals_engine_adaptive_weights.json confirming:

Final composite weights per factor

Total ≤ 1.0

ML influence ≤ 0.40
