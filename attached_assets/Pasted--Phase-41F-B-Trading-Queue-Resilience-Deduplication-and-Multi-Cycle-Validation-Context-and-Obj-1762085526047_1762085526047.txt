🧩 Implementation Tasks
1️⃣ Implement Request Deduplication

Goal: Avoid stacking identical jobs in the queue.

In server/utils/operation-queue.ts, extend enqueue() logic to check existing queued jobs.

enqueue(job: OperationJob) {
  const key = `${job.userId}:${job.mode}:${job.sessionId || 'default'}`;
  if (this.queue.find(q => q.key === key && q.action === job.action)) {
    console.warn(`[41F-B][QUEUE] Duplicate ${job.action} ignored for ${key}`);
    return Promise.resolve({ status: 'ignored', reason: 'duplicate' });
  }

  this.queue.push({ ...job, key });
  this.processNext();
  return job.promise;
}


✅ Prevents redundant “start-while-starting” or “stop-while-stopping” collisions.
✅ Reduces queue size and eliminates duplicate WebSocket notifications.

2️⃣ Separate WebSocket/UI Broadcasts from Engine Jobs

In both:

server/services/paper-sim-service.ts

server/services/live-trading-service.ts

Move any broadcastUserUpdate() or notifyClients() calls outside the queue jobs.
They should fire asynchronously once the job resolves successfully.

Example pattern:

// Inside job execution
const result = await engine.start();
return result;

// After job completion
job.promise.finally(() => {
  tradingStateSync.broadcastUserUpdate(job.userId)
    .then(() => console.log('[41F-B][WS] Broadcast (non-blocking) sent'))
    .catch(err => console.warn('[41F-B][WS] Broadcast error:', err.message));
});


✅ Ensures WebSocket lag never blocks engine operations.
✅ Improves responsiveness on start/stop actions.

4️⃣ Graceful Recovery Logic

Add a lightweight safeguard to handle unclean shutdowns:

  if (this.queue.length > 0) {
    console.warn('[41F-B][QUEUE] Clearing orphaned jobs from previous session');

});


✅ Prevents orphaned “busy” states after restarts.
