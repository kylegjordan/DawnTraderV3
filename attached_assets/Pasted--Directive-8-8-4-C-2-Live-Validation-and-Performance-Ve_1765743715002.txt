🧭 Directive 8.8.4-C.2 — Live Validation and Performance Verification

Purpose:
Validate the full end-to-end signal quality, ranking, and execution pipeline in paper-trading mode, ensuring all Phase C metrics (NGC, CWQI, ProfitRate, Enhanced Risk, and Rolling Normalization) behave as expected under live conditions.

🔹 Session Parameters
Parameter	Setting
Mode	Paper Trading
Duration	Minimum 60 minutes continuous runtime
Diagnostic Logging	Full (include [C], [B.1], [B.2], and SQE logs)
Expected Signal Volume	≥ 200 signals across Tier A/B pairs
Validation Focus	Metric correctness, timing cadence, performance stability
🔹 Execution Steps for Replit
1. Start the Paper Trading Engine

Run the engine in diagnostic mode so that all [C] log tags are emitted.

Confirm that the following appear within the first 5 minutes:

[C][ROLLING_NORMALIZATION]
[C][ENHANCED_RISK]
[C][CWQI_DECAY]
[C][PROFIT_FLOORS]
[C][CONFIG_LOAD]
[B.1][SQE_REJECT]
[B.2][CONFIG]


Each should show live numeric values.

2. Observe and Record Live Metrics

During the 60-minute run, collect metrics snapshots every 10 minutes:

Metric	Source	Expectation
NGC distribution	SQE logs	Mean ≈ 0.55–0.70, SD < 0.15
CWQI distribution	RTB logs	Mean ≥ 0.60, stable decay trend
ProfitRate	quality_index.ts	Within configured strategy floors
Enhanced Risk	risk_index.ts	< 0.7 for most signals; occasional > 0.9 OK
FX5 cadence	[REB2.10][CycleStart]	Tier A ≤ 40 s, Tier B ≤ 12 min
Performance latency	system monitor	< 5 s scan lag; < 70 % CPU
Queue turnover	RTB queue	CWQI decay visible; slots freeing & refilling
3. Confirm Metric Propagation

At least once during the session, verify in logs or UI:

Confidence field (NGC) appears in:

RTB table

Active Trades table

Trade History table

CWQI ranking orders the RTB queue.

SQE rejections appear with [C][PROFIT_FLOORS] or [B.1][SQE_REJECT].

4. Validate CWQI Decay

Check for CWQI decay over time in RTB queue logs:

Log average scan cycle latency and CPU utilization:

Latency < 5 s

CPU < 70 %

No Kraken rate-limit or throttle events.

If throttling appears, note timestamp and affected pairs.

After 60 minutes:

Export the following to /logs/validation/
